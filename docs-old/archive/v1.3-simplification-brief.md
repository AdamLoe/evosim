## What the user resolved (LOCKED — do not re-litigate)

### Deletions (10 — strip from codebase entirely)

1. **Saving** — delete `src/save.rs`, `src/world/save_v1.rs`, schema versioning, `validate_save`, the F.26 autosave + resume + modal flow, `web/src/persistence/*`, all save-related tests. No persistence at all in v1.3.

2. **Carrion** — delete `src/carrion.rs`, `Carrion` struct, `cell_to_carrion` spatial index, carrion render layer in `web/src/render.ts`, carrion vision color (the gray dots fed to NN vision), all `CARRION_*` constants, `decay_carrion` step, `scratch_damage`/`scratch_gain` patterns for carrion.

3. **Genome ENTIRELY DELETED** — delete `src/genome.rs`, `Genome` struct, `TraitMutationRates`, all mutation kernel code, all `g_*` hot mirror fields on CreatureSoA, the body mutation step. **Creatures are identical phenotypes; only NN weights vary across the population.** All creature attributes are constants pulled from `src/constants.rs`:
- Body radius: `FOUNDER_SIZE = 1.0` (fixed)
- Vision: 24-sector eyes at fixed range `VISION_RANGE_MAX` (no eye_count gating)
- Move speed cap: `MOVE_SPEED_MAX = 5.0` (fixed)
- Max age: `FOUNDER_MAX_AGE = 5000` (fixed)
- No pigment trait (color comes from NN weight hash per modification #5)
- No eat/graze/scavenge efficiency — energy threshold is the only gate

Brief intent: evolution = pure NN weight evolution. All creatures structurally identical.

4. **Events** — delete `src/events.rs`, EventLog, EventKind enum, toast UI, all event push sites.

5. **Hall of Fame** — delete `src/hof.rs`, eulogy UI/panel, first-to-* tracking, longest_lived snapshot, weirdest fallback.

6. **snapshot_hash** — delete `src/snapshot_hash.rs`, the §16 acceptance test, both golden files, the `cargo test --release --test acceptance` gate, the bootstrap mechanism. Determinism verification leaves the codebase.

7. **Torus** — REVERT to walled world. Delete `src/torus.rs`, restore wall-clamp logic in `apply_movement_and_repulsion`, restore the `is_at_wall` NN input slot, restore `WALL_THRESHOLD_PAD`. "Creatures should learn to see walls with eyes over time" — so eyes (vision raycast) survive, walls are detectable via vision rays.

8. **F.30** — delete the founder NN hardwiring entirely. Founders get pure uniform-random NN init. Brain::founder body is 4 lines. User explicitly accepts that "it will fail on startup often" — random extinction is OK.

9. **Action types: Rest, Scavenge, Signal, Armor, Pigment, Move** — delete from `Action` enum. **The new action set is `{Graze, Eat, Split}` (3 variants).** Move is NOT an action — movement happens every tick via NN vx/vy outputs regardless of which action was picked. **NN output dimension drops 8 → 5: 3 action logits (Graze, Eat, Split) + 2 movement scalars (vx, vy).** Brain weight matrix `160×24 + 24×8 = 4032` → `(new_input)×24 + 24×5`. New input dim depends on genome deletion + grass-patch dim (see deletion #3 and Q3 vision below); recompute in the master plan.

10. **Species tracking** — delete `src/species.rs`, SpeciesRegistry, species_distance, species_id columns, species panel, speciation events, anchor brain weights cloning. Pop chart stays; species chart goes.

### Modifications (5)

1. **Grass cell size 2.5u → 5u.** `GRASS_CELL_SIZE = 5.0`. Cell count drops from 240×240 = 57,600 to 120×120 = 14,400 (4× perf win on `step` + bilinear sample). NN grass-patch sample spacing doubles (5u between samples instead of 2.5u → patch covers a wider area).

2. **Grass color always full alpha regardless of density.** Render layer paints a fixed-alpha green for any cell with `density > 0`. Cells with `density == 0` still don't paint. Visual simplification — drop the alpha-modulation by density.

3. **Performance gains in UI or backend.** Profile-driven. Likely candidates: brain weight transpose (deferred from v1.2 perf-hot-loop:#1,#18,#20), SIMD opportunities in `GrassGrid::step`, vision raycast tightening, Canvas2D batch fills. Pick the top-3 wins by measurement.

4. **Make sure dev panel, perf panel, inspector, and rest of UI still work.** Major deletions WILL break UI surfaces; the implementer's job is to keep them working at the new (simpler) data model.

5. **Color comes from NN-weight hash (since pigment trait is deleted in #3).** Render the creature's color as a deterministic hash of its NN weights (e.g., xxhash over the weight Vec → 24-bit RGB). As NN weights drift via mutation, the color drifts naturally — and faster than v1.2 pigment-trait drift because there are 4000+ weights vs 3 pigment scalars. Visual signal for evolution = NN brain divergence rendered as color. No new mutation rate constant needed — color drift IS NN drift.

   Implementer note: hash the post-mutation weights at child birth in `Brain::child_from`; cache the f32→u32 color as a hot-mirror field on CreatureSoA so render doesn't re-hash per frame. Inspector should show the hash + raw color for debugging.
