# v1.7.2 — Decisions

Hygiene pass closing out the four post-v1.7 surprises (misleading
`calls`/`ms/call` columns, invisible sample window, stale 200 ms status
throttle, no discoverable TPS/FPS readout). No new spans, no new trees, no
new SAB layout.

## Per-worker `_calls` atomics paired with `_us` atomics
- **Decision**: every per-tick sum-of-workers `_us` accumulator (in
  `NnStats` and `GrassGrid`) is shadowed by a paired `_calls: AtomicU64`
  that workers `fetch_add` in lockstep with the timing. The post-tick
  drain reads both numbers and passes them to `record_under_root`.
- **Why**: the v1.7 profiler recorded one drained sample per tick into
  the ring buffer, so `call_count` measured "ticks where the phase
  fired" rather than the underlying per-creature / per-row invocation
  count. `ms/call` for `nn.forward.l1` at pop 1500 was off by ~1500×,
  hiding the real microsecond-per-creature cost behind a millisecond
  per-tick number. Pairing the atomics is the smallest change that
  carries the truthful count from the worker that owns it through to
  the JSON the panel divides.
- **Applies to**: `profiler`, `nn-stats`, `grass`.
- **Alternatives considered**: a single atomic-of-tuple was rejected
  because it would need 128-bit CAS in the worker hot path; threading
  the count through a separate API (e.g. a new `record_drained`) was
  rejected because every caller is paired anyway and the API churn
  isn't worth it.
- **Code anchors**: `src/world/nn_stats.rs → NnStats.record_chunk_subphases`,
  `src/grass.rs → GrassGrid.compute_propagation`,
  `src/world/nn.rs → World.nn_forward_all_chunks` (drain side),
  `src/world/mod.rs → World.step` (grass drain).

## JSON adds `total_call_count`; legacy `call_count` stays as sample count
- **Decision**: `profile_report_json` gains a `total_call_count` field on
  every node (sum of per-sample call counts). `call_count` keeps its
  existing meaning (sample count in the ring buffer) so any tool reading
  the old shape continues to work; new readers divide `total_us` by
  `total_call_count` for honest `ms/call`.
- **Why**: in-place semantic changes to `call_count` would silently
  break the `web/src/widgets/perf-panel.ts` table and any external
  consumer. Adding a new field with a clear name keeps the shape
  forward-compatible and lets a stale wasm + new TS panel still render
  (falls back to `call_count`).
- **Applies to**: `profiler` (JSON contract).
- **Tradeoffs**: +33% memory per sample (tuple grows from
  `(u32, u32)` to `(u32, u32, u32)`); at 4096 samples × 256 nodes that's
  ~4 MB worst case, acceptable for a runtime-toggleable dev tool.

## Profiler-panel window header read from `max(effective_window_ms)`
- **Decision**: render `window: X.X s` as a single header line above the
  four trees, computed as the max `effective_window_ms` across all
  populated nodes in the merged report.
- **Why**: per-tick aggregation makes the window uniform across every
  node (each tree gets one sample per tick), so one number describes
  the whole panel; `tick.total_ms = 40 s` is otherwise uninterpretable.
  Reading from `effective_window_ms` reuses existing per-node fields
  instead of plumbing a new top-level value through the JSON.
- **Applies to**: `perf-panel`.
- **Revisit when**: if any tree adopts a different sampling rate the
  single header becomes a lie — at that point switch to per-tree
  headers.

## Status text updates every RAF; TPS+FPS appended unconditionally
- **Decision**: drop the 200 ms `lastStatusUpdate` throttle in
  `web/src/main.ts`; rewrite `#status.textContent` once per RAF with
  `seed · tick · pop · TPS · FPS`. TPS comes from
  `header.tps` (already in the per-frame SAB snapshot); FPS is a 1 Hz
  rolling counter ("frames in the last 1 s") computed entirely on main.
- **Why**: the throttle dated from the WorldHandle era where reading
  `tick` was a wasm call; post-Wave-C it's a 4-byte typed-array read
  and the canvas already paints at full FPS. The text was the only
  thing lagging. FPS belongs on main because the worker can't observe
  RAF cadence; using a counter (not a rolling average) matches the
  conventional games-industry meaning and avoids a misleading transient
  while paused or world-ended (FPS naturally trends to 0).
- **Applies to**: `status-bar`.
- **Code anchors**: `web/src/main.ts → frame` (RAF loop).
- **Tradeoffs**: writing `textContent` every RAF is essentially free
  (single DOM node, no layout thrash); the throttle saved nothing real.
