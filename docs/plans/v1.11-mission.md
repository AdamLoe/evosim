# Mission: v1.11 — Snapshot in wasm memory + f32 grass (no quantize)

## Goal

Move the snapshot region from a dedicated `SharedArrayBuffer` into wasm
linear memory, and skip the per-cell grass quantize step on the
snapshot write path. Net effect: `sim_worker.write_output_sab` drops
from ~6.7 ms (post-v1.10 parallel-quantize baseline) to ~1 ms per tick
at pop 80. Snapshot stops being a meaningful fraction of the tick
budget; the sim worker is effectively "ticks only."

## Scope

- `WorldHandle` owns a `snapshot_buf: Vec<u8>` of size
  `2 × SNAPSHOT_SLOT_BYTES` allocated once at construction. The buffer
  lives in wasm linear memory (which is itself a `SharedArrayBuffer`
  when shared memory is enabled).
- New wasm exports: `write_snapshot(slot)`, getters for
  `snapshot_buf_byte_offset`, `snapshot_buf_byte_len`,
  `snapshot_slot_bytes`, `snapshot_header_bytes`,
  `snapshot_creature_bytes`, `snapshot_grass_bytes`.
- Removed: the old `write_snapshot_to(creatures_dst, grass_dst,
  stats_dst)` wasm export and its three `js_sys::Uint8Array`
  parameters — all per-tick wasm↔JS boundary crossings on the snapshot
  path are gone.
- Grass density in the snapshot region is **raw f32 per cell** (4×
  larger than the prior `(d * 255) as u8` quantize). The renderer
  uploads as `R32F` / `RED` / `FLOAT` with `OES_texture_float_linear`
  for bilinear filtering (fallback NEAREST if the extension is
  unavailable; warned at boot).
- Boot reply carries `wasm_memory: WebAssembly.Memory` +
  `snapshot_buf_byte_offset` + `snapshot_buf_byte_len` in place of
  `snapshot_sab`. Main builds typed-array views over
  `wasm_memory.buffer` at the offset for the snapshot region.
- Profiler row rename:
  `sim_worker.write_output_sab.snapshot.grass_copy_to_sab` →
  `sim_worker.write_output_sab.snapshot.grass_copy` (the
  `grass_quantize` row is removed entirely — no quantize to time).
- Native test path (`write_snapshot_to_native`) mirrors the new
  layout. Byte-layout test asserts `grass.len() == GRASS_CELL_COUNT *
  4` and round-trips f32 values exactly.

## Non-goals

- Option B (a second worker reading sim state in parallel via
  double-buffered grass). Discussed and explicitly skipped — the
  marginal saving (~1 ms) is not worth the sim-core grass-buffer
  refactor + new worker lifecycle. May revisit if the sim worker
  ever needs more headroom than the v1.11 baseline provides.
- Internal grass precision change. `GrassGrid.density` stays `f32`;
  the precision change discussed (u8 / u16 fixed-point internal) had
  real sim-feel parity risk and was not justified by the perf delta.

## Plan

1. Add `snapshot_buf` to `WorldHandle`; allocate at construction. ✓
2. Add slot/region byte-offset constants:
   `SNAPSHOT_HEADER_BYTES`, `SNAPSHOT_CREATURE_BYTES`,
   `SNAPSHOT_GRASS_BYTES`, `SNAPSHOT_SLOT_BYTES`,
   `SNAPSHOT_BUF_BYTES`. ✓
3. Rewrite snapshot path: `write_snapshot(slot)` writes header +
   creature SoA + raw f32 grass into `self.snapshot_buf` via
   `copy_from_slice`. No JS-side parameters. ✓
4. Free function `fill_creature_bytes(world, dst)` so the snapshot
   write can borrow `&mut snapshot_buf` while reading `&world`
   without borrow-checker conflicts. ✓
5. Boot handshake: `boot_ready` carries `wasm_memory` + snapshot
   offset + len. ✓
6. Main constructs `DataView` + `Float32Array` views over
   `wasm_memory.buffer` at the offset. Grass becomes `Float32Array`
   of length `GRASS_CELL_COUNT` (not byte length). ✓
7. Renderer: `R8 → R32F`, `UNSIGNED_BYTE → FLOAT`,
   `OES_texture_float_linear` extension requested with NEAREST
   fallback + `console.warn` if unavailable. ✓
8. Update `write_snapshot_to_native` + the byte-layout test for
   f32 grass. ✓
