# v1.3 M4 — UI updates (keep UI working at simplified data model)

**Status of upstream Phase 0 decisions:** Q7 + Q8 LOCKED per `docs/plans/v1.3-amendments.md`.

## 1. Scope summary

The v1.3 pass deletes 10 sim-side feature areas. Each deletion strips Rust modules AND removes/changes wasm-bindgen surface that the TS UI depends on.

**M4's job:** keep surviving UI panels alive against the simplified data model.

**KEEP and adapt** 5 surfaces:
1. Top-bar speed controls (1x/10x/100x/pause per Q8)
2. Population chart
3. Perf panel (simplified)
4. Dev panel (slider set reduced)
5. Inspector (NN weight count + color hash + energy only)

**DELETE** 4 surfaces wholesale:
1. Species chart (D10)
2. Toast stack (D4)
3. Eulogy modal (D5)
4. Persistence UI shell — resume prompt, schema-mismatch modal, autosave toast, save indicator (D1)

**COORD with M5** on the color-hash inspector field. Either embed in `creature_inspect_json` (preferred — one round-trip) or separate getter.

Dominant risk: **ordering**. Many surviving panels read fields (`species_count`, `mean_nose_count`, genome traits) that backend deletions strip. M4 must land AFTER, or atomically alongside, backend pieces that delete those fields.

Per Q-perf: M4 does NOT take on render perf — that's M3.
