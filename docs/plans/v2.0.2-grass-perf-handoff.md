# Handoff: grass propagation is the tick bottleneck (~2 TPS)

Concise brief for a fresh agent to rethink the grass-propagation
performance problem. The shipped v2.0.1 grass code is **correct** (all
tests green) but **slow**. Read this, then re-approach from a clean angle.

## The problem (measured)

Default 9600² world (1920² grass cells = 3.69M), threaded (12 rayon
workers, 20 HW threads), in-browser profiler:

- Sim caps at **~2 TPS**. `tick.grass_step` ≈ **491 ms/tick = ~99% of
  the tick**. `grass_step.row_compute.body` ≈ **1.6 ms/row (~835 ns/cell)**.
- `write_output_sab` is **NOT** the problem: 2.3% of tick. (The original
  #6 complaint named it, but the dirty-tile quantize below already fixed
  it.)
- The 10–20× reduction goal for grass compute is **UNMET**.

## What the current grass step does (`src/grass.rs`)

1. **Shape (#5):** spread is disc-shaped via a 2-pass separable `[1,2,1]/4`
   blur (`h_at` then `blur_at`) plus an **8-neighbour max-of-blur** spill,
   replacing the old 4-neighbour Von Neumann diamond kernel. Logistic
   growth + `[0,K]` clamp preserved. Pure read-`density`/write-`scratch`
   (deterministic, single-thread == rayon).
2. **Frontier (#6):** a 32×32 **active-tile** model — only tiles holding a
   cell in `(ε, K−ε)` plus their fringe are processed; empty/saturated
   tiles skipped. Bit-identical to a full-grid pass (equivalence-tested).
3. **Snapshot:** `quantize_dirty_tiles_into` writes only dirty tiles' u8
   into the SAB (this is why write_output_sab is now cheap).

Density is `Vec<f32>` (u16 deferred).

## Leading root-cause hypothesis (NOT yet fixed)

**The separable blur is recomputed on the fly, defeating separability.**
For each output cell, the 8-neighbour max calls `blur_at` 8 times, and
each `blur_at` recomputes `h_at` (the horizontal pass) from `density` —
so a single cell does roughly *tens* of density reads + multiplies
instead of the ~6 ops a true separable blur costs. ~835 ns/cell is
consistent with that.

**The fix that was NOT done (and the plan actually called for):**
materialize the horizontal pass into a **scratch buffer once** (one H
pass over active tiles + a 2-cell halo), then do the vertical pass +
8-neighbour-max reading that scratch. That turns per-cell cost from
O(neighbours × kernel) to O(1). Expected to be the single biggest win.
Must keep the disc shape and all `grass_v201_tests.rs` green.

## Big unknown: does the frontier even help at this scale?

At 2 TPS the sim **never reached saturated grass**, so we never observed
the active-tile set shrinking. During the long spreading phase (default
seeds grass across the whole map), the frontier may be *most* of the
grid — in which case frontier-skip saves little and per-cell cost
dominates everywhere. **Instrument active-tile count vs total per tick**
(spreading vs steady state) before trusting the frontier as the win.

## What's been tried / decided (don't relitigate)

- **Active-tile frontier** — implemented; effectiveness at scale unverified.
- **Dirty-tile snapshot quantize** — implemented; fixed write_output_sab.
- **Every-N-tick cadence throttling** — REJECTED by lead (trades visual
  smoothness; don't pursue).
- **u16/u8 fixed-point density** — DEFERRED by lead (precision risk; more
  SIMD lanes + cheaper if revisited).
- **Separate writer thread for the SAB write** — DROPPED: write_output_sab
  is only 2.3%, not worth the concurrency risk; also blocked because the
  publish (`CTRL_SEQ`/`CTRL_CURRENT_SLOT`) lives in TS (`sim-worker.ts`)
  against the JS control SAB, a separate buffer from wasm memory — a Rust
  writer thread can't publish directly.

## Open question

Is the current cost a **regression vs `main`**, or was `main` also slow at
9600²? No baseline was measured. The 8-neighbour fused blur is almost
certainly more expensive per computed cell than the old 4-cardinal kernel,
so the spreading phase is likely a regression.

## Suggested angles for the fresh agent (re-think welcome)

1. **Materialize the separable passes** (H→scratch, then V+max). Biggest,
   most obvious win; keep shape + determinism tests green.
2. **Instrument frontier coverage** to see whether tile-skipping actually
   pays at spreading vs steady state.
3. **Measure `main` baseline** to confirm/deny regression.
4. **Question the 8-neighbour max**: separable blur alone measured only
   0.81 axis/diag (still diamond-ish); is there a *cheaper* isotropic
   scheme that still reads as a disc?
5. **wasm-SIMD** on the materialized passes; then **u16/u8** for more lanes.
6. Consider whether the spreading phase itself should be cheaper (coarser
   propagation grid, fewer/denser seeds, or a different growth model) —
   the steady-state and spreading-state cost profiles differ.
