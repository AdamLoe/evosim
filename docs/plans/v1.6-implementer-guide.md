## Per-commit gate suite

Every commit (A1, A2, B, C, D) must pass these gates. Run in this order:

```bash
# 1. Threaded wasm build — ALWAYS. The plain wasm-pack command silently
#    produces a single-threaded bundle (see .cargo/config.toml). Compile/link
#    flags live in config.toml — do NOT override via RUSTFLAGS env.
rustup run nightly wasm-pack build --target web --out-dir web/wasm --dev --features threads

# 2. Verify the bundle is threaded (would otherwise silently regress):
test "$(grep -c initThreadPool web/wasm/evosim.js)" = "2" \
  || { echo "BUNDLE NOT THREADED — check .cargo/config.toml + --features threads"; exit 1; }
grep -q -F 'shared:true' web/wasm/evosim.js \
  || { echo "SAB not shared — check link-args"; exit 1; }

# 3. Rust gates (default features):
cargo fmt --all
cargo build
cargo test --lib
cargo clippy --all-targets -- -D warnings

# 4. Rust gates (threads feature — different code path):
cargo clippy --all-targets --features threads -- -D warnings
cargo test --lib --features threads

# 5. TypeScript gates:
cd web && pnpm typecheck && pnpm build && cd -
```

Notes:
- A2 (sim-bridge.ts types-only) **may skip steps 1 + 2** — no Rust changes. All other steps must run them.
- On any gate failure: fix the underlying issue and create a **new commit**. Do not `--amend` after a hook failure (the failed commit didn't happen, so amend rewrites the previous commit).
- Never pass `--no-verify`. Never pass `--no-gpg-sign` or `-c commit.gpgsign=false`.

## Wave B — Stage 1 sim-worker cutover

One implementer agent. Worktree branch: `worktree-b-stage1-cutover`. **Foreground** (not background) — this is the biggest commit and you'll want eyes on it.

Prompt source: [`v1.6-plan.md` §"Step B"](v1.6-plan.md#step-b--featarch-move-sim-into-web-worker-stage-1-postmessage-snapshots).

**Pre-flight:** Wave A must be reconciled into main. Verify by running `git log --oneline -3` and confirming both A1 and A2 SHAs are present.

**Files touched (10 — biggest commit in v1.6):**
- New: `web/src/sim-worker.ts`.
- Structural: `web/src/main.ts`, `web/src/render-gl.ts`, `web/src/widgets/devpanel.ts`, `web/src/widgets/worker-stats.ts`, `web/src/widgets/perf-panel.ts`, `web/src/rail/inspector.ts`, `web/src/rail/stats.ts`, `web/src/rail/index.ts`, `web/src/sim-bridge.ts` (extends A2 with `SimBridge` class).
- Docs: `docs/dev-server-prompt.md` §X new.

**Gotchas (high — read all):**

1. **First-paint handshake.** Worker runs `world.step_n(1)` and posts one snapshot **before** posting `boot_ready`. Main is guaranteed a valid first frame. If you skip this, the first RAF iteration sees `latestSnapshot === undefined` and either crashes or paints `pop=0`.

2. **`crossOriginIsolated` read.** No Rust export. Worker: `const isolated = (self as unknown as { crossOriginIsolated?: boolean }).crossOriginIsolated ?? false;`. Main keeps the existing `globalThis.crossOriginIsolated` read at `web/src/main.ts:94`.

3. **Slider dispatch is name-only.** Worker calls `world.set_slider(name, value)`. Do **not** call per-typed setters (`set_max_age`, etc.) — they're deleted in Wave C; keeping callers alive in Wave B would mask the deletion. **Bools ride `set_slider` too**: `auto_curriculum` (the only bool DevSlider) is sent as `set_slider({ name: "auto_curriculum", value: 0|1 })`. Rust's `try_set_slider` gains an `"auto_curriculum" => self.apply_auto_curriculum(value != 0.0)` arm in Wave C. No dedicated message kind, no carve-out, no `set_auto_curriculum` wasm export.

4. **`currentSliderState()` reads in-memory widget state.** Devpanel snapshots from `slider.value` / `numInput.value`, not from `getSettings()`. Reason: mid-drag restart should carry the dragged value, not the last-persisted one.

5. **`max_pop_for_sab` handshake assertion.** Main throws on `boot_ready.max_pop_for_sab !== MAX_POP_FOR_SAB`. Error message must reference both values so the fix is obvious ("rebuild wasm").

6. **Drop `__world` debug hook.** No `(window as any).__world` after this. Note in commit body.

7. **`pollRail` signature change.** Drops `WorldHandle`, gains `(snapshot: SnapshotHeader, simBridge)`. Update the single call site in `main.ts`.

8. **Stats sampler `>= 10` guard, not `% 10`.** At high TPS a batch can step past multiple 10-tick boundaries; mod-10 would skip them all.

9. **Sim worker DevTools console.** Chrome: DevTools → Sources → Threads/Workers; Firefox: `about:debugging#/runtime/this-firefox` → Inspect on the worker. Document in dev-server-prompt.md.

10. **Stage 1 pacing is `setTimeout(0)`.** Yes, this caps high-TPS accuracy at ~250 TPS due to Chrome's 4 ms minimum. That's fine — Wave D replaces with `Atomics.waitAsync`. Don't try to ship Wave D's pacing primitive here.

11. **postMessage view-aliasing.** `world.creatures_buffer()` returns a `Float32Array::view(&self.creature_buf)` — a view over wasm memory. `postMessage` does an **eager** structured clone in Chrome + Firefox, so it's safe to mutate wasm memory on the next iteration. Add a one-line comment so the next reader doesn't doubt it.

### Wave B acceptance gate (after reconciliation, before Wave C)

Boot the dev server. Verify:

- **(B-a)** Default settings + auto-run on → sim ticks, render paints, no console errors.
- **(B-b)** Pop ≤ 1500 at 60 TPS holds ≥ 55 FPS.
- **(B-c)** Hit `r` 3 times. Each restart blip ≤ 800 ms (ceiling, not target — locked #14 is 500 ms target / ~600 ms realistic; 800 ms is the acceptance gate ceiling); render keeps painting last-good frame; no orphan red errors.
- **(B-d)** Drag every slider; release; observe sim state changes within 1 frame.
- **(B-e)** Spacebar pauses; spacebar resumes; sim cleanly stops + starts.
- **(B-f)** Click a creature; inspector populates within 2 frames at 60 TPS.
- **(B-g)** Sim Worker console (separate DevTools pane) shows `[sim] crossOriginIsolated=true` and `[sim] rayon workers: N` with N > 1.
- **(B-h)** `__world` is gone from `window` (confirm `window.__world === undefined` in main console).

**Failure modes** and what they mean:
- "Sliders don't take effect" → `drainMessages` not running. Stage 1 uses `setTimeout(0)` which yields cleanly; if you accidentally shipped a sync `while` loop, fix it.
- "Inspector never updates" → `request_id` correlation map not finding entries. Check that `SimBridge.requestInspectId` resolves the promise from the reply handler.
- "Restart drops slider state" → `currentSliderState()` is reading `getSettings()` instead of in-memory widget values.

If B-b fails at pop ≤ 1500, do **not** proceed to Wave C with the failure papered over. Fix Stage 1 first.

## Wave C — Stage 2 SharedArrayBuffer snapshots

One implementer agent. Worktree branch: `worktree-c-sab-snapshots`. Foreground.

Prompt source: [`v1.6-plan.md` §"Step C"](v1.6-plan.md#step-c--perfarch-sharedarraybuffer-snapshots-zero-copy-render-path).

**Pre-flight:** Wave B reconciled. `git log --oneline` shows the Wave B SHA.

**Gotchas:**

1. **SAB allocation in worker.** Two SABs (control 16 B, snapshot ~974 KB). Posted to main in `boot_ready`. Main builds typed-array views per frame.

2. **Atomic flip ordering.** Sim worker writes inactive slot fully, **then** `Atomics.store(ctrl, CTRL_CURRENT_SLOT, new_slot)`, **then** `Atomics.add(ctrl, CTRL_SEQ, 1)`. The store-before-add gives main's render loop a clean read: if seq changed, current_slot is already coherent.

3. **TS-side `worker.snapshot.write` span** — opened via `web/src/perf.ts`'s `span()` in the worker, around `world.write_snapshot_to(...)`. Not Rust-side.

4. **TS-side `frame.snapshot.read` span** — opened in main's render loop around the per-frame `Atomics.load + view construction`.

5. **Deletion list is long — enumerated in [`v1.6-plan.md` §Step C](v1.6-plan.md#step-c--perfarch-sharedarraybuffer-snapshots-zero-copy-render-path). Verify each:**
   - `src/wasm_api.rs`: delete `creatures_buffer`, `grass_buffer`, `grass_buffer_u8`, `creature_ids_buffer`, `pack_render_buffer`, `creature_stride`, `stats_sample`, and **all 21 per-typed slider setters** including `set_auto_curriculum` (bools now ride `set_slider` via the new `"auto_curriculum"` arm in `try_set_slider` — see plan §Step C). Keep `set_slider` name-dispatcher.
   - Delete the corresponding `#[test]` items (`creature_stride_is_8`, `creature_buf_length_matches_population_times_stride`, `set_slider_typed_mutates_field`, …).
   - The `apply_*` private helpers stay — they're called by `try_set_slider`.
   - **Don't re-summarize from this guide**; the plan's list is canonical, so when the plan adds/removes a setter, Wave C tracks the plan, not this doc.
6. **Renderer signature change.** `renderWorld` now takes typed-array views over SAB rather than the Stage-1 postMessage'd payload. Same JS-side cull + pack loop; only the data source changed.

7. **JS-side `pack_render_buffer` equivalent** lives in `web/src/render-gl.ts`. Cull bounds: `cam_cx ± viewport_w/(2·zoom)` plus margin = body_r + 2. Skip creatures outside. Pack 8 floats per visible: `[cx, cy, radius_px, 0, r, g, b, 1]`.

8. **Highlight pass** reads the same SAB SoA — same x/y/color extraction, just at a different offset (per highlighted id).

- **(C-b)** `grass.upload.read` profile span no longer appears in the perf panel (it was the Rust→JS quantize+copy; now replaced by SAB view construction).
- **(C-c)** New `worker.snapshot.write` and `frame.snapshot.read` spans appear in the perf panel.

## Wave D — Stage 3 polish

One implementer agent. Worktree branch: `worktree-d-stage3-polish`. Foreground.

Prompt source: [`v1.6-plan.md` §"Step D"](v1.6-plan.md#step-d--featarch-atomicswait-pacing--step_n-batch--inspector-fast-path).

**Pre-flight:** Wave C reconciled.

**Gotchas:**

1. **`Atomics.waitAsync` not `Atomics.wait`.** This is the single most important detail in v1.6. Synchronous `Atomics.wait` inside a `while` loop blocks the worker event loop, which means `onmessage` callbacks never fire, which means sliders + pause + restart + inspect all dark-hole silently. The fix:

    ```ts
    const messageQueue: SimMessage[] = [];
    self.onmessage = (e) => { messageQueue.push(e.data); };

    async function simLoop(): Promise<void> {
      while (!terminated) {
        drainMessages();                              // reads queue
        // … compute batch, step_n, writeSnapshotToSAB …
        const timeoutMs = paused ? Infinity : Math.max(0, budgetMs - elapsedThisIter);
        const before = Atomics.load(ctrl, CTRL_FUTEX);
        const r = Atomics.waitAsync(ctrl, CTRL_FUTEX, before, timeoutMs);
        if (r.async) await r.value;                   // event loop runs ⇒ onmessage fires
      }
    }
    ```

    If you copy the pseudocode from the plan verbatim, this is what you'll see. The `await` is what allows `onmessage` to run.

2. **Wake mechanism on main:** after every `worker.postMessage(msg)`, `Atomics.add(controlI32, CTRL_FUTEX, 1)` then `Atomics.notify(controlI32, CTRL_FUTEX, 1)`. The `add` mutates the futex so the worker's `waitAsync(before, ...)` returns synchronously with `"not-equal"`; the `notify` covers an already-parked worker.

3. **`Atomics.waitAsync(..., Infinity)` when paused.** Worker sleeps indefinitely; main's `set_paused(false)` notifies the futex to wake. No CPU burn while paused.

4. **`step_n(batch)` accumulator.** Same fractional-budget math as `web/src/main.ts:222-232` today, lifted verbatim into the worker. `MAX_TICKS_PER_BATCH = 2000`.

5. **Inspector fast-path.** Click → JS-side scan of SAB id column for the nearest creature within tolerance → render placeholder body fields from SoA (x/y/color) immediately → async-request `inspect_id` for the full JSON (cooldown, action, NN stats). First paint is sub-frame.

6. **Per-frame refresh throttling.** If the inspector's selected id still appears in the SoA, paint SoA fields immediately. Only send `inspect_id` if the panel is open AND > 250 ms since the last reply. Cuts inspector traffic ~4×.

7. **Slider debounce.** Per-name 16 ms trailing-edge debouncer in `sim-bridge.ts`. Last value wins. Prevents pointermove flooding.

8. **Rayon-thread-count guard.** After `initThreadPool` returns, call `rayon_current_num_threads()` (new wasm-bindgen export — `#[wasm_bindgen] pub fn rayon_current_num_threads() -> u32` under `cfg(feature = "threads")`, else `1`). If `<= 1`, `console.warn("[sim] rayon collapsed to 1 thread — sim will run single-threaded; check COOP/COEP and build flags")`. This is the v1.5 footgun defense.

9. **Strike `sleepNs`.** Earlier plan drafts had a `sleepNs` variable that's never used (and the comment claimed `Atomics.wait` takes ns — wrong, it takes ms). Don't carry it forward.

## Reconciliation playbook

After each Wave's worktree commit lands, the orchestrator merges to main:

```bash
# From repo root.
git checkout main

# For Wave A's parallel agents, merge in the order specified in the plan:
git merge --no-ff worktree-a1-snapshot-infra
git merge --no-ff worktree-a2-sim-bridge-types

# For waves B / C / D (single agent):
git merge --no-ff worktree-b-stage1-cutover
```

On any conflict:
1. **Trivial** (different lines in the same file): hand-resolve, run full gate suite, commit.
2. **Structural** (same lines): inspect both branches, decide which is canonical, hand-edit, gate, commit.
3. **Wide blast radius** (Wave B-style — 10 files): spawn a dedicated reconciliation agent rather than resolving inline.

After merge, **always re-run the gate suite on main**. The merge commit itself can introduce bugs neither branch had.

## Commit conventions

- Conventional commit subject only (`feat(arch):`, `perf(arch):`, `feat(wasm):`, `feat(web):`, `fix(runtime):`).
- Subject line ≤ 70 chars.
- Body explains the **why**; reference plan section by path (e.g., `v1.6-plan.md §"Step B"`).
- Co-author trailer: `Co-Authored-By: Claude Opus 4.7 <noreply@anthropic.com>`.
- Stage files explicitly: `git add -- <file1> <file2> …`. **Never `git add -A` or `git add .`** — repo has `.claude/worktrees/` (gitignored, but defensive matters; v1.5 hit this footgun once).
- Use a heredoc for the message:

    ```bash
    git commit -m "$(cat <<'EOF'
    feat(arch): move sim into Web Worker (Stage 1 postMessage snapshots)

    Per v1.6-plan.md §"Step B". Worker holds wasm + rayon pool; main is
    render-only. UI panels migrate to request/reply message protocol.
    Stage 1 acceptance is correctness, not perf (locked decision 16);
    Stage 2 closes the structured-clone bandwidth gap.

    Co-Authored-By: Claude Opus 4.7 <noreply@anthropic.com>
    EOF
    )"
    ```

## Failure-mode quick reference

| Symptom | Likely cause | Fix |
|---|---|---|
| `pnpm typecheck` errors after wasm-pack rebuild | Stride / export signature drift | Confirm `creature_stride()` returns 8 (or that the export was deleted in C); rebuild |
| Renderer throws `creature_stride mismatch` | A1 not merged or B's renderer guard not tightened | Check `web/src/render-gl.ts` stride guard matches current Rust stride |
| Sim Worker console silent (no `[sim]` lines) | Worker failed to boot — likely wasm init threw | Check Network tab for evosim.wasm 404; or wasm init error in worker console |
| Sliders / pause / restart silently ignored | Step D shipped `Atomics.wait` instead of `Atomics.waitAsync` | Rewrite loop to `async` + `await Atomics.waitAsync(...).value` |
| `[threads] crossOriginIsolated=false` | COOP/COEP headers not reaching dev server | Verify `web/vite.config.ts` headers; restart `pnpm dev` |
| `grep initThreadPool web/wasm/evosim.js` ≠ 2 | wasm-pack ran without `--features threads` | Re-run with the canonical incantation above |
| `boot_ready` handshake throws on max_pop mismatch | Rust + TS constants diverged | Rebuild wasm; or sync both constants if you bumped one |
| Restart blip > 1 s consistently | Rayon re-init slow on user's machine | Document; not a bug unless > 2 s |
| `Atomics.waitAsync` undefined | Safari < 16.4 / Firefox < 119 / Chrome < 87 | All ≥ 2 years old; user's browser is too old |
