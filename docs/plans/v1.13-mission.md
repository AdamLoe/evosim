# Mission: v1.13 — friendlier defaults + header/monitor overhaul

## Goal

Make evosim approachable on first load: the canvas should dominate,
controls should look like a media player rather than a wall of toggles,
and observability lives in one place (the bottom panel) instead of being
split between a right-rail Monitor tab and a Profiler panel.

The first wave (defaults + curriculum removal) has already shipped on
this branch. The remaining waves restructure the shell.

## Scope

### Wave 0 — SHIPPED (defaults + small removals)

Already landed in working tree, not yet committed.

- Theme default `midnight`; rail `railOpen=false`; default active tab
  `inspector`.
- Defaults: `TARGET_RAYON_WORKERS=12`, `grass_initial_seed_count=1000`,
  `split_threshold=99`, `split_jitter=1`, `founder_count=32`,
  `repulsion_max=0.1`, `max_population=8000` (TS lowers to 2000 on first
  boot when `navigator.hardwareConcurrency < 8`).
- Mutation buckets default to 1/3 / 1/3 / 1/3: `(weight=1, rate=0,
  sigma=0)`, `(1, 0.05, 0.05)`, `(1, 0.30, 0.20)`; remaining 5 buckets
  zero-weight.
- Auto-curriculum subsystem removed entirely from Rust + TS + UI +
  drift-guard test. Slider slots 17–20 retained as
  `_reserved_curriculum_*` no-ops to keep SAB index ordering stable.
- "Show population graph" toggle removed (graph still lives in Monitor
  tab — and will migrate to perf panel in Wave 2).
- World-end no longer parks the sim worker. Once population hits zero
  the sim drops into a thin grass-only path (`grass_step` +
  `rebuild_row_bitset` + `tick++`) so the canvas keeps filling. Main
  shows a "World ended" overlay with Restart / Keep watching.

### Wave 1 — Header trim + media-player buttons

- Strip everything from `#top-bar` except: play/pause toggle, restart,
  auto-restart, settings (⚙), and the (moved) profiler/perf toggle.
  The status text (seed / tick / pop / TPS / FPS) moves into the perf
  panel — see Wave 2.
- Top bar becomes see-through over the canvas (semi-transparent
  background, no border).
- Icon buttons styled like the existing `#perf-open` floating button:
  square, subtle background, accent border on hover.
  - Play/pause: single button, icon swaps glyph based on state.
  - Restart: dedicated icon button (currently a text button).
  - Auto-restart: toggle button; highlighted (accent border + accent
    background tint) when `getSettings().autoRun` is true.
  - Settings ⚙: highlighted when the Settings rail panel is the active
    tab AND the rail is open.
  - Perf: highlighted when `Settings.showProfiler` is true. Reuses the
    same `setProfilerVisible` source-of-truth.
- Remove the floating bottom-right `#perf-open` button — its job moves
  to the new top-bar perf button.
- Keep the `~` rail-toggle hotkey and the `r` restart hotkey.

### Wave 2 — Perf panel becomes the monitor

The bottom panel (currently `#perf-box`) absorbs everything from the
right-rail Monitor tab. The Monitor tab itself is removed.

- Drop `data-tab="monitor"`, `#rail-monitor`, `installMonitorTab`,
  `rail/monitor.ts`. Rail is now Inspector / NN / Settings.
- New perf-panel layout (responsive flex; see widths below):
  - **Graphs row**: two small time-series.
    - **FPS / TPS combined graph**: two coloured lines on one chart
      (FPS in `--chart-line`, TPS in `--accent-2` or similar). Small
      inline legend `■ FPS  ■ TPS` underneath the title. Both series
      share a y-axis (max of the two visible values).
    - **Population graph**: migrates from `rail/stats.ts` unchanged.
  - **Selectors row**: two "button-group + numeric input" combo
    widgets for **TPS** and **max population**. Each:
    - A pill row with 4–6 common values (TPS:
      10/30/60/180/500/1000).
    - A number input next to the pills. If the typed value matches a
      pill, that pill is highlighted; otherwise no pill is
      highlighted.
    - Max-population selector moves out of the Settings tab (the Sim
      group there drops the row entirely).
  - **Render-loop seq-gate** (replaces the earlier max-FPS-cap idea):
    Inside the RAF callback, if `seq === lastPaintedSeq`, skip the
    paint entirely — re-schedule and return. The renderer never
    paints the same snapshot twice. Position interpolation between
    snapshots is dropped (would require painting duplicates by
    definition).
    - **Invariant**: FPS ≤ TPS, always. With TPS=60 on a 240 Hz
      display, FPS ≈ 60 instead of 240. The FPS counter measures
      *painted* frames only.
    - Side effect: the seed + current-tick display in the old top bar
      is gone; not surfaced anywhere in this plan. Save/Load will
      reintroduce a way to find them in a future release. Acceptable
      for v1.13.
  - **CPU Process Monitor** (renamed from "Process" / `worker-stats`):
    - Drop the textual summary lines (`world_uptime_us` etc.); keep the
      per-worker table only.
    - Rename the section title to "CPU Process Monitor".
    - Rename column `w` → `#`, and switch to 1-indexed display.
  - **Profile system**: largely unchanged from today. The four-tree
    profiler tables (`tick`, `frame`, `nn`, `grass_step`) sit at the
    bottom. The existing "reset profile" / restart-style controls
    stay attached here.
- Responsive flex behaviour, controlled by container queries (or
  matchMedia fallback) on the panel width:
  - **Small** (≤ ~620 px): single column. Order: graph (FPS) → graph
    (TPS) → graph (pop) → selectors → CPU Process Monitor → profile
    logs.
  - **Medium** (~620–1000 px): two columns up top — graph + graph next
    to a graph + selector block — then CPU Process Monitor full-width,
    then profile logs.
  - **Large** (> ~1000 px): three graphs in a row, then selectors +
    CPU Process Monitor side-by-side, then profile logs.
- Status string from the old top bar (seed / tick / pop / TPS / FPS /
  world-ended suffix) renders as a single header line at the top of
  the perf panel.

### Wave 3 — Sliding panels

- Right rail and bottom panel each get a drag handle on their inner
  edge.
  - Rail: handle is a 6 px-wide strip on the left edge; drag changes
    `--rail-w` (clamped between e.g. 280 and 720 px).
  - Bottom panel: handle is a 6 px-tall strip on the top edge; drag
    changes `--profiler-h` (clamped between e.g. 160 and 60 % of
    viewport height).
- Cursor changes to `ew-resize` / `ns-resize` on hover over the handle.
- Width/height persists in `Settings` (`railW`, `profilerH`).
- Touch support: pointer events, not mousedown.
- Bottom panel auto-stretches the canvas region above it via the
  existing grid (already row-grid `topbar / canvas / profiler`).

### Wave 4 — Inspector tab visibility

- The Inspector rail tab is only visible while a creature is selected.
  When nothing is selected the tab button is hidden and the panel is
  hidden — rail starts with just NN / Settings.
- Clicking a creature: opens the rail, makes the Inspector tab visible,
  switches to it, populates. (Existing behaviour minus the
  always-visible empty-state.)
- Click-empty / Escape: deselect, hide the Inspector tab. If Inspector
  was active, fall back to NN tab.
- Remove the "Click a creature to inspect" empty state from
  `#rail-inspector`.

## Non-goals

- No SAB / protocol changes. All control still rides
  `set_slider` + the existing futex/epoch transport.
- No renderer changes.
- No additional themes or palette work.
- No FPS cap implementation if it turns out RAF is the only available
  knob — punt to a follow-up plan rather than re-architecting the
  render loop.

## Plan

1. **Wave 0 (commit only)**: stage the existing working-tree changes
   into conventional commits — defaults, curriculum removal,
   world-end popup, doc edits. One concept per commit.
2. **Wave 1**: top-bar trim + icon buttons + see-through styling +
   move profiler toggle up.
3. **Wave 2**: bottom-panel rebuild. Migrate Monitor components
   (population graph, worker-stats table, status line) into the panel,
   add FPS/TPS graphs and the three selectors, delete the Monitor
   rail tab.
4. **Wave 3**: drag-to-resize for rail width and panel height +
   persisted settings keys.
5. **Wave 4**: Inspector-tab visibility tied to selection.
6. **Docs**: rewrite `app-shell.md` (rail tab list, top-bar contents,
   resizing rules) and `profiler.md` (panel now hosts graphs +
   selectors + process table + profile trees) in place; refresh
   `overview.md` shape diagram. Delete this plan once the four
   architecture/decisions docs match the new state.

## Open questions

- **Bottom-panel drag handle interplay with the canvas.** The handle
  sits at the top of the panel, which is the bottom of the canvas
  container. Need to make sure pointer-events on the handle don't
  steal `mousedown` from the camera-pan handler.
- **Rail-tab visibility when no creature selected (Wave 4).** Do we
  hide the tab button or just disable it? Hiding shifts the other tab
  buttons; disabling keeps layout stable but adds a "dead" tab. Default
  assumption: hide.
