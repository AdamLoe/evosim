> **Post-ship polish (2026-05-29):** the Wave 2.5 halo as originally
> specced (centered Gaussian, additive blend, pulsed) read as a fat
> blue cloud that saturated to a hard ring at any meaningful pop. It
> was redesigned in-place to a **rim-light**: a narrow Gaussian band
> centered at the body edge (r ≈ 0.55 in halo-quad coords), with
> `SRC_ALPHA, ONE` blending, no pulse, and a slight cool-white tint.
> Trails were also re-tuned: the original 0.4 × single-tick segment
> at fixed 1.5 px thickness was invisible at any TPS, so trails now
> span the **full prev → curr displacement**, with thickness scaling
> as `0.6 × radiusPx` clamped to ≥ 2 px. Wave 3's interpolation
> wiring (prev/curr id-Maps, alpha lerp) was correct — the trails
> were just too short and thin to see. See current shader source in
> [`web/src/render-gl.ts`](../../web/src/render-gl.ts) `HALO_FS` and
> the trail-pack loop in `renderWorldImpl`.

# v1.9.2 mission — canvas polish + interpolation

Visual polish pass on the renderer. Three landing surfaces:

1. The grass texture goes from blocky to soft, with a green tint and
   subtle organic motion.
2. Creatures get anti-aliased edges, a subtle radial shading, a thin
   outline ring, and a bioluminescent halo. They will start to look
   like creatures, not flat dots.
3. The renderer interpolates positions between snapshot flips so motion
   is smooth at any TPS. Each creature gets a short fading velocity
   trail as a near-free side-effect of the prev/curr maps.

No backend (Rust) changes. No new sim mechanics. Pure TS + GLSL.

## Goals

1. Make grass look like a landscape, not a pixel grid.
2. Make creatures look alive.
3. Make motion smooth at low TPS as well as high.

## Wave 1 — Grass polish

Owner: [`web/src/render-gl.ts`](web/src/render-gl.ts) — the
`grassTex` setup and the `GRASS_FS` fragment shader.

**Changes:**

- Swap both `MIN_FILTER` / `MAG_FILTER` from `gl.NEAREST` to
  `gl.LINEAR_MIPMAP_LINEAR` (min) and `gl.LINEAR` (mag).
- After every `texSubImage2D` upload, call `gl.generateMipmap(gl.TEXTURE_2D)`
  so the mip chain stays current. The upload is per-frame today; the
  added mipmap cost is ~0.5–1 ms at 960×960. If perf measurably
  regresses, fall back to plain `LINEAR` filtering and revisit.
- Shader (`GRASS_FS`):
  - Tint base color from `vec3(1.0, 1.0, 1.0)` to a soft green:
    `vec3(0.55, 0.85, 0.45)`.
  - Add a low-amplitude wave term so the field looks alive when zoomed
    in. Cheapest implementation: sample `u_grass` at a few small
    offsets and blend, OR a procedural sin-noise based on `v_uv` +
    a slow time uniform:
    ```glsl
    float wave = 0.08 * sin(v_uv.x * 18.0 + u_time * 0.6)
               + 0.06 * sin(v_uv.y * 22.0 - u_time * 0.4);
    float d2 = clamp(d + wave * d, 0.0, 1.0); // attenuate by density
    ```
    so empty cells stay empty. Add `uniform float u_time;` in the
    shader and a new uniform location; pass `performance.now() / 1000`
    each frame.
- Keep the existing `if (d <= 0.0) discard;` early-out — both for perf
  and so the wave term can't paint outside grass.

**Theme integration (optional but recommended):** add a
`--grass-tint` token to themes.ts (default `0.55, 0.85, 0.45` for
Charcoal, varied per theme: cooler green for Slate, near-monochrome
for Midnight, brighter green for Vivid, olive for Light). Push it
into the shader as `uniform vec3 u_grass_tint;` and replace the
hardcoded `vec3(0.55, 0.85, 0.45)`. If you go this route, every theme
must define `--grass-tint`; update `REQUIRED_TOKENS` and the
defaults-drift test isn't affected (themes aren't part of the
Rust↔TS drift surface).

## Wave 2 — Creature shader polish

Owner: [`web/src/render-gl.ts`](web/src/render-gl.ts) — the
`DISC_VS` / `DISC_FS` programs and the instance assembly.

The disc program currently draws four classes of disc (body, two
optional trait rings, highlight ring) sharing one instanced draw.
Bodies use `inner_px = 0` (filled). After this wave, bodies still use
the same instance lane but the fragment shader produces a more
nuanced look.

**Fragment shader (`DISC_FS`) — bodies only:**

```glsl
in vec2 v_local;            // [-1, 1]
in vec2 v_radii_px;
in vec4 v_color;
out vec4 out_color;

uniform vec4 u_ring_color;  // theme-driven --creature-ring
uniform float u_ring_inner; // start of ring (e.g. 0.84)
uniform float u_ring_outer; // end of ring (e.g. 0.92)

void main() {
  float r = length(v_local);
  if (r > 1.0) discard;

  // Annulus shortcut still used by rings — keep existing branch.
  if (v_radii_px.y > 0.0 && r * v_radii_px.x < v_radii_px.y) discard;

  // --- Bodies-only path below ---
  // Anti-aliased edge: smoothstep against fwidth so the disc edge
  // softens at low zoom without going blurry at high zoom.
  float aa = fwidth(r) * 1.5;
  float alpha = 1.0 - smoothstep(1.0 - aa, 1.0, r);

  // Radial shading: 15% lift at center, 15% drop at edge. Pure
  // multiplication so action-EMA color identity stays readable.
  float shade = mix(1.15, 0.85, r);

  // Outline ring near the perimeter. smoothstep keeps the ring soft.
  float ring_t = smoothstep(u_ring_inner - aa,
                            u_ring_inner + aa, r) *
                 (1.0 - smoothstep(u_ring_outer - aa,
                                   u_ring_outer + aa, r));

  vec3 body = v_color.rgb * shade;
  vec3 col = mix(body, u_ring_color.rgb, ring_t * u_ring_color.a);
  out_color = vec4(col, v_color.a * alpha);
}
```

The annulus branch (`v_radii_px.y > 0.0 …`) still serves trait rings
and the highlight pass; only the filled-body path runs the new shading.
That means the highlight ring **doesn't get** the shading — that's
correct, the inspector ring is a UI element not a creature.

Add the two new uniforms to the renderer's `DiscProgramUniforms`,
look them up at link time, and set them once per frame from the active
theme tokens.

**New theme tokens:**

- `--creature-ring` — rgba color of the body outline ring.
  Default in Charcoal: `rgba(0, 0, 0, 0.6)`. Tune per theme;
  Midnight wants brighter (`rgba(255, 255, 255, 0.4)`); Light wants
  darker / more visible.
- `--creature-halo` — used in Wave 2.5 below.

Parse the rgba color CSS-side (a `readCssVarRGBA(name): [r,g,b,a]`
helper in `themes.ts` or `render-gl.ts`) and feed as a `vec4` to the
uniform. The default ring stops `[u_ring_inner, u_ring_outer]` =
`[0.84, 0.92]` are constants in the renderer (not theme tokens — they
control thickness, which doesn't need to be themed).

**Wave 2.5 — Glow halo (second instanced draw, additive blend):**

After the main disc draw, issue a second instanced draw of the SAME
instance buffer through a "halo" program that:

- Renders a quad scaled to `outer_px * 1.8` instead of `outer_px`.
- Uses `gl.blendFunc(gl.ONE, gl.ONE)` (additive) for that draw only,
  then restores to `(gl.SRC_ALPHA, gl.ONE_MINUS_SRC_ALPHA)`.
- Fragment shader: radial falloff alpha,
  ```glsl
  float r = length(v_local) / 1.8;     // re-normalize against bigger quad
  float falloff = pow(1.0 - clamp(r, 0.0, 1.0), 2.0);
  out_color = vec4(v_color.rgb * u_halo_strength, falloff * u_halo_alpha);
  ```
- `u_halo_strength` ~0.4, `u_halo_alpha` ~0.25 to start. Tune per
  theme: Midnight / Vivid want strong halo; Light wants almost none.

**Cap halo intensity** so 30 k overlapping halos don't wash the canvas
white. Either:
- A hard alpha cap (`min(falloff * u_halo_alpha, 0.3)`), or
- Skip the halo pass entirely when `pop > 8000` (perf + visual
  hygiene — at high pop the per-creature halo blends into noise
  anyway).

Recommendation: ship both — cap alpha at 0.3, AND skip the pass when
`pop > 8000`. The renderer already knows `pop` from
`SnapshotHeader.pop`.

## Wave 3 — Snapshot interpolation + velocity trails

The big one. After this lands, motion is smooth at any TPS.

**State model:**

- `prevById: Map<number, {x, y}>` — positions at the previous
  snapshot.
- `currById: Map<number, {x, y}>` — positions at the current
  snapshot. (Same data as the SAB read; this map indexes it by id for
  lookup.)
- `flipTimeMs: number` — `performance.now()` when the seq counter
  last bumped.
- `lastSeenSeq: number` — for flip detection.
- `expectedIntervalMs: number` — `1000 / targetTPS`, clamped to
  `[16, 250]` so very low TPS doesn't produce slow-mo gliding.

**Per-RAF flow (in `main.ts → frame` or factored into render-gl):**

1. Read `seq = Atomics.load(controlI32, CTRL_SEQ)`.
2. If `seq !== lastSeenSeq`:
   - Promote `currById → prevById` (swap or move).
   - Rebuild `currById` from the current SoA read (iterate creature
     instances, decode id from the `idView[i*8+6/7]` pair, store
     `{x, y}` keyed by id).
   - Update `lastSeenSeq = seq`, `flipTimeMs = now`.
3. Compute `alpha = clamp((now - flipTimeMs) / expectedIntervalMs, 0, 1)`.
4. For each SoA index `i`:
   - Decode id.
   - `prev = prevById.get(id); curr = currById.get(id);`
   - If both present: render at `lerp(prev, curr, alpha)`.
   - If only curr (newborn): render at curr.
   - If only prev (just died, lingering in old map): skip the render,
     but optionally fade the trail (see below).

The interpolated positions feed `a_center` in the disc instance
buffer; nothing else changes for bodies.

**Velocity trail (drops out for free):**

Add a SECOND instanced draw, this time `LINE`-primitive or a thin
quad-as-line. For each creature with both prev and curr:

- Endpoint 1: lerp(prev, curr, max(0, alpha - 0.4))
  (trail trails behind the body — start of trail is "where the body
  was 40 % of the interval ago")
- Endpoint 2: lerp(prev, curr, alpha) (current rendered body
  position)
- Color: `v_color.rgb` with alpha = 0.5 × (1 − distance from current
  position / trail length). Fades toward the back.

Skip the trail when `length(curr - prev) < epsilon` (stationary
creatures).

The trail draw needs its own minimal program (vertex passes
endpoints; fragment fades alpha along the line). Roughly a 50-line
shader pair + a small VAO setup.

**Perf budget:**

- Building `currById` Map on flip: ~32 k entries → ~1–2 ms in JS at
  worst case. Runs once per snapshot (not per frame).
- Per-RAF id decode + lookup: ~0.5 ms at 32 k.
- Total renderer overhead: well under 5 ms per frame. Acceptable.

**Edge cases:**

- World restart: `prevById.clear(); currById.clear(); flipTimeMs = now;
  lastSeenSeq = 0;`. The first post-restart flip naturally re-seeds
  curr without interpolation (no entries in prev → all newborn path).
- High `pop` deltas (mass extinction event): nothing special — the
  Map handles missing keys.
- `targetTPS = 1000` regression test: `expectedIntervalMs = max(16, …)`
  keeps alpha sane.

## Commit shape

One commit per wave is fine:
- `feat(render): wave 1 — grass mipmaps + green tint + wave term`
- `feat(render): wave 2 — creature AA edge, radial shading, ring, glow halo`
- `feat(render): wave 3 — snapshot interpolation + velocity trails`
- `docs: v1.9.2 — render-pipeline + app-shell updates, plan shipped`

Or merge Waves 1 + 2 into a single "shader polish" commit if they're
landing together — judgment call. Wave 3 stays its own commit because
the bisect surface is larger (architectural change to render path).
