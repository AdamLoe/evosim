### Cross-PR risks the dependency graph forces us to plan around

1. **`for_each_in_radius` wrap is the deepest sim-code change in the pass.** It touches: repulsion (`src/world/tick.rs:84`), eat-candidate search (`src/world/tick.rs:261`), `creature_at` for the inspector (`src/wasm_api.rs:361`), and a tick-tail no-op test sweep (`src/world/tick.rs:905`). Vision raycast in `src/vision.rs:218` also wraps — separate code path from `for_each_in_radius` but identical risk shape. **All four call sites must accept the wrapped semantics atomically in the same commit** or scavenge will silently scan with old-bounds while repulsion wraps, etc.
2. **Sequential ↔ threaded bit-identity** at `0xd56cd6881d2898fc` is currently preserved by S39's runtime test (`acceptance_threaded_actually_matches_sequential_t10000`). The brain-shape change (PR-2) does **not** change RNG draw order (forward-pass is RNG-free), so equivalence should survive. The risk surface is the par-chunks-mut path in `src/world/nn.rs:82-145` which reads `prev_vx`/`prev_vy` from a `mem::take`'d slice: if the input layout slot indices change (PR-2 adds 25 slots before/after the existing 16-extras block — brief says vision unchanged at offset 10..130, so the layout question is "where do the 25 patch inputs live?" — see §F #2).
3. **Photosynth → Graze rename slot collision (PR-1 ↔ PR-2).** PR-1 renames the enum slot only; the F.30 hardwiring in `src/brain.rs:60-75` still references `photo_out = 3` and `NN_FOUNDER_PHOTO_BIAS`. PR-1 must leave the constants and the wiring code intact (the slot now means Graze mechanically) so the hardwiring still "tilts the prior toward slot 3 = Graze" which is actually the desired behaviour for grazers. PR-2 deletes the constants in the F.30 rewrite. See §F #3 for the exact policy.
4. **Save schema two-bump cascade.** PR-1 changes the on-disk shape (drop sun, add grass) — schema version 1 → 2. PR-2 changes it again (add nose_count, brain shape). PR-3 only adds modal UX. Each pre-PR-3 schema bump goes through the existing `LoadError::SchemaVersionMismatch` path; the user's running browser tab carries an autosaved JSON of the old shape, so PR-3's modal-and-reset UX is required to bring them online. Goldens regen accordingly because `snapshot_hash` walks the new SoA shape.
5. **Founders with `eye_count = 0` + `nose_count = 0` MUST survive the acceptance seed `evosim-test-001`.** Brief says "The world seed must place enough initial grass for at least one founder lineage to survive (test this)." If `grass_initial_seed_count = 8` is not enough at the pinned seed, golden regen #3 will fail criterion (a) "population > 0" or (b) "≥ 2 species" of the §16 acceptance. Mitigation: bump seed count to whatever value makes the pinned seed pass.
