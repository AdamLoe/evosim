1. p1e's arithmetic ties directly to founder survival, which is the immediate §16 acceptance risk.

4. P3e is allowed to retune per master §B P3e row.

## D. Move-bias SET vs ADD recommendation

**Issue.** p2f §4 + §4.5 locks **SET semantics**: `creatures.vx[i] = move_bias_x[i] * MOVE_SPEED_MAX` (overwrites NN forward-pass output of vx/vy). p2f §11 risk #2 flags: "May permanently bottleneck evolved motion. **Recommend user confirms.** Mitigation: SET → ADD is one-line change."

**Option (a) — SET (per literal brief reading).**
- NN never controls velocity in any descendant lineage; `move_bias_*` always wins.
- Move logits at output slots 0/1 are dead weights — NN cannot evolve motion.
- This is a **mechanic decision** with major selection-pressure implications: a key behavior pathway (NN-driven movement) is permanently disabled.
- If `move_bias_*` mutates (no plan currently), then mutation alone determines motion vector — but there's no plan to mutate them.

**Option (b) — ADD.**
- `vx[i] += move_bias_x[i] * MOVE_SPEED_MAX` (post NN forward-pass).
- NN-derived vx_logit becomes the "intent"; bias is a stochastic perturbation.
- Founders still random-walk (NN forward over zero/random weights yields ~0; bias dominates).
- Evolved descendants can ramp NN motion above bias if selection rewards directed motion.
- Bias decays naturally as `MOVE_SPEED_MAX` clamp truncates large NN+bias sums (or scales NN-output up so bias becomes 5-10% perturbation).

**Cross-reviewer recommendation: ADD (option b).**

Rationale:
1. The brief says "Move += baseline + small random direction-persistence" — the **`+=`** literally reads ADD. SET would have been written `Move = baseline`. p2f's SET reading is an unforced choice.
2. ADD preserves evolvability — the v1.2 brief explicitly wants "the three-tier food chain (grazers / predators / scavengers)". Predators need directed motion to chase prey; SET bottlenecks chasing.

## F. §16 acceptance survival risk + mitigation

**Risk concretely.** Brief locks: founders spawn with `eye_count = 0` AND `nose_count = 0`. At nose_count=0, grass-patch inputs zeroed → hidden-0 "on-grass detector" sees nothing → Graze prior dormant. Move-bias drives Brownian motion (re-rolled every 20 ticks). With 8 initial grass cells × 6.25 sq.u = 50 sq.u of 360,000 sq.u world (≈ **0.014% coverage**), Brownian founders are very unlikely to encounter grass before energy depletes.

p2f §8 explicitly flags this as **HIGH risk**: "Lineage may extinct before grass propagation spreads enough."

Compounding factors:
- `r_in_cell = 0.005` is slow logistic growth (~doubling time 140 ticks once seeded).
- `k_propagate = 0.05` cross-kernel spread → ~5% to each neighbor per tick at full saturation. Initial 8 cells take ~50-100 ticks to spread by one ring.
- Founder upkeep ~0.15/tick (UPKEEP_BASE per p1e §4).
- Founder starting energy ~50 (FOUNDER_START_ENERGY default).
- Time to starve at zero gain: ~333 ticks.

Probability one of 32 founders Brownian-walking covers a 50-sq.u grass patch within 333 ticks: rough estimate around 5-15%. Lineage extinction risk is real.

**Proposed orchestrator mitigation policy for P3e tuning.**

Tuning loop:
1. **First probe**: defaults from brief (`grass_initial_seed_count = 8`, `r_in_cell = 0.005`, `k_propagate = 0.05`, `GRAZE_MAX_PER_TICK = 0.1`). Run `cargo test --release --test acceptance`. If §16 passes → done.
2. **First adjustment if §16 fails**: raise `grass_initial_seed_count` to **50** (per p2f §8 recommendation). This raises coverage to 0.087% — still tiny in absolute, but at N=32 founders each Brownian-walking, capture probability rises substantially. Re-probe.
3. **Second adjustment**: raise to **100** (slider max). Re-probe.
4. **Third adjustment**: raise `r_in_cell` toward 0.02 (faster patch growth so even late-arriving founders catch the patch ring expansion). Re-probe.
5. **Fourth adjustment**: raise `MOVE_BIAS_REROLL_INTERVAL` to 60 ticks (founders walk straight longer; covers more ground). Re-probe.
6. **Fifth adjustment / escalation**: surface as user-confirm question in `docs/research/v1.2-final-report.md` — "founders cannot survive at slider-max grass seeding; need to either raise founder starting energy, increase brain hardwiring strength, or revise founder design (give founders nose_count=1 by default)."

**Plans to amend.**
- Master §B P3e row: amend "tune defaults" to explicit ladder ("start at brief defaults; if §16 fails, raise grass_initial_seed_count to 50, then 100, then raise growth_r, then raise MOVE_BIAS_REROLL_INTERVAL, then escalate to user-confirm").
- p2f §8 mitigation list (1-4): keep as-is; cross-reference to master §B P3e.
- DECISIONS one-line in PR-3 regen entry: "P3e: tuning loop converged at grass_initial_seed_count = N, GRAZE_MAX_PER_TICK = M (acceptance passes T=10000 seed evosim-test-001 sequential and threaded)."
