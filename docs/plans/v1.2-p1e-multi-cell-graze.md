## 2. The graze step itself

```rust
pub(crate) fn graze(&mut self) {
    let n = self.creatures.len();
    if n == 0 { return; }

    for i in 0..n {
        if self.creatures.action_this_tick[i] != Action::Graze { continue; }
        let eff_i = self.creatures.g_graze_eff[i];
        let max_per_cell = GRAZE_MAX_PER_TICK * eff_i;
        if max_per_cell <= 0.0 { continue; }
        let xi = self.creatures.x[i];
        let yi = self.creatures.y[i];
        let ri = self.creatures.g_size[i] * BODY_RADIUS_PER_SIZE;

        let mut total_gain = 0.0_f32;
        self.grass.for_each_cell_overlapping_circle(xi, yi, ri, |cell_idx| {
            let delta = self.grass.consume(cell_idx, max_per_cell);
            total_gain += delta;
        });
        self.creatures.energy[i] += total_gain;
    }
}
```

### Scratch vs direct write

eat_and_scavenge uses scratch buffers because Eat is a two-pass and Scavenge writes back during candidate iteration. Graze has no such constraint: each creature touches only grass cells (not other creatures), and `total_gain` is a per-iteration accumulator. **Decision: write `creatures.energy[i] += total_gain` directly inside the per-creature loop.**

## 3. Determinism for sequential vs threaded

**Invariant: `World::graze` runs SEQUENTIALLY in step 5, regardless of `--features threads`.**

Justification: graze writes to `self.grass.density` (a single shared Vec). Two creatures may overlap the same grass cell (especially post-Split). par_chunks_mut over creatures would race on `density[cell]` writes.

Determinism within sequential graze:
- Outer loop: stable SoA index order (same in both branches).
- Inner loop: row-major order from integer bounding box on torus (no float modulo, no HashMap, no rayon).
- `GrassGrid::consume` is read-min-write; no FP-associative reductions.
- Sequential = threaded bit-identity: graze produces same energy/density sequence both feature builds. S39 equivalence test holds.

## 4. `GRAZE_MAX_PER_TICK` final value

**Locked: `GRAZE_MAX_PER_TICK: f32 = 0.1`.**

Justification:
- A graze_eff=1.0 founder on a max-density cell drains `min(1.0, 0.1) = 0.1` per tick → empties cell in 10 ticks.
- Founder body (size=1.0, radius=1.0) overlaps 1-4 cells; max gain ~0.1*4 = 0.4 energy/tick. UPKEEP_BASE ≈ 0.15/tick → stationary founder on grass survives.
- A size=10 predator (radius 10) overlapping ~121 cells caps at 0.1*121 = 12.1 energy/tick at full density — high but offset by heavy upkeep.
- Cross-ref `r_in_cell = 0.005`, `k_propagate = 0.05`: max-density cell regrows 0.005 if existing + k*neighbors. GRAZE_MAX_PER_TICK = 0.1 sits below worst-case propagation inflow → grazed cells next to clumps recover; isolated grazed cells stay drained.

**Note:** P1c plan locked `0.25` for the same constant. **Cross-reviewer must reconcile P1c vs P1e**; PR-1 commit uses one value. Recommendation: defer final pick to P3e tuning; both pieces declare a const, the actual value gets set in `src/constants.rs` with cross-piece agreement.

## 5. Energy gain semantics — locked formula

The brief at lines 60-61 has an internally inconsistent statement. The task description disambiguates:

**Locked formula:**

```
for each creature i with action_this_tick = Graze:
    eff_i           := g_graze_eff[i]
    max_per_cell    := GRAZE_MAX_PER_TICK * eff_i
    gain_i          := 0
    for each cell k overlapping creature i:
        delta_k     := min(grass.density[k], max_per_cell)
        grass.density[k] -= delta_k
        gain_i      += delta_k
    creatures.energy[i] += gain_i
```

Efficiency factor applied PER-CELL (inside the cap), NOT post-sum. Energy gained equals exactly the grass density consumed (conservation property).

**`eat_efficiency` does NOT enter the graze formula.** Only `graze_efficiency`.

**Edge:** `eff_i = 0` short-circuits.

DECISIONS entry under "## v1.2 grass mechanic":
> P1e (graze formula): brief's "sum of deltas ... multiplied by efficiency" treated as a typo. Lock formula: `gain = Σ min(grass[k], GRAZE_MAX_PER_TICK * eff)`. Efficiency applies in the per-cell cap only; energy gained equals grass density consumed (conservation).

## 6. Edge cases

1. **Creature at world seam.** Integer index wrap via `rem_euclid`, float distance wrap via `wrap_signed`. Both deterministic, no float modulo.
2. **Cell with `grass[cell] = 0`.** `consume` returns 0.0 → no-op.
3. **Creature with `graze_efficiency = 0`.** Early-out fires. Zero overhead.
4. **NaN/negative position.** `floor()` on NaN yields NaN, `as i32` yields 0. Distance check fails (NaN comparison false). Zero gain. Safe.
5. **Overlap with itself across seam.** Max radius 10 vs WORLD_SIZE 600 — impossible.
6. **Two creatures grazing same cell same tick.** Lower SoA index drains first, deterministic order. No two-pass needed.
