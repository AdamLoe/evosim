## Locked decisions (from mission + review's "must do before implementation")

The mission's three-stage shape (postMessage → SAB → polish) stands. The review's ten "must do before implementation starts" edits are folded in as binding constraints:

1. **Path A** — separate SAB outside wasm linear memory; one wasm instance, in the sim worker; main holds no wasm at all. (review C1)
2. **Frustum cull lives on main, JS-side**, reading from the SAB snapshot SoA. `pack_render_buffer` becomes unused and is deleted in Wave C. (review C2)
3. **Snapshot stride grows from 6 to 8 floats** per creature: `[x, y, body_radius, color_r, color_g, color_b, id_lo (u32 reinterpret as f32), id_hi (u32 reinterpret as f32)]`. `creature_stride()` returns 8 post-Wave A. (review C3)
4. **Tick pacing uses `step_n(batch)`**, not `step_n(1)`, with the same fractional-budget accumulator main.ts uses today (`web/src/main.ts:222-232`). (review C4)
5. **Pacing primitive is `Atomics.waitAsync` + `await`** on a futex word in a small "control" SAB. **Not** `Atomics.wait` — that blocks the worker event loop and prevents `onmessage` from ever firing, dark-holing every slider / pause / restart / inspect message. The worker loop is `async`; each iteration `await`s the wait promise so the event loop runs between ticks and drains incoming messages into a JS-side queue. `setTimeout(0)` is forbidden as a pacing primitive at any TPS. Browser support: Chrome 87 / Firefox 119 / Safari 16.4 — all ≥ 2 years old. (review C5 + plan-review C1)
6. **Snapshot stats block** carries `tick`, `pop`, `world_ended`, `tps`, `jank_count`. (review I8)
7. **Rust API gains `write_snapshot_to(...)`** taking three `js_sys::Uint8Array` (creatures, grass, stats). Old `creatures_buffer`/`grass_buffer_u8`/`creature_ids_buffer` exports stay through Stage 1 and are deleted in Wave C. (review I1)
8. **Message-protocol table is canonical** — see §Sim-bridge message protocol below. Discriminated unions live in `web/src/sim-bridge.ts`. (review I2)
9. **Stage 1 acceptance is "correctness, not perf"** — postMessage's structured-clone cost may regress FPS at high pop; that's expected and exits at Stage 2. (review I5)
10. **Time budget is 3–4 days.** Stage 1 alone is a full day; Wave B is the long pole (1.5 days). (plan-review correction to the original 2.5–3 estimate)

Additional locked items from the review's "Add to scope":

11. **Worker-stats and perf-report polling** are 750 ms / 1 s request-reply, not per-frame. (I4)
12. **`crossOriginIsolated` check happens twice** — once on main (decides whether to spawn a threaded sim worker), once in the sim worker (re-verifies after `initThreadPool`, runtime-warn if `rayon::current_num_threads() <= 1`). **Both sides read the JS global directly** (`globalThis.crossOriginIsolated` / `(self as unknown as { crossOriginIsolated?: boolean }).crossOriginIsolated`) — no Rust export needed. (I6 / I9 + plan-review C3)
13. **Slider drain ordering** — the sim worker drains the postMessage queue at the **top of each loop iteration**, before `step_n` and the snapshot write. A slider sent at tick T takes effect for tick T+1, deterministically. (I7)
14. **Restart blip target 500 ms, realistic ~600 ms** with rayon re-init (not the mission's optimistic 100 ms). Render keeps painting the last-good frame during the gap. (I3 + plan-review polish)

15. **First-paint handshake**: the sim worker runs **one tick and writes one snapshot** (Stage 1 postMessage; Stage 2 SAB) **before** posting `boot_ready`. Main is guaranteed a valid first frame; no zero-pop ghost frame. (plan-review C5)

16. **Stage 1 acceptance ceiling is pop ≤ 1500** (matches mission success criterion #1). Beyond that, structured-clone cost may regress FPS — and that's **what Stage 2 closes**. Wave B is **not** allowed to land on `main` if pop=1500 is unusable; and Wave B + Wave C are **not bundled** into one merge — staging guarantee preserved so the bisect surface stays narrow. (plan-review I9)

17. **Snapshot stride-6→8 transition is single-renderer-safe**: the renderer's stride guard accepts `stride === 6 || stride === 8` during the A1→B window so a dev-server boot between A1 landing and B landing doesn't throw. The tolerant guard is removed in Wave C (stride is stably 8 from B onward). (plan-review C4)

No user override sheet for v1.6. The review's recommendations are accepted in writing here.

## Sim-bridge message protocol (canonical)

Single source of truth for both sides. `web/src/sim-bridge.ts` exports these as discriminated unions; Wave A materializes them. `request_id: number` is a monotone u32 minted on the main thread.

### main → worker

| `kind` | payload | freq |
|---|---|---|
| `boot` | `{ seed: string, initial_grass_seed_count: u32, energy_max: f32, founder_count: u32, initial_sliders: Record<string, number> }` | once at worker spawn |
| `set_slider` | `{ name: string, value: number }` | per slider input event |
| `set_target_tps` | `{ tps: number }` | per TPS dropdown change |
| `set_paused` | `{ paused: boolean }` | per space / play-pause click |
| `inspect_at` | `{ wx: f32, wy: f32, tolerance_world: f32, request_id: u32 }` | per canvas click |
| `inspect_id` | `{ id: number, request_id: u32 }` | per inspector refresh frame (worker can resolve id → idx → JSON without an extra round-trip) |
| `request_nn_stats` | `{ request_id: u32 }` | 750 ms |
| `request_profile_report` | `{ request_id: u32 }` | 1000 ms |
| `profile_enable` | `{ on: boolean }` | per checkbox toggle |
| `reset_jank` | `{}` | per button click |

`set_*` and `profile_enable` writes are wake events: main calls `Atomics.notify(controlI32, FUTEX_WORD, 1)` after `postMessage` so the worker breaks out of `Atomics.waitAsync` and drains the queue before the next tick.

**Bool sliders ride `set_slider`.** `auto_curriculum` (the only bool DevSlider) is sent as `set_slider({ name: "auto_curriculum", value: 0|1 })`. The worker calls `world.set_slider("auto_curriculum", value)`; Rust's `try_set_slider` gains a `"auto_curriculum" => self.apply_auto_curriculum(value != 0.0)` arm. No dedicated message kind; no per-typed `set_auto_curriculum` wasm export. Keeps the protocol surface minimal.

Restart is **worker termination + respawn**, not a message. Main calls `worker.terminate()` and `new Worker(...)`; the new worker boots with a fresh `boot` payload. Old SAB views remain valid (the SAB stays GC-rooted until the new boot_ready arrives); the renderer keeps painting the last-good frame during the ~500 ms blip.

### worker → main

| `kind` | payload | freq |
|---|---|---|
| `boot_ready` | `{ world_size: f32, grass_dim: u32, threads: u32, rayon_ok: boolean, max_pop_for_sab: u32, snapshot_sab: SharedArrayBuffer \| null, control_sab: SharedArrayBuffer \| null }` (SABs are `null` on Stage 1; populated from Stage 2 onward) | once per worker lifetime — posted **after** the worker has run one tick and written one snapshot, so main's first frame is guaranteed valid (plan-review C5) |
| `snapshot` | **Stage 1 only**: `{ tick: u32, pop: u32, tps: f32, world_ended: boolean, jank_count: u32, creatures: Uint8Array, grass: Uint8Array, ids: Float64Array }` — replaced by SAB writes in Stage 2 | once per batch (NOT once per tick) |
| `inspect_reply` | `{ request_id: u32, json: string \| null }` | once per `inspect_at` / `inspect_id` |
| `nn_stats_reply` | `{ request_id: u32, json: string }` | once per `request_nn_stats` |
| `profile_reply` | `{ request_id: u32, json: string }` | once per `request_profile_report` |

### SAB layout (Stage 2 onward — Wave C materializes)

Two SABs are created in the sim worker (`new SharedArrayBuffer(byteLen)`) and posted to main via `boot_ready`:

**Control SAB** — 16 bytes (`Int32Array(4)`):
- word 0: `current_slot` (u32, atomic) — which snapshot slot is live (0 or 1). Sim worker writes the inactive slot, then `Atomics.store(ctrl, 0, new_slot)` flips.
- word 1: `seq` (u32, atomic, monotone) — incremented after every flip so render can tell if a new snapshot is available.
- word 2: `futex` (u32, atomic) — futex word the sim worker `Atomics.waitAsync`s on. Main `Atomics.notify(controlI32, 2, 1)` after every `postMessage` to wake the worker.
- word 3: reserved.

**Snapshot SAB** — two slots, each:
- offset 0: stats header (5 × 4 bytes = 20 bytes) → `[tick: u32, pop: u32, world_ended: u32 (0/1), tps_bits: u32 (f32::to_bits), jank_count: u32]`. TPS is stored as the raw bit pattern of the f32 — same 4 bytes, exact round-trip, no encoding decision to document. Stage-2 readers do `new Float32Array(buf, offset + 12, 1)[0]`.
- offset 20 → 32: **12 bytes of padding** to 32-byte align the creature SoA that follows. Stride is 32 bytes per creature, so creature 0 must start 32-byte aligned for typed-array views to be valid (Chrome/Firefox enforce alignment on `Float32Array(buf, offset, len)` constructors). Do **not** trim this padding to save bytes.
- offset 32 (aligned): creature SoA, capacity `MAX_POP_FOR_SAB` × 32 bytes. **`MAX_POP_FOR_SAB = 8000`** (matches the initial-seed-N slider ceiling, gives headroom). Slot creature cap = 256 KB.
- offset (32 + 256 KB): grass density u8, `GRASS_CELL_COUNT = 230_400` bytes.

Per-slot size ≈ 256 KB + 230 KB + header ≈ 487 KB. Two slots ≈ 974 KB. Allocated once at worker boot; never resized.

Snapshot writer (in Rust, `WorldHandle::write_snapshot_to`) writes `pop` ≤ MAX_POP_FOR_SAB creatures. Population that would overflow → log-warn + truncate (deterministic, dead creatures simply aren't rendered for that frame). Pop is allowed to exceed cap because `founder_count` is bounded but births aren't, so we need an honest overflow story.

**Cross-language `MAX_POP_FOR_SAB` sync**: the `boot_ready` reply carries `max_pop_for_sab: number` sourced from the Rust constant; main asserts it equals the TS `MAX_POP_FOR_SAB` constant at handshake time and throws if they disagree. Single point of failure, immediate detection. (plan-review I2)

- `src/wasm_api.rs`:

The renderer will reinterpret the last two slots as u32 via `new Uint32Array(buf.buffer, buf.byteOffset + off + 24, 2)`.

### Step A2 — `feat(web): sim-bridge.ts message protocol + SAB layout types`

**Mission section:** review §I2 (message-protocol table) + §C1 (Path A SAB ownership) + §C5 (pacing primitive / futex word) + plan §"Sim-bridge message protocol".

**What you're doing:** Materialize the discriminated-union types for the worker boundary. No runtime code; only TypeScript types, constants, and helpers. Wave B imports this; Wave C extends the SAB layout helpers.

**Files to touch (only one):**

- `web/src/sim-bridge.ts` (new file). Contents:

  - `export const MAX_POP_FOR_SAB = 8000;` (matches Rust constant; Wave B asserts equality against the `boot_ready` payload's `max_pop_for_sab` field — throws on mismatch).

### Step D — `feat(arch): Atomics.waitAsync pacing + step_n batch + inspector fast-path`

**Mission section:** v1.6-mission.md §"Stage 3 — Async inspector + slider polish" + review §C4 (`step_n(batch)`) + §C5 (pacing primitive) + §I7 (slider drain ordering) + §I9 (runtime rayon check).

**Files to touch:**

- `web/src/sim-worker.ts`:
  - Set up a JS-side message queue:
    ```ts
    const messageQueue: SimMessage[] = [];
    self.onmessage = (e: MessageEvent<SimMessage>) => { messageQueue.push(e.data); };
    function drainMessages(): void { while (messageQueue.length) handle(messageQueue.shift()!); }
    ```
  - Convert the sim loop to **`async` + `Atomics.waitAsync`** (NOT `Atomics.wait` — that blocks the worker event loop and prevents `onmessage` from ever firing; pseudocode in the previous draft of this plan was buggy). The `await` is what lets `onmessage` callbacks run between iterations:
    ```ts
    async function simLoop(): Promise<void> {
      while (!terminated) {
        drainMessages();                          // reads from messageQueue (filled by onmessage during prior await)
        const now = performance.now();
        const elapsed = now - lastTickWallMs;
        lastTickWallMs = now;
        budget += targetTPS * (elapsed / 1000);
        if (budget > MAX_TICKS_PER_BATCH) budget = MAX_TICKS_PER_BATCH;
        const batch = Math.floor(budget);
        budget -= batch;
        if (paused || worldEnded) { budget = 0; }
        else if (batch > 0) {
          world.step_n(batch);
          const writeSpan = span("worker.snapshot.write");
          writeSnapshotToSAB();                   // SAB flip + seq bump
          writeSpan.close();
        }
        // Pacing wait. When paused, sleep forever (woken by set_paused(false) notify) so
        // we don't burn CPU on snapshot writes nobody's looking at. (plan-review polish)
        const timeoutMs = paused ? Infinity : Math.max(0, (1000 / targetTPS) - (performance.now() - now));
        const before = Atomics.load(ctrl, CTRL_FUTEX);
        const r = Atomics.waitAsync(ctrl, CTRL_FUTEX, before, timeoutMs);
        if (r.async) await r.value;               // event loop runs here → onmessage fires → queue fills
        // r.async === false ⇒ "not-equal" (main already notified) — fall straight through.
      }
    }
    simLoop();
    ```
  - `MAX_TICKS_PER_BATCH = 2000` (mirrors main.ts's current cap).
  - After `initThreadPool`, call new wasm-bindgen helper `rayon_current_num_threads()` (export from Rust); if `<= 1`, `console.warn("[sim] rayon collapsed to 1 thread — sim will run single-threaded; check COOP/COEP and build flags")`. Hard guard against the v1.5 footgun.

## Section 4 — Ambiguities surfaced

(Items the mission AND review left open — recommendations attached.)

1. **id encoding in the stride-8 layout.** Mission/review say `[id_lo: u32, id_hi: u32]`. The cleanest Rust→JS path is `f32::from_bits(u32)` on the Rust side and `new Uint32Array(buf.buffer, offset, 2)` on the JS side over the same memory. Recommend that pattern (no double-conversion cost). Wave A1 uses it.
2. **`MAX_POP_FOR_SAB` ceiling.** Mission silent; chose 8000 to match the `initial seed N` slider's `web/src/widgets/devpanel.ts:382` ceiling and give 2× headroom on the practical worst-case observed in v1.5 testing (~4000). Truncation on overflow is log-warned but doesn't crash. If the user routinely runs pop > 8000, bump the const and rebuild — single source of truth in both `src/constants.rs` and `web/src/sim-bridge.ts`. Wave A2 runtime-asserts both consts agree.
3. **Snapshot-write profile span lives TS-side as `worker.snapshot.write`** (not Rust-side). Reason: `write_snapshot_to` is called from JS (sim-worker), not from `World::step`, so a Rust span would orphan at root level instead of nesting under `tick.*`. TS-side `span()` already handles non-Rust spans (e.g., `grass.upload.gpu`). Wave C wires it; Wave A's earlier "add inert span Rust-side" idea was wrong and is dropped. (plan-review C2)
4. **`SimBridge` class home.** Pure types in `sim-bridge.ts` (Wave A2). The runtime `SimBridge` class lives in the *same file* in Wave B — keeps the discriminated unions and their dispatcher together. Alternative was a separate `sim-bridge-runtime.ts`; rejected for one fewer import hop.
5. **Inspector reply ordering.** Two pending `inspect_id` requests in flight (rare — only happens if main's RAF runs faster than the worker can reply). Wave B handles by tracking `lastSentRequestId` and ignoring replies where `request_id < lastSentRequestId`. Cheap; deterministic.
6. **`rayon::current_num_threads()` timing.** Mission silent. Called immediately after `initThreadPool` resolves; that's the latest the value can change. Wave D wires the warning there.
7. **`reapplyDevSliders` on restart.** v1.5 used a 20-call burst (`web/src/widgets/devpanel.ts:112-135`). Post-decoupling: the new worker's `boot` message carries an `initial_sliders` map, so there's NO burst — the worker applies them before its first tick. Cleaner than messaging 20 setters post-boot. Wave B wires this.
8. **Profiler `frame.snapshot.read` span.** TS-side span name added in Wave C. Mission silent on the name; this matches the existing `grass.upload.read` / `frame.*` naming convention.
9. **`world.tps` rolling window post-decoupling.** Lives in `WorldHandle` (Rust), so it tracks worker-side tick wall time, not main-thread frame time. That's the intended semantic (sim TPS, not render FPS). Surface as `tps_bits` (raw `f32::to_bits`) in the snapshot header per locked decision 6 — reader does `Float32Array(buf, offset + 12, 1)[0]`.
10. **Stage 1's structured-clone budget at pop > 4000.** Review §I5 noted Stage 1 may regress FPS at high pop. **Resolved by locked decision 16**: Stage 1 acceptance is pinned at pop ≤ 1500. Beyond that, the structured-clone cost is allowed to regress FPS — that's what Stage 2 closes. Wave B is **not** allowed to bundle into Wave C as an escape hatch (would widen the bisect surface). 11. **`pack_render_buffer` deletion timing.** Wave C deletes it. Wave B is allowed to leave it in place even though no JS caller uses it — keeps the diff smaller. Either timing works; recommend Wave C (single death, single commit).
12. **`set_paused` semantics in the worker.** When paused, the worker drains messages but skips `step_n` and resets `budget = 0`. **Pacing wait switches to `Atomics.waitAsync(..., Infinity)`** so the worker parks until `set_paused(false)` notifies the futex — no 60 Hz idle wake, no snapshot churn nobody's reading. The last snapshot before pause stays visible (main keeps painting from it). On unpause, the next iteration's `drainMessages` consumes the unpause message, `budget` accumulates from the wall-clock delta since pause-start. (plan-review polish)
13. **Worker termination during a `step_n(batch)`.** `worker.terminate()` is unconditional; an in-progress wasm call is dropped. SAB views on main remain valid (the SAB stays alive); rayon child workers are GC'd with the parent. Restart re-allocates everything. Mission silent; no special handling needed.
14. **Auto-run / world-ended restart.** v1.5's `autoRun` setting restarts on `world_ended`. Post-decoupling, main observes `world_ended` in the snapshot header; restart is `worker.terminate() + new Worker`. Same trigger, different mechanism. Wave B preserves the setting; restart timing is dominated by the ~500 ms rayon re-init (locked decision 14).
15. **`profile_enable` ordering with snapshots.** `profile_enable(true)` is a message; the worker applies it between `drainMessages` and `step_n`. The next tick's `tick.*` profile samples reflect the new state. No race.
