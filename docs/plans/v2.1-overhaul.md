# v2.1 — shippable neuroevolution overhaul (hub)

## Mission

Turn evosim into a shippable single-pool **neuroevolution** sandbox. Four
coupled moves: (1) cut the 6-trait body genome so the brain is the only
heritable thing; (2) reduce biomes to **dead-grass avoidance zones** (food
absence, not a movement tax); (3) replace the anti-selection hard random
cull with a **food-limited, density-dependent equilibrium** that exposes
live tuning knobs; (4) add full per-creature **NN input/output inspection**
and rebuild the **settings panel** into one navigable surface (sim settings
+ profiler + NN editor) behind a minimal top bar. Done = a fresh page load
produces a population that self-stabilizes below the pop cap, visibly
improves at foraging over generations, is inspectable per-creature, and
sits behind a polished settings UI.

## Why now

Today a creature's heritable state is brain weights **plus** a 6-trait
genome that modulates biomes, combat, speed, and metabolism — many coupled
levers that make equilibrium untunable and muddy the "is the brain getting
smarter?" question. And the `MAX_POP_FOR_SIM` **random cull** is both the
boom-bust ceiling and an anti-selection mechanism (it kills good and bad
foragers equally), so selection never compounds. v2.1 removes both
problems at their root before any UI polish.

## Scope

**In:** genome removal, biome reduction, equilibrium rework + tuning
sliders, NN inspection, settings/profiler UI overhaul, top-bar reduction.

**Out (for v2.1):**
- **Species + sexual mating** stays as an optional toggle — not tuned, not
  featured. It must keep compiling/passing tests, but multi-species
  differentiation is explicitly deferred.
- No save/load, no new world-generation, no new biome types.

blind — inspection is the instrument for P2/P3. **P2 before P3** because a
simpler model has a far smaller tuning surface. **P4 mostly independent** of
sim internals and can run alongside P2/P3, but its settings-row wiring must
land **after** P2/P3 finalize the slider set (genome/biome sliders removed,
equilibrium sliders added) — so P4 splits into a UI-structure stream (early)
and a slider-wiring stream (last).

  `app/web/tests/e2e/defaults-drift.spec.ts`.
- **Cross-feature equivalence** stays green throughout: `cargo test --lib`
  **and** `--features threads` both pass at every commit.
- **Species mode keeps compiling.** Every phase that touches sim core must
  keep `species_mode` building and its tests green even though it is
  unfeatured.
- **Rust-canonical defaults.** Any new slider's default lives in Rust
  (`constants.rs`) and is mirrored into `settings.ts` + the drift fixture.

## Resolved decisions (settled 2026-06-11)

The forking questions are decided; they are folded into the phase plans.

1. **Creature coloring** (P2) → **lineage / ancestry color**: hue inherited
   at split with a small mutation so descendants share a color and lineages
   are visible blooming/dying. Makes evolution legible on canvas.
2. **Biome penalty** (P2) → **strip the tax, food-only**: remove
   `K_BIOME_SPEED/COST/UPKEEP` and the water/desert movement-penalty
   sliders; keep **only** the grass-capacity cap. Biomes do exactly one
   thing — no food there.
3. **P3 success metric** → **stable band + foraging trend**: population
   holds a target band over T ticks across K seeds (no extinction, no
   cap-pinning) AND a foraging proxy (avg energy gathered per lifespan, or
   avg lifespan) trends upward.
4. **Settings IA** (P4) → **left sub-nav categories**: a vertical category
   list inside the panel; the profiler and NN editor are their own entries.

One sub-decision stays inside P2 as an implementation choice (not a
ship-level fork): whether the NN biome inputs are dropped entirely or
replaced with a compact raw biome-type signal — see
[`v2.1-p2-simplify-model.md`](v2.1-p2-simplify-model.md).
