## User overrides applied (post-mission)

These differ from the locked mission defaults. They take precedence everywhere below.

1. **`CURRICULUM_MIN_FACTOR` default = `0.0`** (not `0.25`). User wants the floor to actually anaesthetize at low pop by default, with a knob to tune it. Add a new `curriculum_min_factor: f32` field to `DevSliders` (range `[0.0, 1.0]`, step 0.05, default 0.0) and a corresponding wasm setter + UI slider. User can dial it up to 0.25 if they want the review-recommended floor, or set `min_pop=0` to scale from zero.
2. **No `nearest_creature_color` NN input.** Slot 28 becomes padding (`0.0`). The 32-input layout is otherwise unchanged. Predator-recognition is deferred to a future release that adds directional color inputs (per-sector dominant color rather than a single scalar).
3. **`creature_stride` = 6** (drop all four `flag_*` slots). Confirmed.

These overrides are baked into Steps 3, 4, 5b prompts below.

## Section 2 — Wave plan

### Wave A — 4 agents in parallel; worktree-isolated; background

Each lands one atomic commit on its worktree branch. Merge order during reconciliation:

1. **S1 (sliders+TPS+overlay+founder_count)** — biggest surface. Merge first.
2. **S2 (threading dynamic)** — small. Merge second.
3. **S4 (curriculum)** — additive DevSliders fields + apply factor in 3 sites. Merge third.
4. **S3 (color overhaul)** — most invasive (creature.rs, brain.rs, wasm_api.rs, inspector.ts, render-gl.ts, tick.rs, nn.rs). Merge last.

Light reconciliation done inline by orchestrator (DevSliders block, Settings interface, devpanel UI). Spawn dedicated reconciler only if any wave fails its gates.

### Wave B — 1 agent serial

**S5a — NN topology only.** Pyramid `NN_INPUTS(112) → 48 → 24 → 5`, Leaky ReLU, tanh on velocity, per-layer He init. Existing 112 inputs unchanged. NN_WEIGHT_COUNT becomes `112*48 + 48*24 + 24*5 = 6648` for this commit (mission's "still 2808" claim assumes 32 inputs — only reached after Wave C lands).

### Wave C — 1 agent serial

**S5b — NN inputs rewrite.** 32-input semantic layout. Deletes `vision.rs`, deletes `VisionPass`, deletes `World::vision`, deletes SoA columns (`eye_trig`, `last2_action`, `prev_energy`), deletes vestigial `first_*_fired`/`peak_population`/`population_milestones_fired`. Adds `proximity.rs` with sector LUT + per-creature 8-accumulator scratch + wall_proximity + creature_proximity (bilinear) + grass_density (per-row-bitset gated). `NN_INPUTS=32`, `NN_WEIGHT_COUNT=2808` (assert).

### Wave D — 2 agents in parallel

1. **S6 — grass scale-up.** Cell size 5u→1.25u, 480×480 cells, R8 GPU upload, parallel `step`, per-row bitset confirmed.
2. **doc-cleanup.** Fix `wasm_api.rs` doc comments (R32F→R8 references, 5.0→1.25); remove stale M5 NN-weight-hash references in code comments.

Light textual conflicts only. Inline reconciliation.

### Wave E — verify

Runtime smoke per `docs/dev-server-prompt.md`. Rebuild wasm with `--features threads`, launch dev server `:47821`, browse and confirm: (a) sim runs at pop > 100 without panic, (b) colors visibly differentiate by action, (c) grass renders 480×480, (d) all new sliders functional, (e) settings overlay opens/closes cleanly, (f) inspector displays EMA RGB. Capture `profile_report_json()` at pop=1000 for the perf comparison.
