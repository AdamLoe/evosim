# v1.3 D3 — Genome entirely deleted

## 1. Scope summary

Delete the entire genome system: the `src/genome.rs` module, the `Genome` struct, `TraitMutationRates`, all body trait fields (size / max_age / graze_eff / eat_eff / scavenge_eff / move_speed / vision_range / eye_count / eye_offsets / nose_count / armor / bite_reach / pigment_r/g/b), the body mutation kernel, all `g_*` SoA hot-mirror Vecs on `CreatureSoA`, the founder genome anchor, and the body-mutation step in `handle_births`. After this piece lands, every creature is structurally identical: body radius = `FOUNDER_SIZE = 1.0`, max age = `FOUNDER_MAX_AGE = 5000`, move speed cap = `MOVE_SPEED_MAX = 5.0`, vision = 24 sectors at `VISION_RANGE_MAX = 80.0`. The ONLY per-creature variation is the NN weight vector. This is the largest single deletion in v1.3 (~500–1000 lines).

## 6. Risks

1. **NN dim mismatch breaking the build.** Removing `g_*` reads in `build_nn_input` shifts every input offset. If `NN_INPUTS` stays 160 with zeroed slots, the SIMD chunking (`INPUT_CHUNKS = 20`) still works but ~9 slots become permanently zero. If `NN_INPUTS` shrinks (D9's call), the `const _: () = assert!(NN_INPUTS == 160)` in `brain.rs` fires and `INPUT_CHUNKS` must change. **Mitigation:** coordinate the constant change with D9.
2. **UI panels break silently if not coordinated.** `creature_inspect_json` returns a different JSON shape; inspector.ts will throw on missing keys. **Mitigation:** require D3's commit to include the inspector JSON shape change AND the inspector.ts update OR explicit M4 cross-piece dependency.
3. **`Brain::child_from` path needs rewrite.** Currently `handle_births` does both `genome.mutate_in_place` AND `brain.child_from`. After D3, only the brain mutation survives. Also the `move_bias_*` re-init lines at lines 488-491 depend on `move_bias_*` fields which are NOT in D3's scope but ARE in D6/Q6's scope. Cross-check ordering.
4. **`recompute_eye_trig_at` becomes trivial.** All creatures have the same 24-sector trig table. Computing it per-creature wastes memory. Risk: leave the per-creature `eye_trig: Vec<f32>` and miss a 96 KiB/creature × N savings. Flag as a Q-perf follow-up; D3 should NOT lift the trig to a const yet (out of scope, the brief explicitly bumps perf to Phase 6 follow-up).
5. **Test fixture sprawl.** ~50 tests need rewrite or delete. Risk: an `assert_eq!` in a surviving test still references a deleted field, producing a build break in `cargo test` but not `cargo build`. **Mitigation:** run `cargo test --lib --no-run` early in the implementation.
6. **`max_size_reached`, `cumulative_upkeep`, `digestion_cooldown`.** These three SoA fields are NOT in D3's deletion list but their meaning changes. `max_size_reached` is now constant — delete. `digestion_cooldown` is still meaningful (eat action). `cumulative_upkeep` was used by carrion (D2) — already deleted by D2.
