# Benchmark Recipe — v2.0.5

Fixed measurement scenario for v2.0.6 S9 and any future before/after perf
comparison. Values are pinned against the current Rust and TypeScript defaults.
This is intentionally retained as a long-lived runnable reference.

---

## 1. Seed Policy

| Field | Value | Rationale |
|---|---|---|
| `world_seed` | **42** | A fixed non-zero u32 pins biome generation (Water/Desert blob placement + species anchor positions). A zero seed causes `new_with_founder_count` to draw a random value; any non-zero value is used as-is. |
| String RNG seed | **`bench-v2.0.5`** | Pins single-pool founder brains/genomes and the sim RNG stream. Launch with `?seed=bench-v2.0.5`. |

**Threaded trajectory note:** the threaded scatter kernel uses lossy relaxed
cross-tile writes, so trajectories can still diverge after tick 0 even with both
seeds pinned. The two seeds do pin the initial world: `world_seed` pins biome and
grass-clump layout; the string seed pins founder brains/genomes and the sim RNG
stream. Single-pool founder positions are the deterministic Halton sequence.
Use warmup + a windowed average rather than exact-output matching.

representative of the baseline sim, and avoids the extra per-tick species-aware

alternative (ON with 10 seeded species) was considered and rejected: it adds
`starting_species_count * starting_species_member_count = 100` founders plus
16-sector NN input overhead, making the baseline heavier and harder to interpret.
If a future wave explicitly benchmarks species mode, add a parallel bench run
marked `species_mode=ON` and compare against this recipe as the baseline.

## 4. Target TPS and Measurement Methodology

| Param | Value | Source |
|---|---|---|
| `targetTPS` | **uncapped** (set to 9999 or highest available) | `settings.ts` DEFAULTS has `targetTPS: 180`; see below |
| Profiler window | **10 000 ms** (10 s) | `settings.ts` `profilerWindowMs: 10_000` |

**TPS methodology: uncapped (run as fast as possible).**

The target TPS (default 180 in `settings.ts`; `CTRL_TARGET_TPS_BITS` SAB lane
in `web/src/generated/control-sab.ts`) acts as a pacing cap — the worker sleeps
for the remainder of the 1000/targetTPS ms slice after each tick. Measuring at
the capped default (180 TPS) reveals wall-clock throughput but not
compute-time-per-tick: a tick that takes 2 ms will still sleep ~3.6 ms to hit 180
TPS, so `tick.total` in the profiler will look fast even if we have headroom to
spare.

For a **perf comparison** the relevant quantity is the time to execute one tick
at the same population and grass density, not the sleep budget. Therefore:

- Set `targetTPS = 9999` (or the largest value the slider allows) before
  starting the measurement window. This removes the sleep and lets the profiler
  report raw compute cost.
- Observe the **achieved TPS** from the snapshot header `tps_bits` field (or the
  on-screen TPS counter). This is the ground truth for "how fast is the sim
  actually running."
- Record achieved TPS as the primary perf metric; the profiler span durations are
  the diagnostic decomposition.

**Alternative considered:** measuring at capped 180 TPS to simulate "real user
experience." Rejected for before/after perf comparison because: (a) a tick that
is cut in half may still be pacing-limited at 180 TPS, making improvement
invisible; (b) the profiler's rolling-average durations are accurate at both cap
levels, but comparing achieved TPS across code changes is more meaningful when
the cap is not the bottleneck.

## 5. Viewport and Zoom

| Param | Value | Source |
|---|---|---|
| Canvas CSS size | **1920 × 1080 px** (or as close as the display allows) | `crates/evosim/src/wasm_api/mod.rs → write_snapshot` default-scale contract |
| Initial zoom | **1.0** | `web/src/render/camera.ts → makeCamera` |
| Camera center | **(4800, 4800)** (world center = `worldSize / 2`) | same |
| LOD level at these settings | **mip level 0** (full resolution) | `write_snapshot` LOD formula: visible_cell_span_x = (9600 / 1.0) / 5.0 = 1920; ratio = 1920 / 4096 ≈ 0.47 < 1.0 → level 0 |

**Why viewport matters:** `write_snapshot` in `crates/evosim/src/wasm_api/mod.rs` takes camera
parameters and computes the grass clipmap window every tick. The window size
(and whether it triggers mip level 0 vs level 1+) directly affects
`write_output_sab.snapshot.grass_copy` cost. At zoom = 1.0 and a 1920-wide
canvas the full 1920 × 1620 cell window is written at level 0 — the most
expensive path. Pinning zoom = 1.0 + 1920 × 1080 ensures the before/after
comparison hits the same code path.

**Resize note:** the canvas size is set by the OS/browser window. Use the
browser's DevTools device emulation to fix `1920 × 1080` if the measurement
machine has a different screen. The sim does not cap rendering to a smaller
logical size.

## 6. Warmup

| Param | Value | Rationale |
|---|---|---|
| Discard ticks | **first 2000 ticks** (≈ 11 s at 180 TPS; ≈ 4 s uncapped at ~500 TPS) | Grass coverage and creature population need time to reach quasi-steady state. At tick 0 the world has 32 founders and 40 seeded grass clumps of radius 8. By tick ~1000–2000 the population typically reaches its first growth plateau and the grass scatter has spread across viable cells. |
| Population target | **steady state** — the population histogram should not be in early exponential growth; the on-screen counter should be oscillating or growing slowly before measuring. | |

**Practical warmup procedure:** boot with both pinned seeds and `targetTPS =
9999`. Wait until the on-screen population counter stops growing rapidly (the
"hockey stick" phase ends). For the default settings with `max_population = 8000`
this takes roughly 1000–3000 ticks. Then use "Reset profiler + jank" and start
the measurement window.

---

## 7. Profiler Window

| Param | Value | Source |
|---|---|---|
| Window duration | **10 000 ms** (10 s) | `web/src/settings.ts` `profilerWindowMs: 10_000`; `crates/evosim/src/wasm_api/mod.rs → profile_set_window_ms` clamped [500, 600_000] |
| Minimum sample count | Wait until **at least 500 ticks** fall inside the window before reading | At 50 TPS (heavy load), 500 ticks = 10 s exactly; at 500 TPS, 500 ticks = 1 s, well within the window. |

The profiler emits rolling-window means for each span. At the 10 s window and
typical 50–500 TPS uncapped, the mean will be well-averaged. Do not shrink the
window below 5000 ms for a before/after comparison; noise increases
proportionally.

## 8. What to Record

Capture the following from the perf panel's profile report:

### Tick sub-tree (Rust profiler, `tick` root)

| Span | Notes |
|---|---|
| `tick` | Total per-tick sim work (the outer span wrapping all phases). Primary perf number. |
| `tick.grass_step` | Stochastic scatter kernel pass across the 3.7 M cell grid. Usually the dominant tick cost at default settings. |
| `tick.pyramid_refresh` | `grass.refresh_pyramid()` rebuilding the LOD mip levels. Added in v2.0.5 S1 — previously unprofiled. |
| `tick.grid.rebuild` | Spatial hash grid rebuild. |
| `tick.nn` | Parallel NN forward pass across all creatures (rayon). |
| `tick.movement` | Creature movement + biome penalty application. |
| `tick.movement.integrate` | Velocity integration + movement cost. |
| `tick.movement.repulsion` | Repulsion scan using the start-of-tick grid. |
| `tick.movement.apply` | Apply repulsion forces + clamp/wrap. |
| `tick.graze` | Grass-bite resolution. |
| `tick.attack` | Attack resolution. |
| `tick.handle_births` | Birth + population-cap cull. |
| `tick.collect_deaths` | Death sweep. |
| `tick.energy_bookkeeping` | Per-tick energy drain + clamp. |
| `tick.bookkeeping_tail` | Residual bookkeeping (NN stats, genome tracking). |

### sim_worker sub-tree (worker spans routed through Rust profiler)

| Span | Notes |
|---|---|
| `sim_worker` | Total per-iter worker wall-clock (includes read + tick + write + profiler). |
| `sim_worker.tick` | Wall-clock time the worker spends on `world.step_n(1)`. Should closely track `tick` above. |
| `sim_worker.write_output_sab` | Total snapshot + other SAB write time. |
| `sim_worker.write_output_sab.snapshot` | `write_snapshot` total (all sub-phases). |
| `sim_worker.write_output_sab.snapshot.creatures` | Creature SoA pack into the snapshot buffer. |
| `sim_worker.write_output_sab.snapshot.grass_copy` | Grass clipmap window copy via `pyramid.viewport_window`. |
| `sim_worker.write_output_sab.snapshot.biome` | BiomePyramid clipmap window copy. |
| `sim_worker.read_input_sab` | Control SAB read (slider/camera/pause reads). |

### Scalar metrics to capture alongside profiler spans

| Metric | How to read | Notes |
|---|---|---|
| Achieved TPS | Perf-panel TPS counter | Primary perf number; all span durations are per-tick means. |
| Population | On-screen population counter or snapshot header `pop` field | Ensures before/after comparison runs at comparable population. |
| Tick number | Snapshot header `tick` field | Confirms warmup has elapsed. |

```
       grass_clump_size = 8     (already default)
       grass_multisight = true (already default)
       init_graze_boost = 1.0  (already default)
       init_split_boost = 1.0  (already default)
       species_mode = false    (already default)

  3. Set live settings:
       max_population = 8000   (already default)
       grass_decay_pct = 0.04  (already default)
       [all other live sliders: leave at defaults, see Section 3 above]

  4. Click Apply, then hard-reload `/?seed=bench-v2.0.5`.
     Do NOT click Restart: Restart intentionally clears the URL string seed.
     The seeded reload pins the string seed and persisted world_seed = 42 pins
     biome/clump generation.

  5. Set targetTPS = 9999 (uncapped) via the TPS slider in the perf panel.

  6. Confirm browser viewport CSS size = 1920 × 1080 (DevTools device emulation).
     Confirm zoom = 1.0 (the camera resets on hard reload).

WARMUP:
  7. Wait until the population counter is no longer in rapid exponential growth
     (typically tick 1000–3000 at these settings). Do not start measuring during
     the early growth spike.

  8. Click "Reset profiler + jank" to clear accumulated samples.

  9. Wait for ≥ 500 more ticks to fall in the 10 s profiler window.

RECORD:
  10. Open the perf panel. Capture:
        - Achieved TPS (on-screen)
        - Current population
        - Current tick
        - All span mean durations from the tick and sim_worker subtrees listed
          in Section 8 above.

  11. In the main-page DevTools console run `copy(window.__lastProfilerReport)`
      to capture the latest Rust profile tree, then fill the before/after table.
```

## 10. Limitations and Pinnable/Non-Pinnable Knobs

| Knob | Pinnable? | Notes |
|---|---|---|
| Biome layout | YES (via `world_seed = 42`) | Deterministic from `world_seed` via SplitMix64 in `app/crates/evosim/src/world/biome.rs`. |
| Species anchor positions | YES (via `world_seed = 42`, species_mode only) | Deterministic from `world_seed ^ SEEDING_PRNG_SALT`. Moot here (species_mode OFF). |
| Grass scatter initial cell positions | YES (via `world_seed`) | Grass boot seeding is deterministic from `world_seed`. |
| Founder brains/genomes + sim RNG stream | YES (via `?seed=bench-v2.0.5`) | The string seed drives single-pool founder brain/genome draws and the later sim RNG stream. |
| Per-tick sim trajectory | NO under threaded scatter | Lossy relaxed cross-tile grass writes can diverge run-to-run. The recipe compensates with warmup + windowed averaging. |
| Canvas physical pixel count | PARTIAL | CSS pixels are fixed at 1920 × 1080; physical pixels depend on `devicePixelRatio` (1.0 on a standard display, 2.0 on retina). The render layer uses the physical pixel canvas; the sim `write_snapshot` path (the perf target) uses the CSS viewport dimensions for its LOD computation — so DPR does not affect snapshot cost. |
| Rayon thread count | NOT DIRECTLY PINNABLE from the UI | Determined by browser's SharedArrayBuffer thread pool size. Typically 8 logical cores. The bench recipe does not pin core count; note the machine's core count in the before/after table. |
| NN topology | YES (via Settings → NN tab, default `32→48→24→5`) | The recipe uses the legacy default topology. If a future wave changes the topology, record it in the comparison table. |
