# v1.9 mission — dev-panel UX + constants cleanup

## Goals

1. Restructure the app shell: split into a left column (top-bar +
   canvas + optional profiler) and a persistent right rail with three
   tabs (Inspector / Monitor / Settings). Kill the floating dev-panel
   overlay, the floating pop-graph overlay, and the worker-stats panel
   embedded inside the dev panel.
2. Inside the new Settings tab, turn the dev-panel content into a
   **stage-then-apply** surface with Apply / Cancel / Reset controls.
3. Surface a few missing sliders, raise the resolution of others, and
   wire dynamic constraints between coupled sliders.
4. Clean up legacy "founder" constants now that there is no genome and
   no special-case starting cohort.
5. Audit and lock down the Rust ↔ TS default-value coupling so the two
   sides can't drift silently.
6. Visual polish pass (typography, palette, density) — separable; can
   slip to v1.10 if scope tightens.
7. Defer the bigger questions (NN evolution variance, larger worlds,
   chunk-cap tuning, inspector growth) — see "Out of scope" below.

## Wave A — app shell layout

**Top-level layout:**

```
┌──────────────────────────────────┬──────────────────────┐
│ ┌──────────────────────────────┐ │ ┌──┬─────┬─────────┐ │
│ │ top-bar (TPS/FPS/tick/pop)   │ │ │Ⓘ│Ⓜ   │⚙        │ │
│ ├──────────────────────────────┤ │ ├──┴─────┴─────────┤ │
│ │                              │ │ │                  │ │
│ │ canvas                       │ │ │ active tab body  │ │
│ │                              │ │ │                  │ │
│ ├──────────────────────────────┤ │ │                  │ │
│ │ profiler (optional, ✕)       │ │ │                  │ │
│ └──────────────────────────────┘ │ └──────────────────┘ │
│           left column            │     right rail       │
│           (flex: 1)              │     (fixed 420px)    │
└──────────────────────────────────┴──────────────────────┘
```

- **Left column** holds the top-bar (unchanged content), the canvas,
  and the profiler panel as a bottom slot. Top-bar moves *inside* this
  column (not the very top of the app). Canvas fills available space;
  profiler bottom panel only takes height when its toggle is on.
- **Right rail** is the existing `#right-rail` element (currently
  CSS-hidden since v1.1). Un-hide it, fix its width to **420px**,
  always visible, no collapse.
- The standalone `#devpanel-box` overlay is **removed entirely**. The
  `~` hotkey and ⚙ button instead focus the rail on the Settings tab
  (open it if not already, switch tab to Settings).
- The standalone `#stats-box` (pop graph) overlay is **removed
  entirely**; its content moves into the Monitor tab.
- The `installWorkerStatsPanel` call inside the dev panel goes away;
  worker stats move into the Monitor tab.

**Tabs:**

| Tab | Contents | Default open behavior |
|---|---|---|
| **Inspector** | Today's inspector content. Empty-state message when nothing is selected. | Opens automatically when a creature is clicked. After deselecting, stays on Inspector with the empty message. |
| **Monitor** | Pop graph (top) + worker/process stats (bottom). Both always shown when the tab is active — no internal toggles. | Manual switch only. |
| **Settings** | Current dev-panel content; Apply / Cancel / Reset as a fixed footer of this tab only. | Opens when ⚙ button is clicked or `~` hotkey is pressed (if no creature-click event drove a different tab). |

**Settings tab inner layout:**

```
┌──────────────────────────────────┐
│  …sections, scrollable inner…    │
│                                  │
├──────────────────────────────────┤
│ [ Apply ][ Cancel ][ Reset ]     │ footer of the tab — border-top
└──────────────────────────────────┘
```

- The tab body scrolls; the footer pins to the bottom of the right
  rail when Settings is the active tab.
- Sections get stronger visual separation (heavier rule, more vertical
  padding, possibly subtle background tint per section).
- The rail's own tab-bar (Inspector / Monitor / Settings) functions as
  the implicit "header" of this tab — no in-tab title bar or ✕ button
  is needed (the rail is always visible).

**Profiler bottom panel:**

- Stays toggleable. The `show profiler` checkbox lives in the
  Settings tab's `display` group (live-apply, see below).
- The panel itself gets its own ✕ button which **flips the same
  setting off** — single source of truth, the checkbox and the ✕
  agree.

**Live vs staged carve-out:**

Not every widget stages. Page-side display/render settings have no sim
round-trip — staging them would block live preview. The two existing
top groups stay **live-apply** (edit → instant effect + instant
persist + no dirty mark):

- `run` group: `auto run`.
- `display` group: `show profiler`, `show pop graph`, `show grass`,
  `grass opacity`.

Everything below (sim, energy, lifecycle, curriculum) is
**stage-then-apply**. The dirty machinery only tracks staged widgets.

**Interaction model — stage-then-apply (sim widgets only):**

- Widget edits update only the in-memory widget value. They do **not**
  push `set_slider` to the worker, and they do **not** write
  `localStorage`.
- `currentSliderState()` keeps reading widget values (boot-payload path
  is unchanged — mid-drag restart still carries the staged value).
- Per-widget "last-applied snapshot" tracks the value at the most
  recent commit (initial = boot-applied values; updated on Apply and
  Reset). A widget is **dirty** iff its current value differs from its
  snapshot.

**Footer buttons:**

- **Apply** — pushes every dirty staged slider via `set_slider`,
  writes the same values to `localStorage`, updates each snapshot to
  the just-applied value, clears the dirty set. Disabled when no
  staged widget is dirty.
- **Cancel** — restores every staged widget to its last-applied
  snapshot. Does not touch the worker or `localStorage`. Clears the
  dirty set. Disabled when no staged widget is dirty.
- **Reset** — restores every staged widget to its canonical default
  (see "Defaults ownership" below), pushes those defaults via
  `set_slider`, writes defaults to `localStorage`, updates every
  snapshot to the default, clears the dirty set. Always enabled.

**Closing the panel preserves staged edits.** Re-opening shows them
still dirty. Only Apply, Cancel, or Reset clears the dirty set.

**Construction-only knobs** (`founder_count`, `energy_max`,
`initial_grass_seed_count`, the new `full_grass_on_init` toggle) live
in the staged group too. Apply persists + pushes them via
`set_slider`, but the *current* world keeps whatever values it spawned
with. They only shape the *next* world.

**Visual dirty-state:** dirty rows get a thin colored left-border
accent so the user can see what's pending before hitting Apply. No
layout shift; subtle but scannable.

**Construction-only toast:** any time Apply or Reset commits a change
to a construction-only knob, fire a short-lived toast: *"Some changes
only take effect on new simulations."* Same toast on both paths — no
extra UI prompt or auto-restart. Cancel never fires the toast (it
pushes nothing).

**Inspector tab interaction:**

- Click a creature on canvas → switch the rail to the Inspector tab,
  show inspector body.
- Deselect (click empty world) → Inspector tab shows an empty-state
  message ("Click a creature to inspect"). The rail stays on Inspector;
  the user can switch away manually.
- Opening the rail via ⚙ or `~` does **not** switch to Inspector — it
  goes to Settings.

## Wave C — constants cleanup

Rename and normalize. Pure mechanical rename across the crate + tests
+ docs.

| Old | New | Reason |
|---|---|---|
| `FOUNDER_ENERGY` | `START_ENERGY_DEFAULT` | All creatures, not just initial cohort. |
| `FOUNDER_SIZE` | `CREATURE_SIZE` | Single shared body size since D3. Picked over `BODY_SIZE` to avoid collision with the existing `BODY_RADIUS_PER_SIZE`. |
| `FOUNDER_MAX_AGE` | `MAX_AGE_DEFAULT` | Slider-default convention. |
| `FOUNDER_SPLIT_JITTER` | `SPLIT_JITTER_DEFAULT` | Now exposed as a slider (Wave B). |
| `FOUNDER_COUNT_DEFAULT` | `STARTING_POP_DEFAULT` | Already a slider; clearer name. |
| `SPLIT_THRESHOLD` | `SPLIT_THRESHOLD_DEFAULT` | Slider-default convention. |
| `SPLIT_GIFT_MAX` | `SPLIT_GIFT_MAX_DEFAULT` | Verified cap semantics — slider value is the per-split transfer cap (`gift = clamp(parent_energy_after_cost, 0, slider)`). Preserve `_MAX` in the name; add `_DEFAULT` suffix. |
| `UPKEEP_BASE`, `UPKEEP_GUT`, `UPKEEP_NN_FIXED` | unchanged | These are *not* slider defaults — they're the fixed components multiplied by `upkeep_multiplier`. Keep the bare name. |
| `UPKEEP_MOUTH_DEFAULT` | unchanged | Already correctly named. |

- `BITE_REACH_MIN` (dead code, sibling of above).
- `COST_EAT_ATTEMPT` and the matching slider/setter/setting (Wave B).

Also update the compile-assert
`MAX_POP_FOR_SIM >= FOUNDER_COUNT_DEFAULT as usize * 32` to use the new

## Wave D — defaults ownership + drift guard

**Defaults ownership decision (recommended): Rust stays canonical.**

The Rust crate is also a native library (`cargo test --lib` runs in
CI) and every world-level test constructs a `World` whose `DevSliders`
need defaults *somewhere*. Moving the source of truth to TS forces one
of two bad outcomes:

- Tests pass `DevSliders` explicitly at every call site — noisy and
  drifts away from real boot conditions.
- Rust keeps "test-only" defaults — the drift problem reappears in a
  different shape.

So: Rust `*_DEFAULT` constants remain authoritative. `settings.ts`
mirrors them. The drift guard makes the mirror provable.

**Drift guard implementation:**

1. Add `WorldHandle::sliders_defaults_json() -> String` (small, returns
   a `{name: f32}` map built from the `*_DEFAULT` constants). Useful
   beyond v1.9 — gives the renderer and future panels a way to query
   what "default" means without hardcoding.
2. Add a Playwright e2e that:
   - clears `localStorage` and boots the page,
   - reads `sliders_defaults_json()` via the bridge,
   - asserts every value matches the `settings.ts` defaults object.

Test fails fast if either side moves.

## Wave E — visual polish (sliceable to v1.10)

The app currently reads as "dev panel bullshit" rather than a finished
product. Goals: less shouty, more cohesive, more app-like. **This
wave is the first thing cut if v1.9 scope grows.**

**Typography rules:**

- No `text-transform: uppercase` on any UI text. The existing
  `header()` helper in `devpanel.ts` (sets `textTransform: "uppercase"`)
  changes to sentence-case label rendering.
- No all-lowercase labels either (current sliders use `eat bite frac`,
  `grass propag k`, `nn σ`, etc.). All slider/section labels move to
  **sentence case** with full words where reasonable (e.g., "Eat bite
  fraction", "Grass propagation rate", "NN mutation σ").
- One font stack, one weight ramp (regular + medium for emphasis).
  Drop ad-hoc letter-spacing tweaks.

**Color palette:**

- Define a small named-token palette in CSS variables: `--bg-app`,
  `--bg-panel`, `--bg-panel-alt`, `--fg`, `--fg-muted`, `--accent`,
  `--accent-dirty` (for the dirty-row left border), `--border`,
  `--danger` (for Reset hover). Replace ad-hoc `rgba(255,255,255,0.08)`
  / `rgba(255,255,255,0.15)` literals scattered through `devpanel.ts`
  with these tokens.
- Pick a coherent dark palette — concrete proposal: warm-neutral
  charcoal background (`#1a1814` / `#221f1a`), off-white foreground
  (`#e8e3da`), single muted teal or amber accent. Open to alternatives
  — call out in the implementation pass.

**Density / spacing:**

- Consistent row padding inside panels (8px vertical, 12px horizontal).
- Heavier section separators (visible `border-top` on each section
  header instead of relying on opacity changes).
- Tab bar gets a clear active-tab indicator (underline or background
  fill, not just font weight).

**Out of scope for this wave:** redesigning the canvas itself (creature
sprites, grass shader, world chrome). Save for a dedicated v1.10+
pass — much bigger surface.

## Out of scope (deferred)

- **NN evolution variance.** The "60/30/10 mutation regimes" idea is
  good but needs more design — likely a dedicated panel with per-tier
  rate/sigma sliders, possibly tier-mix sliders, possibly per-tier
  survival pressure. Revisit after v1.9 ships and we can A/B against
  the current uniform-jitter behaviour. No code in v1.9.
- **Larger worlds.** Would cascade through SAB sizing, grass grid,
  renderer batching, and frustum cull. Out of v1.9 scope.
- **Chunk count cap (`MAX_CHUNKS`).** Worth revisiting only after we
  understand whether current cap is actually hurting throughput. Chunks
  are **index-based NN-forward work units**, not spatial tiles, and
  `pop/32` already targets ~32 creatures/chunk so smaller chunks would
  mean *more* chunks, not smaller pop slices. Plan: add a quick perf
  experiment behind a feature flag after v1.9 — bump `MAX_CHUNKS` to
  32 or 64 and measure `tick.nn` wall time at 30 k pop. Not in v1.9.

## Resolved design decisions

- **Dirty-state:** thin colored left-border accent on dirty rows.
- **Revert on construction-only knobs:** push defaults via `set_slider`
  without restarting; fire the "only takes effect on new simulations"
  toast if any construction-only knob was dirty.
- **Apply on construction-only knobs:** same — pure persist + push +
  same toast. No "restart now" button, no auto-restart. User uses the
  existing restart hotkey when they're ready.
- **`SPLIT_GIFT_MAX` semantics:** verified as a cap
  (`gift = clamp(parent_energy_after_cost, 0, slider)`). Rename to
  `SPLIT_GIFT_MAX_DEFAULT`.

## Implementation notes

- **Reuse the existing rail.** `#right-rail` and `#rail-tabs` already
  exist in `web/index.html` (hidden via CSS since v1.1). Un-hide and
  extend; don't build a new container.
- **Tab plumbing.** Today's rail has Stats and Inspector tabs; rename
  Stats → Monitor (expand contents), keep Inspector, add Settings.
  Routing lives in `web/src/rail/index.ts`.
- **Settings tab module.** `web/src/widgets/devpanel.ts` becomes the
  Settings tab installer. Its install function takes the rail's
  Settings panel element instead of `#devpanel-box`.
- **Move pop graph** out of `#stats-box` overlay into the Monitor tab
  body. Move worker-stats installer out of the dev panel and into the
  Monitor tab body below the pop graph.
- **Top-bar relocation** is just CSS — `#top-bar` lives inside the
  left column as its first child.
- **`~` and ⚙ behavior:** both now mean "switch the rail's active tab
  to Settings." If a creature is selected, the click handler may have
  already switched to Inspector — these controls don't override that
  unless explicitly invoked.
- **Toast helper.** Single shared `showToast(msg, ms)` — fired from
  Apply or Reset whenever the dirty set intersected the
  construction-only set: `{founder_count, energy_max,
  initial_grass_seed_count, full_grass_on_init}`. Cancel never fires.
- **`getSettings()` must silently ignore unknown `localStorage`
  keys** so Wave B's removal of `eatCostMultiplier` (and any future
  removals) doesn't break existing users.
- **Dirty tracking** lives in the Settings tab module — a
  per-Rust-slider-name map of `{value, snapshot}` plus a small
  dirty-changed event so the footer enable-state and per-row indicator
  update in one pass on every widget input.
- **Profiler ✕ / Settings checkbox parity.** Both write the same
  `showProfiler` setting via the live-apply path; the panel's
  visibility is a pure function of that setting.
