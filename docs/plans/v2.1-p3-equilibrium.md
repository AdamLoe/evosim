# v2.1 P3 — food-limited equilibrium + tuning knobs

Part of [`v2.1-overhaul.md`](v2.1-overhaul.md). Depends on P2 (simpler
model) and uses P1 (inspection) + live sliders to tune by hand.

## Mission

Make **food the population limit, not the cull**. Replace the
`MAX_POP_FOR_SIM` random cull (which kills good and bad foragers equally and
causes boom-bust overshoot) with density-dependent, food-limited mortality
so the population self-stabilizes below the cap and death correlates with
foraging skill — which is what lets brains actually get smarter. Expose the
equilibrium as **live tuning sliders** so the band can be dialed in by hand.

## Scope

**In:**
- Demote `MAX_POP_FOR_SIM` to a **safety ceiling** only (perf/SAB sizing).
  Keep the cull as a hard backstop, but tune so it effectively never fires.
- Add a **soft mortality / density-dependence** path: local-crowding energy
  cost and/or food-competition so overcrowded, poorly-foraging creatures
  starve first. Exact mechanism is a P3 design choice — candidates: per-tick
  crowding upkeep scaled by neighbours in a radius; grass carrying-capacity
  tuning so total food is genuinely bounded; starvation drain below an
  energy floor.
- New **live tuning sliders** (Rust-canonical defaults, mirrored to web):
  grass carrying-capacity / regrowth rate, crowding-mortality strength,
  crowding radius, starvation threshold + drain rate, and a prominent
  reproduction energy cost (surface existing `split_gift`).
- Tune defaults toward a stable, improving regime.

**Out:** no NN changes, no new biomes, no species-mode tuning.

## Approach (streams)

**Stream A — mortality/equilibrium mechanic.** Rework
`World::handle_births` cull into a backstop; add the density-dependent
mortality + starvation in `energy_bookkeeping`/`collect_deaths`. Owned:
`app/crates/evosim/src/world/mod.rs`,
`app/crates/evosim/src/world/tick.rs`,
`app/crates/evosim/src/constants.rs`,
`app/crates/evosim/src/grass/mod.rs` (if carrying-capacity/regrowth knobs
attach to scatter).

**Stream B — slider plumbing.** Add the new live sliders to `DevSliders`,
`SLIDER_NAMES`, `settings.ts`, and the Settings UI rows; coordinate the
single `SCHEMA_MAJOR` bump with P2. Owned:
`app/crates/evosim/src/world/mod.rs` (DevSliders),
`app/crates/evosim/src/wasm_api/mod.rs` (SLIDER_NAMES),
`app/web/src/settings.ts`, `app/web/src/widgets/devpanel.ts`,
`app/web/tests/e2e/defaults-drift.spec.ts`.

**Stream C — equilibrium verification harness.** A headless long-run test
or bench that runs N ticks across K seeds and asserts the population holds a
band without extinction or cap-pinning, and reports a foraging proxy trend.
Owned: `app/crates/evosim/benches/` or a `#[test]` long-run under
`app/crates/evosim/src/world/tests/`. This is also the **P3 exit-gate
instrument** — see hub Q3.

## Tuning loop (manual, the heart of this phase)

This phase is iterative, not one-shot. With P1 inspection + the new live
sliders: run the sim, watch population + the pop chart, click starving vs
thriving creatures to confirm death tracks bad foraging, adjust sliders, and
converge on defaults. Capture the chosen defaults in `constants.rs` and the
rationale in `decisions/sim.md`.

## Exit gate

**Stable band + foraging trend** (hub Q3, decided). Across K≥3 seeds running
T ticks (T large enough for many generations), population stays within a
target band — neither extinct nor pinned at the cap — AND a foraging proxy
(avg energy gathered per lifespan, or avg lifespan) trends upward over the
run. The Stream C harness encodes exactly this assertion. Plus:
`cargo test --lib` ×2, clippy ×2, `cargo bench --no-run`,
`pnpm typecheck/build/test:e2e` green.
