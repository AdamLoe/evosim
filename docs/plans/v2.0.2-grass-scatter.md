# Mission: replace the grass blur with stochastic u8 scatter

## Goal

Grass propagation is the tick bottleneck — `tick.grass_step` ≈ 491 ms
(96–99% of the tick) at the default 1920² grid, capping the sim at ~2 TPS.
Replace the deterministic separable-Gaussian blur with a **stochastic
per-cell scatter** model: cheap dice-roll spreading, u8 density, lossy
relaxed-atomic writes, no O(grid) double-buffer (only a transient per-tile
frozen-source snapshot). Target ~50–100× on per-cell
grass compute, ~20× on the overall tick (lifting TPS from ~2 to the
render/target cap of 30–60). The u8 + tile-based data layout is deliberately
**1B-cell-friendly**, but the actual scaling work — render LOD, viewport
snapshot, biome-at-LOD tint, scale-invariant sensing — is split out to
[`v2.0.3-grass-lod-pyramid.md`](v2.0.3-grass-lod-pyramid.md). **This plan is
the propagation perf fix at the default scale.** Adds a "living noise" decay
mechanic so the field grows/decays/regrows instead of settling into static
green.

This supersedes the analysis in
[`v2.0.2-grass-perf-handoff.md`](v2.0.2-grass-perf-handoff.md) (which
proposed *materializing* the blur). We are dropping the blur entirely
instead.

**Honest framing.** This is not *only* a perf fix. Materializing the separable
blur (the superseded handoff) is ~72→~15 reads/cell ≈ **5×** (~491 ms →
~100 ms → ~10 TPS) at zero cost to determinism, the energy economy, or the
test suite — but it can't reach the render cap and gives none of the
living-noise feel or the integer-native layout. The scatter rewrite buys the
full speedup **and** the grow/decay/regrow feel **and** the scaling story, at
the cost of everything in the determinism / freeze / graze sections below. We
take it deliberately for **feel + CPU headroom**, not memory: per the project
steer, CPU speed matters more than memory size, and 1B cells is an
*aspirational* goal (likely unreachable at a decent tick rate — see "Known
floor"), not a requirement.

## Why the current model is slow (root cause, confirmed in code)

`grass_cell_next` ([`src/grass.rs`](../../src/grass.rs)) recomputes the
separable blur on the fly for every cell: the 8-neighbour max calls
`blur_at` 8×, each `blur_at` calls `h_at` 3×, each `h_at` calls `sample_d`
3× → **~72 bounds-checked, strided density reads per cell** (~835 ns/cell)
where a true materialized separable blur costs ~6. The blur is also why the
grid must be f32 and double-buffered. The scatter model removes all of that.

## The scatter model (target behavior)

Per tick, for each cell that has grass:

- **Decay roll:** with probability `grass_decay_percentage`, subtract
  `grass_decay_amount` (floor 0).
- **Spread roll:** with probability `grass_spread_percentage`, pick ONE
  target cell at distance ring 1 / 2 / 3 (chosen by the ring sliders) and
  **add** `grass_spread_amount` to it, clamped to the target's biome cap.

Emergent properties (intended):

- **Big patches spread fast, lone specks spread slow** — spread rate scales
  with the number of grass cells in a region.
- **In-cell fill is just "neighbours spread onto me"** — no separate
  logistic term. A cell deep in a patch saturates fast; an isolated speck
  fills slowly.
- **Decay keeps the field alive** — visible grow/decay/regrow noise instead
  of a static green plateau. Decay also means *no grassy tile is ever truly
  static* (see active-set rule below).

New sliders (replace the old `r_in_cell` / `k_propagate` grass tuning):
`grass_spread_percentage`, `grass_spread_amount`,
`grass_spread_ring1_pct` / `ring2_pct` / `ring3_pct` (distance bias),
`grass_decay_percentage`, `grass_decay_amount`. (Slider plumbing route
owned by app-shell / shared-memory docs; confirm names + ranges during
implementation.)

### Persistence: spread vs decay is a critical threshold (don't let the field collapse)

Active decay introduces a failure mode the old logistic model never had: the
current model has **no spontaneous spawn** ([`grass.rs`](../../src/grass.rs#L1071)
test) and only ever *grows* existing grass, so grass can't die. With decay a
cell can reach 0, and the only refill is a neighbour spreading onto it — so a
region that decays out has no recovery path. Whether the field stays alive or
slowly collapses is a **branching-threshold** property of the spread/decay
balance, *per biome*:

- **Plains (cap 1.0): tune super-critical** — spread-in ≫ decay-out, so
  established patches self-sustain and refill their own gaps. Lone specks may
  still wink out; that is fine (it *is* the "living noise"). What must not
  happen is a global monotonic decline.
- **Water (cap 0.04): naturally sub-critical** — the low biome cap throttles
  the reinforcement a cell can hold, so grass creeps one cell past the shore
  and then dies for want of spread. **This is a free emergent shoreline** —
  grass can't march into water because it relies on the boost from shore grass
  to out-pace decay, and the cap denies it.

This is a **tuning target**, not a guaranteed invariant — and we ship it that
way. **No spontaneous spawn (resolved):** the system stays a pure
spread-vs-decay branching process. Tune plains super-critical and water
sub-critical; if a tail event collapses a region (or the whole field) it stays
collapsed, and that is an **accepted** outcome — a world that burns out is a
legitimate (and kind of cool) result, not a bug to patch with a respawn floor.
CPU/feel is the priority, not a self-healing field.

One interaction, accepted: the dead-world thin tick keeps grass-only
propagation running so the canvas "fills in"
([`mod.rs:761`](../../src/world/mod.rs#L761)). With decay and no spawn, a dead
world's grass can also decay toward empty, so that canvas can go dark over
time. Accepted — same "burns out" semantics.

### Where the randomness comes from (must NOT poison global determinism)

A parallel stochastic kernel needs random draws per cell, and this is the
crux of the design — the scatter rolls **cannot** draw from the shared
`SimRng` ([`src/rng.rs`](../../src/rng.rs)). That stream is sequential
state shared with creature logic; calling it inside a `rayon` `par_iter`
would (a) require a lock and (b) make the draw order thread-dependent,
which desyncs the RNG stream for *creatures*, not just grass — i.e. it
breaks global determinism, the thing the whole codebase is built on.

So grass gets its **own per-cell, position-addressable, stateless RNG**:
a hash of `(world_seed, cell_index_or_tile_id, tick)` → the cell's draws
for this tick. Properties this buys us:

- **No shared mutable RNG state** → safe to call from any worker, any
  order, never touches the creature stream.
- **Order-independent** → the draw a cell gets does not depend on which
  worker or what iteration order reached it. This is what makes the *draws*
  reproducible given `(seed, tick)` and makes the single-threaded exactness
  oracle (below) possible. The lossy *writes* are not reproducible (see the
  trade-off below) and we don't require them to be.
- What this *actually* guarantees, scoped honestly: the per-cell **draw** for
  a fixed `(seed, cell, tick)` is reproducible, so grass **never perturbs the
  creature RNG stream**. It does *not* mean the field is reproducible — by tick
  2, *which* cells are sources is itself the output of last tick's lossy
  writes, so the field (and therefore which draws matter) diverges across
  thread counts. The invariant preserved is "grass never touches `SimRng`,"
  not "grass decisions are deterministic."

## Storage + write model (Phase-1 decisions, 1B-aware)

- **u8 density** (0–255), not f32 → 4× less memory; 1 GB at 1B cells. The
  blur needed f32 precision for the [1,2,1] taps; additive scatter + clamp
  is fine in u8.
- **No full scratch buffer — but the source set IS frozen per tile.** A
  naive in-place pass over live cells has a real **intra-tick cascade** bug:
  a cell that *receives* grass this tick has density > 0, so when raster
  iteration reaches it, it qualifies as a source and re-spreads in the same
  tick — making spread speed depend on tile/raster order (and nondeterministic
  under parallel tiles). The blur avoided this by freezing the whole frame.
  We get the same freeze cheaply by **snapshotting each tile's source values
  into a transient per-worker local buffer (~1 KB)** before scattering:
  - **Decisions** (am I a source? roll spread/decay) read the **frozen local
    copy** → no cascade, order-independent.
  - **Mutations** (the target's `+spread`, the cell's `−decay`) are relaxed
    load → modify → clamp → store on the **global** `AtomicU8` field. When the
    RMWs on a cell are *serialized* (same worker, or non-overlapping in time)
    they compose — decay and an incoming spread both land. They do **not**
    compose under true concurrency: two overlapping load→…→store RMWs on the
    same cell race and one update is lost *wholesale* (a decay store can clobber
    a whole spread, not "drop one increment"). Accepted as noise.
  - This is O(tile) transient scratch, not an O(grid) double-buffer, so it
    still scales. **But the per-tile freeze is not a true frame freeze, so "no
    cascade / order-independent" holds only *within* a tile.** Across a seam, a
    cross-tile spread written into a neighbour tile *before that tile freezes*
    lands in its frozen source and re-spreads this tick. Each tile is processed
    once, so this is a **single hop**, range-bounded (~2×range past the seam) —
    not an unbounded chain — but it is **raster-order dependent**, i.e. a faint
    seam-aligned directional anisotropy. That is exactly the axis bias v2.0.1's
    disc work fought, so **the single-seed disc test must confirm it stays
    invisible.** The only way to kill it entirely is a true frame freeze (freeze
    all active sources before any scatter) = an O(active)≈O(grid) buffer at
    steady state, i.e. the very double-buffer this design drops. So we keep the
    per-tile freeze and accept the bounded seam skew.
- **Lossy relaxed-atomic writes — justified by the clamp, not instruction
  count.** Density cells are `AtomicU8`; spread/decay do relaxed load →
  add/sub → **clamp to biome cap / floor 0** → relaxed store. We do *not* use
  `fetch_add`/`fetch_sub` (which on wasm are single-instruction atomic RMWs,
  not CAS loops) because (a) they cannot express the biome-cap clamp, and
  (b) u8 `fetch_add` **wraps on overflow** → a near-cap cell could suddenly
  flip to ~0, a visible bug. So load→clamp→store is the right primitive; the
  cost is that under true concurrent collision an entire write is lost — a
  decay store can clobber a whole spread store, not merely "drop one
  increment." Invisible in a grass field, but state it honestly. This removes
  the disjoint-tile requirement, so the current `unsafe ScratchPtr` dance is
  **deleted** and cross-tile writes become legal.
  - **Trade-off accepted:** grass is no longer bit-identical across thread
    counts / re-runs. This *leaks*: creatures sense grass density, so the
    **whole sim** is no longer bit-reproducible across thread counts either —
    and that is fine. Coherence is *not* at risk: grass advances at the **end**
    of the tick (step 7), after sensing (step 2) and graze (step 5), so
    creatures always sense the **prior tick's fully-settled field** across the
    tick boundary — there is no torn read. The only thing given up is
    cross-thread / cross-run bit-identity, which the game does not need (the
    physics may be a touch fuzzy), and the global creature RNG is never touched.
    Grass-touching determinism tests are rewritten accordingly — audit every
    suite that asserts an exact density field, not just the grass module (e.g.
    `grass_biome_tests::biome_grass_propagation_is_deterministic`). Note
    `cargo test` runs single-threaded (no `--features threads`), so it cannot
    observe the cross-thread fuzz at all — the only check on threaded behaviour
    is the browser/visual pass.
- **No per-cell live list.** A `cell→position` index for a per-cell list is
  ~4 GB at 1B cells — dead on arrival. Instead we iterate the existing
  **active-tile set** and scan each active tile's contiguous 1024-cell block
  (1 KB u8, cache-friendly).
- **Biome-at-LOD tint and viewport-bounded snapshot are NOT in this
  plan.** Those are the 1B-scale *output* concerns — moved to
  [`v2.0.3-grass-lod-pyramid.md`](v2.0.3-grass-lod-pyramid.md) (which also
  covers render LOD and scale-invariant sensing from one mip pyramid). Here,
  **per-cell biome and the full-region snapshot stay exactly as today** — at
  the default 3.7M scale the whole region ships fine and the render path is
  untouched.

### u8 density touches graze + creature sensing (NOT a grass-internal-only change)

This is the honest consequence of u8: density is read by the rest of the sim,
so switching the storage type is **not** a graze-untouched refactor.

- [`bilinear_sample`](../../src/grass.rs#L838) returns f32 density into
  creature sensing → must convert u8 → f32 on read.
- [`consume`](../../src/grass.rs#L893) drains density and awards energy
  **proportional to density taken** → the energy reward per bite is now
  quantized to 256 levels over `[0, GRASS_MAX]`.
- **Blast radius: `density: Vec<f32>` → `Vec<AtomicU8>` touches every reader.**
  Grep all `.density` uses before estimating scope — at minimum `bilinear_sample`,
  the sector scan's direct read ([`proximity.rs:407`](../../src/world/proximity.rs#L407)),
  the row bitset rebuild, `classify_tile`, `quantize_dirty_tiles_into`, and the
  wholesale-set init loop ([`mod.rs:458`](../../src/world/mod.rs#L458)) all move
  to relaxed atomic loads. Mechanical (relaxed loads are plain loads on wasm, no
  perf hit), but it is **not** a "graze-only" change.

That re-quantization is a real (small) change to the **energy economy**, so
the graze/sensing read path is **in scope** (see corrected non-goals).

**Decision: u8 (resolved).** The economy can't perceive finer than u8:
`GRASS_MAX = 1.0`, the sole structural boundary is the graze threshold
`density_chunk = GRASS_MAX / grass_bites_per_block` (default 0.5 → u8 level
128), and the worst-case partial-bite reward error from u8 quantization is
`(1/255)/density_chunk` ≈ 0.78% at default — below the sim's stochastic
variance. Sensing reads density through `bilinear_sample` / sector
aggregation as *interpolated, normalized smooth f32* (no fine thresholding on
raw density), and the renderer already only ever sees u8 (the snapshot
quantize maps `density → round(d/GRASS_MAX*255)` today) — so u8 storage is
*zero* visual change. u16 would buy 65536 levels to shave a sub-1% error the
economy can't feel, at 2× memory against the 1B / 1 GB budget that is the
whole point; and scatter is additive-integer-native (clamp-RMW on `AtomicU8`),
which f32 can't express without a CAS. So **u8** — and deciding it now (not
f32-first) avoids rewriting the graze/sensing read path twice.
  - **Guard:** `grass_bites_per_block` is a live slider; if set absurdly high,
    `density_chunk` shrinks toward the u8 step and the reward quantizes
    coarsely. Cap its max (e.g. ≤ 32 → ≥ 8 u8 levels/bite) when the six
    sliders get their ranges (open decision #1). A range cap, not a
    correctness fix.

### Spread shape must stay a disc (don't regress v2.0.1's hard-won isotropy)

v2.0.1 spent real effort making spread read as a **disc, not a diamond**
([`grass.rs`](../../src/grass.rs#L113-L122)), and the scatter model must not
regress it. **Resolved (open decision #2):** targets are picked from a
**precomputed disc offset table**, not Chebyshev rings. A Chebyshev "ring" is
a *square* (its corners sit at √2× the edge distance), so picking uniformly
over a Chebyshev distance — and tuning ring weights — can only adjust *radial*
reach, never round the angular corners; the footprint would read
square/diamond and the test below would catch it.

The table is built once (rebuilt only when the spread sliders change): all
`(dx, dy)` offsets within the spread radius, each with a probability weight
encoding the **radial** falloff (the `ring1/2/3_pct` sliders become radial
bands over the table) while the **angular** distribution within each radius
stays uniform — so the cumulative footprint is round. Sample with one RNG draw
into the cumulative-weight table (binary search or an alias table).
**Requirement + test:** the spread footprint of a single seed is round, not
axis-biased.

## Active-tile set (the data-structure answer)

- **Unit of bookkeeping is the tile, not the cell.** ~1M tiles at 1B cells;
  the active subset is the spreading frontier.
- **Active = any tile with grass, OR an empty tile within range z of grass**
  (so it can receive). The *only* skippable tiles are empty-and-isolated.
  Decay means saturated tiles are NOT skippable (they spontaneously develop
  gaps and must keep being processed) — the v2.0.1 "skip saturated" tile
  class optimization is dropped.
- **List maintenance = append + compact-while-iterating.** Append tiles grass
  newly reaches; as the per-tick pass walks the active list, build the next
  list from tiles still non-empty (drop empties in the same pass). O(1) per
  entry, no shifting, no separate removal scan. The ~1M-entry tile list is
  small enough that this is cheap even on a full map.
- **Cross-tile spread is covered for free:** range z ≤ 3 ≪ tile size 32, so
  any spread crossing a tile boundary lands in an immediate fringe neighbour,
  which the existing fringe rule marks active for next tick.

### Known floor (be honest about it)

If the map is **mostly full of grass**, every cell can spread and decay, so
the work is fundamentally O(all cells) and nothing skips. Best case is then
"make each cell ~5–10 ns and parallelize": ~100–250 ms across 20 cores at
1B cells. Sparse maps win big (O(grass area)); the full-map floor is the
worst case and is accepted. (The O(events) sampling alternative — pick N
random cells to spread/decay — would beat the floor but requires the
per-cell indexable list we are explicitly avoiding.)

## What each tick does (grass phase)

1. **Refresh the active-tile list** — append newly-reached tiles; compact out
   now-empty tiles while iterating. Skip only empty-and-isolated tiles.
2. **Parallel over active tiles** (rayon). Each worker first **snapshots its
   tile's source densities into a transient local buffer** (the frozen
   source, prevents intra-tick cascade). Then for each cell that had grass in
   the snapshot, using the per-cell `(seed, tile, tick)` RNG:
   - decay roll → lossy relaxed RMW subtract on the global cell, floor 0;
   - spread roll → pick a ring-1/2/3 target (uniform over the ring, disc-safe),
     lossy relaxed RMW add on the global target, clamp to its biome cap.
3. **All writes are load→clamp→store relaxed `AtomicU8`** — cross-tile legal,
   collisions clobber (accepted noise), no scratch *buffer* (the per-tile
   local snapshot is transient O(tile), not an O(grid) double-buffer).
4. **Mark touched tiles active + dirty** for next tick (fringe rule).
   **Concurrency gap to close:** today `tile_active` / `tile_dirty` are plain
   `Vec<u64>` ([`grass.rs:169`](../../src/grass.rs#L169)) and dirty-marking
   assumes each active tile owns its own writes ([`grass.rs:406`](../../src/grass.rs#L406)).
   Once a worker can spread into a *neighbour* tile, that neighbour's
   active+dirty bits must be set by the writing worker — so the bitsets need
   atomic relaxed set-bit, or a per-worker "touched-tiles" list merged after the
   parallel pass. Otherwise cross-tile target changes silently miss the next
   snapshot and the next-tick active set.
5. **Snapshot:** quantize changed tiles into the SAB — **whole region, as
   today** (u8 storage makes this a near-memcpy). Viewport-bounded snapshot is
   [`v2.0.3`](v2.0.3-grass-lod-pyramid.md).

No blur, no f32 storage, no O(grid) double-buffer, no per-cell global list,
no `unsafe` disjoint partitioning.

## Scope

The speedup comes from **dropping the blur**, not from u8 — the kernel is the
same either way. The 1B-scale *output* work (render LOD, viewport snapshot,
biome-at-LOD tint, scale-invariant sensing) is **out of scope here**; it lives in
[`v2.0.3-grass-lod-pyramid.md`](v2.0.3-grass-lod-pyramid.md). This plan is the
propagation rewrite at the default scale:

- **Task 0 — native `criterion` bench of the scatter kernel** over a synthetic
  mid-spread field, *before* deleting the blur or rewriting tests. The headline
  targets (~50–100× cell, ~20× tick) are **unvalidated**: the browser caps at
  ~2 TPS and can't fast-forward to a vegetated steady state, and the real
  unknown is the cost of scattered, cache-unfriendly, possibly-cross-tile
  atomic RMW writes. The rest of the rewrite is gated on the bench hitting
  roughly the target per-cell cost.
- Rewrite `compute_propagation` + per-cell kernel in `src/grass.rs` to the
  scatter model; delete `h_at` / `blur_at` / `grass_cell_next` and the
  `ScratchPtr` machinery.
- Per-cell `(world_seed, tile/cell, tick)` RNG (the entropy source above).
- Per-tile frozen-source local snapshot + lossy relaxed RMW writes on the
  **u8** density field; **per-cell biome/capacity stays as today, render path
  untouched**.
- Active-tile set → "grass-or-adjacent" rule + append/compact maintenance;
  drop the saturated-skip class.
- The six sliders end-to-end (sim + control SAB lanes + UI).
- Graze/sensing read path adapted to u8 (in scope).
- Tests rewritten (see Testing).
- Measure in browser; confirm `grass_step` drop + TPS lift.

## Testing (how we keep "skipping is exact" without losing the oracle)

The frontier's safety net today is `compute_propagation_full` (the full-grid
ground truth). A stochastic + lossy kernel can't be reference-tested naively
— but the **position-addressable `(seed, tile, tick)` RNG makes it possible
again**: keep a `#[cfg(test)]` full-grid scatter that uses the *same* seeded
RNG, run it single-threaded, and assert the active-tile path produces the
identical field. That proves "empty-and-isolated is the only skippable class"
is exact. **Caveat:** the oracle must use the *same per-tile frozen-source
scheme* as the active path — if it froze the whole frame instead, the accepted
≤1-tick tile-seam skew (see "No full scratch buffer" above) would make
active ≠ full-grid even single-threaded and the test would spuriously fail, so
the oracle isolates *skip-exactness*, not seam behavior. **Do not delete the
full-grid reference — rewrite it to the scatter kernel.** Other tests: spread-rate-scales-with-patch-size, decay floors at 0,
biome-cap clamp on the target, single-seed footprint is round (disc, not
diamond), and field persistence over a long idle run (no global monotonic
collapse — see the persistence invariant). We deliberately do **not** test
same-thread-count reproducibility: lossy relaxed-RMW collisions are
timing-dependent, so that assertion would be flaky by design, and the
property is not one we need.

## Non-goals

- Bit-identical-across-thread-count determinism for grass (traded away for
  lossy relaxed atomics — but the **decision layer stays deterministic** and
  the global creature RNG is never touched).
- The O(events) per-cell-sampling variant (needs the per-cell list we reject).
- Going past ~1–2B cells in one tab (needs memory64 or a sparse/quadtree
  store; the *mechanic* is already compatible, only the backing store changes).
- Every-N-tick cadence throttling as a *perf* mechanism (a cadence slider may
  still be added later as a feel knob, but it is not load-bearing here).
- Changing NN / movement / attack phases. **(Graze/sensing IS touched — the
  u8/density read path and energy-reward quantization — so it is explicitly
  in scope, not a non-goal.)**

## Verification

- `cargo test` green (rewritten grass tests incl. the full-grid exactness
  oracle + unchanged suites).
- Threaded wasm rebuild (`--features threads`, mandatory), dev server, Perf
  overlay: `tick.grass_step` ≈ single-digit ms at default scale (target
  ~50–100× vs ~491 ms); overall tick ~20× (TPS ~2 → render/target cap).
- Visual check: grass grows from patches, decays/regrows as living noise,
  spread footprint reads round, respects biome caps (desert/water stay
  sparse), no static-green plateau.
- Persistence check: a long idle run shows no global collapse — plains stays
  vegetated, water stays a thin shoreline fringe.
