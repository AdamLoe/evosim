# v1.9.1 mission — post-ship bug fixes + small UX patches

Follow-up to v1.9. Items surfaced after running the new app shell:
canvas sizing race, inspector click broken, profiler not visibly
updating, and a small batch of focused UX additions (theme picker,
pop-graph polish, side-panel toggle, reset-clears-profile).

## Goals

1. Fix the canvas sizing race that stretches the world and breaks
   click→world hit-tests.
2. Make the Rust profiler always-on; the Settings checkbox controls
   panel visibility only. Default the panel to **visible**.
3. The profiler-area "Reset" button (currently labelled `↺` and
   wired to reset_jank only) also clears the profiler's accumulated
   data — both Rust and TS sides.
4. Settings ⚙ button toggles the right rail open/closed. Creature
   click forces the rail open and switches to Inspector.
5. Population graph: sharper rendering (DPR-aware), Y axis pinned to
   0, max value labelled at top-left, current value at top-right.
6. Themeable palette: a small `themes.ts` map keyed by id; Settings
   live-apply dropdown switches CSS vars. Ship 4 themes.

## Wave 1 — Canvas sizing fix

**Symptom:** The world is horizontally stretched. Clicks on creatures
miss because `screenToWorld` reads `viewW`/`viewH` that don't match
the canvas's actual layout box.

**Root cause:** [`web/src/main.ts`](web/src/main.ts) reads
`canvas.clientWidth || window.innerWidth` once, then on every
`window.addEventListener("resize", …)`. On first paint, `clientWidth`
can be 0 (CSS layout hasn't flushed yet), so the buffer falls back to
`window.innerWidth` — way wider than the actual grid cell. The buffer
gets sized to the window, the browser stretches it down to the cell's
true width, and the world ends up squashed.

**Fix:**

- Drop the `|| window.innerWidth` fallback. If `clientWidth` is 0,
  wait — don't paint garbage.
- Replace the `window.resize` listener with a `ResizeObserver` on
  `#canvas-wrap` (the canvas's grid-cell parent). Resize when the box
  actually changes, not just when the window does.
- Keep the dpr-multiplication on the canvas drawing buffer.

```ts
const observer = new ResizeObserver(resize);
observer.observe(document.getElementById("canvas-wrap")!);
```

After the fix, click→world should be correct and the inspector flow
should work end-to-end without further code changes. Confirm by
clicking a creature on canvas and watching the Inspector tab
populate.

## Wave 2 — Profiler always-on + reset clears it

**Decision:** The Rust profiler runs full-time. The Settings "Show
profiler" toggle controls **panel visibility only**, not Rust-side
recording.

**Changes:**

- Default `Settings.showProfiler` to `true` so the panel shows on
  first boot.
- In `web/src/widgets/perf-panel.ts → setProfilerVisible`: remove the
  `setProfilerEnabled(visible)` call and the
  `panelBridge.postMessage({ kind: "profile_enable", on: visible })`
  call. Keep `panelVisible` so the poll skip + UI hide still work.
- Send `profile_enable: true` exactly once at boot. Simplest place:
  the worker boots with the Rust profiler enabled by default. So just
  drop the toggle's `profile_enable` send — the Rust side stays on
  for the worker's lifetime.

Actually — `WorldHandle::profile_enable` is the current entry point;
the worker doesn't call it at boot. Add a single call in
`web/src/sim-worker.ts → handleBoot` right after world construction:
`world.profile_enable(true);`. Then the toggle is purely a panel show
/hide.

**Reset button:**

Currently the perf-panel's `↺` button only fires
`{ kind: "reset_jank" }`. Extend behaviour to also clear profile
data:

- Rust: add `WorldHandle::profile_clear()` that calls
  `self.inner.profile.clear()`. Implement `Profiler::clear()` in
  `src/profiler.rs` — drop all accumulated samples (re-init each
  root's ring buffer). If the existing API already has a "drain" or
  "reset" idiom, reuse it.
- TS bridge: new message kind
  `{ kind: "reset_profile" }` paired with the existing
  `reset_jank`. Worker handler calls `world.profile_clear()`.
- TS perf side: `web/src/perf.ts` needs a parallel `resetFrameTree()`
  that empties the TS-side frame tree.
- Wire `#jank-reset` click → both `reset_jank` AND `reset_profile` +
  the TS-side `resetFrameTree()`. The button stays single-purpose
  from the user's POV: "Reset" clears all the noise.
- Update the button's `title` attribute from "Reset jank counter" to
  "Reset profiler + jank".

## Wave 3 — Settings ⚙ toggles the rail open/closed

**Behaviour:**

- Add a new persisted setting `railOpen: boolean` (default `true`).
- Add a CSS class on `#app-shell` (e.g. `.rail-collapsed`) that
  switches the grid template to `1fr 0` so the rail width collapses.
  The rail itself should set `display: none` when collapsed (so its
  contents don't render and tab-bar focus traps don't fire).
- Settings ⚙ button click toggles `railOpen` (live-apply, persist).
- `~` hotkey: same toggle behaviour (was: switch to Settings).
- Creature click: force `railOpen = true` AND `rail.switchTab("inspector")`.
- Inspector empty-state when nothing's selected — leave the rail
  open. The user's call: "shows nothing or says loading or whatever"
  is fine; the existing empty-state message handles this. No
  auto-collapse.

## Wave 4 — Population graph polish

`web/src/rail/stats.ts → drawChart`:

- **DPR-aware sizing.** On install (and on each Monitor-tab show),
  read `#chart-pop`'s `clientWidth`. Set
  `canvas.width = clientWidth × devicePixelRatio`,
  `canvas.height = 120 × devicePixelRatio`. Use
  `ctx.scale(dpr, dpr)` so the existing drawing math doesn't need to
  change.
- **Y axis: 0..max.** Replace the current `ymin = … samples …` logic
  with a hard floor at 0. `ymax` stays the max sample value (or 1 if
  empty).
- **Labels:**
  - Top-left: `max: <ymax>`
  - Top-right: `now: <last sample population>`
  - Drop the awkward axis-line + duplicated label that's there today.
- **Subtle gridline** at Y=0 and Y=ymax/2 in `var(--border)` color
  — restraint over decoration.
- Listen for canvas resize via a single `ResizeObserver` set up in
  `installMonitorTab`. Re-size + redraw on layout change.

No tooltip per the user's instruction.

## Wave 5 — Themes

**Shape:**

```ts
// web/src/themes.ts
export interface Theme {
  id: string;
  name: string;                       // display label for the dropdown
  tokens: Record<string, string>;     // CSS variable → value
}

export const THEMES: Record<string, Theme> = { ... };
export const DEFAULT_THEME_ID = "charcoal";

export function applyTheme(id: string): void {
  const t = THEMES[id] ?? THEMES[DEFAULT_THEME_ID];
  const root = document.documentElement;
  for (const [k, v] of Object.entries(t.tokens)) {
    root.style.setProperty(k, v);
  }
}
```

**4 seed themes** — each defining every token currently in
`:root` in `styles.css` (--bg-app, --bg-panel, --bg-panel-alt,
--bg-canvas, --fg, --fg-muted, --fg-faint, --border, --border-strong,
--accent, --accent-dirty, --danger):

- `charcoal` — current warm-neutral charcoal + muted teal. Default.
- `slate` — cool-dark blue-grey + cyan accent.
- `light` — high-readability light mode (pale background, dark text,
  muted accent). For users who want one.
- `vivid` — high-contrast dark with a saturated magenta accent. The
  "fun" option.

The actual palettes are the implementer's call; aim for visual
distinction so the picker pays off.

**Settings integration:**

- `Settings.theme: string` (default `"charcoal"`).
- Live-apply dropdown in the Display group: "Theme: [Charcoal ▾]".
  Options are read from `Object.entries(THEMES)`.
- Apply on boot from `main.ts` (call `applyTheme(getSettings().theme)`
  before installing UI) so the very first paint uses the persisted
  theme, not a flash of the default.

**`styles.css` doesn't change** beyond the `:root` block — keep the
existing tokens; `applyTheme` overrides them at runtime via inline
style on `<html>`. The `:root` block becomes the fallback (if theme
JS errors).
