# v2.0.1 Recon — Grass propagation shape + grass/snapshot perf

Read-only recon against `src/` (HEAD on `feat/v2.0.0`). Verified against
`src/grass.rs`, `src/wasm_api.rs`, `src/constants.rs`, `src/world/mod.rs`,
`src/world/tick.rs`, and the TS seam in `web/src/{render-gl,sim-worker,sim-bridge,main}.ts`.
No builds run. Note: any wasm rebuild to test perf must pass `--features threads`
or the grass `par_chunks_mut` path silently degrades to the sequential branch.

## 0. Ground truth (sizes & cadence)

- `WORLD_SIZE_DEFAULT = 9600.0`, `GRASS_CELL_SIZE = 5.0` → `grass_dim = 1920`,
  `grass_cell_count = 3_686_400` cells (`constants.rs:13,195`; verified by the
  `from_world_size` test asserting `grass_dim == 1920`, `grass_cell_count == 3_686_400`).
  The task's "1920²" is correct (~3.69M cells, not 57_600 — the stale `tick.rs:820`
  comment "57_600 cells" predates the runtime-size migration).
- `GRASS_MAX = 1.0`; `GRASS_IN_CELL_GROWTH_R_DEFAULT = 0.01`;
  `GRASS_PROPAGATION_RATE_K_DEFAULT = 0.003`; per-biome capacity factors
  Plains 1.0 / Desert 0.30 / Water 0.04.
- **Propagation runs EVERY tick** (`world/mod.rs:838-843` live path, `:761` dead-world
  thin path). **`write_snapshot` runs EVERY tick** (`sim-worker.ts:482`), which
  re-quantizes the entire 3.69 MB grass region every tick.
- Render is decoupled: main repaints on a RAF seq-gate (`main.ts:309`), uploading
  the full grass texture per *painted frame* (`render-gl.ts:954-958`), so the
  TS-side texture upload cadence is already independent of the snapshot write
  cadence. The Rust-side per-tick re-quantize is NOT — it is unconditional.

## A. Current grass propagation kernel (problem #5 — diamond shape)

Algorithm lives in `GrassGrid::compute_propagation` (`grass.rs:217-355`). Double
buffer: read `self.density`, write `self.scratch`, then `mem::swap`. `row_body`
(`grass.rs:246-314`) processes one row, reading rows `iy-1, iy, iy+1` from `d`.

Per-cell update rule (`grass.rs:289-306`), with per-cell biome capacity `K = cap[c]`:

```
v        = d[c]
logistic = r * v * (1 - v / K)                       // in-cell logistic growth toward K
max_nbr  = max(d[N], d[S], d[E], d[W])               // 4-neighbour Von Neumann kernel
prop     = k * max_nbr                                // MAX-of-neighbours spill (not sum)
d'[c]    = clamp(v + logistic + prop, 0.0, K)
```

Neighbours are the 4 cardinal cells only (N/S/E/W). Boundary: ghost-zero when
walled, opposite edge when `wrap_world` (`grass.rs:249-287`). **This 4-neighbour
(Manhattan / L1) kernel is exactly why spread fronts grow as diamonds** — equal
per-tick reach along axes, none on the diagonal, so an isolated seed expands as
an L1 ball (a diamond). The `max`-of-neighbours (not sum) rule throttles the
cascade but does not change the diamond *shape*.

Two more pieces of the data path:
- `rebuild_row_bitset` (`grass.rs:159-177`): after each step, a full O(cells)
  scan sets a per-row "any density > 0" bit (`row_has_density`, one u64 per 64
  rows). Used by the NN grass-sector scan to skip empty rows. **Note: it is a
  whole-grid scan every tick, distinct from `row_compute.body` but also O(cells).**
- No row/tile empty-skip exists *inside* `compute_propagation` — `row_body`
  iterates every `ix` of every row unconditionally (`grass.rs:267`). The
  `row_nonempty` bitset is only consumed elsewhere (NN scan), never to skip
  propagation work. The "row-empty optimization" in docs is the NN-scan skip,
  not a propagation skip — the propagation inner loop has no early-out.

### A. Options to make spread organic/circular

| Opt | Idea | Shape quality | Cost vs today | Seam? |
|----|------|--------------|---------------|-------|
| A1 | **8-neighbour kernel** with diagonal weight (e.g. cardinal w=1, diagonal w=0.707). max- or weighted-sum-of-8. | Octagon — much rounder than diamond, still slightly faceted. | ~2× neighbour reads/cell; same memory pattern (iy-1/iy/iy+1 rows already loaded). | No |
| A2 | **Separable Gaussian-ish blur** (3-tap or 5-tap horizontal then vertical pass) blended with logistic growth, replacing the discrete kernel. | Near-perfect circular fronts; the canonical isotropic spread. | 2 separable passes but each is 1-D and cache-linear; can be *cheaper* than a 2-D 8-tap and is the natural fit for SIMD + periodic running (see B). | No (Rust-internal) |
| A3 | **Distance-weighted radial kernel** (precomputed small stencil, e.g. 5×5 with 1/d weights). | Circular. | Most expensive per tick (up to 25 reads/cell) unless run every N ticks. | No |
| A4 | **Jitter / blue-noise threshold** on the propagation gate (per-cell hashed offset to the spill amount). | Breaks the diamond facets into an organic, slightly noisy edge; cheapest "looks-organic" hack. | Negligible add (one hash per cell). Can layer on A1. | No |

All A-options are **Rust-internal**: they change only the values written into the
existing f32 density grid. The snapshot/grass-region layout (u8 per cell) and the
TS reader are untouched. **A2 (separable blur) is the standout** because it is
both the roundest *and* the cheapest to combine with the B perf wins below.

## B. Make `row_compute.body` and `write_output_sab` 10–20× cheaper (problem #6)

### B-1. `grass_step.row_compute.body` — why it's expensive

It is O(cells) = 3.69M f32 cells **every tick**, each doing 4–5 neighbour loads,
a divide-or-reciprocal, two mults, a clamp, plus per-row branchy boundary index
computation (`grass.rs:249-305`). At default sliders `r = 0.01`, `k = 0.003` the
field changes very slowly per tick, so most of this work is recomputing
near-identical values. The dominant waste is **doing a full-grid float pass every
single tick when the visible field barely moves**.

Ranked wins (highest leverage first):

| # | Idea | Expected speedup | Risk | Seam / cadence? |
|---|------|-----------------|------|-----------------|
| B1 | **Propagate every N ticks** (e.g. N=8–16), scaling `r`/`k` by N to keep the same net growth. Grass is a slow background field; nobody perceives per-tick granularity. | **~Nx (8–16×) directly** — this alone hits the 10–20× ask. | Low-med: graze still consumes per tick, so density can dip between propagation ticks; pick N so regrowth still feels alive. Determinism/test fixtures that step grass per tick need updating. | **Rust-internal** if the snapshot keeps writing the (unchanged-between-steps) grass every tick. Becomes a cadence change only if combined with B5. |
| B2 | **Coarser propagation grid** — propagate on a downsampled lattice (e.g. ½ or ¼ resolution: 960² or 480²) and upsample for sampling/snapshot. | 4–16× fewer cells. | Med-high: bilinear graze sampling + `consume` + biome capacity all index the full grid today; needs a resolution-decoupling layer. Larger refactor. | Rust-internal *if* the snapshot still emits full-res (upsampled) u8; **seam change** if snapshot ships the coarse grid (TS texture dim changes). |
| B3 | **Skip-empty-and-saturated rows/tiles** — reuse/extend `row_has_density` to early-out fully-empty rows, and add a "fully saturated AND all neighbours saturated" tile skip. Only the active frontier does work. | 2–10× depending on field fill (huge early, shrinks as world fills). | Low: bitset already exists; add a "row interior fully at capacity" check. Frontier rows still pay. | Rust-internal. |
| B4 | **wasm-SIMD (`v128`) the inner loop** + fixed-point/integer density (u8 or u16 instead of f32). Process 4 (f32x4) or 16 (u8x16) cells per instruction; the logistic+spill is branch-light if boundary handling is hoisted out of the hot interior. | 4–8× (SIMD width) × extra from integer/cache; combine with separable A2 for clean 1-D SIMD. | Med: needs `--features simd`-style build flag; boundary rows handled separately; integer requantization of growth math. | Rust-internal (density stays internal); if density becomes u8 the snapshot quantize step becomes a memcpy (bonus, see B6). |
| B5 | **Separable passes (A2) running every N ticks** — one redesign that is rounder (A) *and* cheaper (B1+SIMD-friendly). | Multiplicative with B1. | Med. | Rust-internal. |

**Recommended stack for `row_compute.body`: B1 (every-N) × B3 (frontier skip),
optionally A2/B4 for the kernel itself.** B1 alone reaches the 10–20× target with
the least risk and zero seam impact. B3 compounds it cheaply. Also fold
`rebuild_row_bitset` (a second full-grid scan every tick) into the same N-tick
cadence — it only needs refreshing when density actually changed.

### B-2. `write_output_sab` — what it writes & why it's expensive

`WorldHandle::write_snapshot` (`wasm_api.rs:551-641`) writes, every tick, into one
of two slots of a wasm-memory `Vec<u8>`:

1. **Creature SoA** (`creatures_off`, `fill_creature_bytes` `wasm_api.rs:1203`):
   32 B/creature × pop, 8 f32 lanes (x, y, radius, color_u32, id_lo, id_hi,
   packed_u32, pad). Per creature: HSV→RGB color compute, species lookup, bit-pack.
2. **Stats header** — 20 B LE (`wasm_api.rs:590-595`).
3. **Grass region** (`quantize_grass_into` `wasm_api.rs:1319`): a scalar loop over
   ALL 3.69M cells, `f32 → u8` quantize, **every tick**. This is the dominant
   cost of the span — a 3.69 MB write/scan per tick regardless of whether grass
   changed or whether anyone repaints.

The profiler already splits `write_output_sab.snapshot.creatures` vs
`.grass_copy` (`wasm_api.rs:628-639`), so the grass share is measurable today.

Ranked wins:

| # | Idea | Expected speedup | Risk | Seam / cadence? |
|---|------|-----------------|------|-----------------|
| C1 | **Quantize grass every N ticks**, not every tick (match B1's propagation cadence — between propagations the grass field is byte-identical, so re-quantizing is pure waste). | **~Nx on the grass_copy span**; combined with B1 the two slow spans share one cadence. | Low. The double-buffer slot must still contain valid grass each tick — keep writing the *cached* quantized bytes, or only re-quantize into the slot when grass changed and let the reader read the freshest slot. Simplest: a dirty flag set by propagation/graze. | **Cadence change at the seam boundary** — but the TS reader already tolerates this (it seq-gates and re-uploads the whole texture per painted frame; stale-but-valid bytes are fine). No *layout* change. Document the new "grass updates every N ticks" contract. |
| C2 | **Dirty-tile / changed-cell grass encoding** — track which grass tiles changed (graze + frontier) and only re-quantize those; pair with `texSubImage2D` partial uploads on the TS side. | 5–50× on grass_copy when the field is mostly static; degrades to full cost when everything changes. | High: needs a dirty-tile structure Rust-side AND a matching partial-upload path in `render-gl.ts`. | **Seam change** (Rust emits a dirty-rect list / the TS upload must read it). Cross-wave: render-gl.ts must follow. |
| C3 | **Downsampled grass for the snapshot** — quantize a ½/¼-res grass texture into the slot (the renderer already samples a smooth R8 texture with bilinear-ish shader). | 4–16× on grass_copy + 4–16× smaller upload. | Med. Visual: coarser grass texels, but the grass FS already smooths. | **Seam change**: snapshot grass region byte length + `grass_dim` texture dim change; `sim-bridge.ts makeSlotLayout` and `render-gl.ts` texture dims must follow. Natural pairing with B2. |
| C4 | **Skip quantize when no repaint is pending** — only write grass into the slot the renderer is about to read. Needs the worker to know the render is idle (e.g. read a "render alive / wants frame" flag from a control SAB word). | Up to full grass_copy savings when render is throttled/backgrounded. | Med: adds a control-SAB signal main→worker. | **Seam change** (new control word), but no snapshot *layout* change. |
| C5 | **Make density u8 internally (B4)** so `quantize_grass_into` becomes a `copy_from_slice` (memcpy) instead of a per-cell scalar quantize. | 2–4× on grass_copy (memcpy vs scalar loop) + the SIMD wins on propagation. | Med (integer density math). | Rust-internal for the snapshot (still u8 out); the density storage change is internal. |
| C6 | **Creature SoA: write fewer/cheaper fields** — color recompute per tick is wasted when genome/species color is static; cache the packed color on the creature and memcpy. Minor next to grass but real at 32k pop. | 1.2–2× on creatures span. | Low. | Rust-internal (same 32 B layout). |

**Recommended for `write_output_sab`: C1 (every-N quantize, matched to B1) as the
zero-layout, low-risk 10×+ win; then C5 (u8 density → memcpy) if B4 is adopted;
C2/C3 only if more is needed (both cross the seam).**

## Coupling: one redesign for both A and B

The cheapest joint solution: **A2 separable organic blur + B1/C1 every-N cadence.**

- A2 gives circular spread (fixes the diamond) and is the natural form for SIMD
  (1-D linear passes) and for running periodically.
- Running it every N ticks (B1) cuts `row_compute.body` ~Nx.
- Quantizing the grass into the snapshot on the same N-tick cadence (C1) cuts
  `write_output_sab.grass_copy` ~Nx.
- All three are **Rust-internal with NO snapshot-layout change** — the only
  externally-visible effect is a cadence change (grass advances every N ticks),
  which the existing seq-gated, full-texture TS reader already tolerates with no
  code change. This hits the 10–20× target on both spans in one wave without
  touching the wire format.

If a still-bigger cut is wanted later, layer C3/B2 (coarse grid → smaller snapshot
texture) — but that one DOES cross the seam (`makeSlotLayout`, `render-gl.ts`
texture dims) and must ship render-gl.ts in the same wave.

## Seam-impact summary

- **Rust-internal, no seam change:** all of A1–A4, B1, B3, B4, B5, C1 (cadence
  only — reader already tolerant), C5, C6.
- **Crosses the Rust↔TS SAB seam (render-gl.ts/sim-bridge.ts must follow same wave):**
  B2 + C3 (coarse/downsampled snapshot grass → texture dim + slot-layout change),
  C2 (dirty-rect list + partial `texSubImage2D`), C4 (new control-SAB word).
