## 1. Full module sketch

```rust
//! GrassGrid — 240×240 = 57_600 flat-Vec<f32> density field over the
//! 600u toroidal world. Each cell is 2.5u square. Independent of
//! SpatialGrid (5u, body queries). See v1.2 grass-mechanic-brief §Grass
//! storage / Grass dynamics per tick / Initial grass seed / Bilinear
//! sampling.

use crate::constants::*;
use crate::rng::SimRng;
use serde::{Deserialize, Serialize};

#[derive(Clone, Debug)]
pub struct GrassGrid {
    /// Row-major density, length GRASS_CELL_COUNT (= 57_600).
    /// Cell (ix, iy) lives at iy * GRASS_GRID_DIM + ix. Values clamped
    /// to [0.0, GRASS_MAX] post-step. Hash-stable: snapshot_hash walks
    /// this in linear order.
    pub density: Vec<f32>,
    /// Double-buffer scratch. Same length as `density`. Recomputed every
    /// `step` call; never read between ticks. NOT saved (rebuilt on load
    /// as a zero-fill).
    pub scratch: Vec<f32>,
}

impl GrassGrid {
    /// World-init constructor. Seeds `initial_seed_count` random cells
    /// with `GRASS_MAX`; all others zero. Draws from `rng` via the same
    /// world RNG used everywhere else (deterministic given fixed seed).
    pub fn new(rng: &mut SimRng, initial_seed_count: u32) -> Self;

    /// One propagation tick. Reads `self.density`, writes `self.scratch`,
    /// swaps. Formula per cell c (toroidal cardinal neighbors n,s,e,w):
    ///   d' = clamp(
    ///     d[c]
    ///       + r_in_cell * d[c] * (1 - d[c] / GRASS_MAX)
    ///       + k_propagate * (d[n] + d[s] + d[e] + d[w]),
    ///     0.0,
    ///     GRASS_MAX,
    ///   )
    /// Empty cells with all-zero neighbors remain zero (logistic term
    /// vanishes at d=0; propagation term sums to zero).
    pub fn step(&mut self, r_in_cell: f32, k_propagate: f32);

    /// Toroidal-aware bilinear sample at continuous world position.
    /// Used by PR-2 P2d (build_nn_input grass-patch inputs). Reads four
    /// surrounding cell-center values, weights by inverse area.
    /// World wraps at `WORLD_SIZE = 600.0`.
    pub fn bilinear_sample(&self, x: f32, y: f32) -> f32;

    /// Clamp-take with cap. `cell_idx` is the flat density index;
    /// `max_take` is the requested withdrawal (typically
    /// `GRAZE_MAX_PER_TICK * graze_efficiency`). Returns the actual
    /// delta removed (≤ `max_take`, ≤ `density[cell_idx]`).
    /// Single-threaded: PR-1 P1e calls this in the sequential graze
    /// loop, NOT inside the threaded NN chunk path.
    #[inline]
    pub fn consume(&mut self, cell_idx: usize, max_take: f32) -> f32;

    /// Iterate every cell whose center is within toroidal distance
    /// `r` of `(cx, cy)`. Invokes `f(cell_idx)` once per hit. Used by
    /// P1e to find graze-overlap cells. Bounded by `r ≤ WORLD_SIZE/2`.
    pub fn cells_overlapping_circle(
        &self,
        cx: f32,
        cy: f32,
        r: f32,
        f: impl FnMut(usize),
    );

    /// Cheap getter for the snapshot/render path.
    #[inline]
    pub fn density_at_cell(&self, cell_idx: usize) -> f32 {
        self.density[cell_idx]
    }
}

/// Convert continuous world coords to a flat cell index. Toroidal wrap.
#[inline]
pub fn cell_index_for(x: f32, y: f32) -> usize {
    // Use rem_euclid on the integer cell coordinate to wrap correctly
    // for negative or > WORLD_SIZE inputs. f32 % may produce negative
    // values for negative x; rem_euclid on i32 is bit-stable across
    // sequential and threaded paths.
    let ix = ((x / GRASS_CELL_SIZE).floor() as i32).rem_euclid(GRASS_GRID_DIM as i32) as usize;
    let iy = ((y / GRASS_CELL_SIZE).floor() as i32).rem_euclid(GRASS_GRID_DIM as i32) as usize;
    iy * GRASS_GRID_DIM + ix
}
```

API-shape rationale (mirrors `src/grid.rs:33-50` for `SpatialGrid::cell_of` style — both expose a public `cell_*_for(x, y)` flat-index helper, both are stateless math).

## 2. `step` implementation pseudocode + SIMD/scalar decision

**Decision: scalar for v1.2 with a `// TODO(v1.3): SIMD via wide::f32x8` marker.**

Justification:
- Cost ceiling (see §10): scalar 57_600 cells × ~6 fused-mul-add per cell ≈ 350k FMA/tick. At ~1 GFLOP on a single WASM core that's ~0.35 ms/tick — comfortably under the budget freed by deleting the sun two-pass (which the brief calls out at `src/world/tick.rs:176-218`, ~14k creature pairs × refill/payout pass).
- SIMD wouldn't reduce wall-clock noticeably until cell count grew ≥ 4×.
- The propagation kernel's toroidal neighbor lookup is awkward to vectorize directly because the leftmost/rightmost column-of-8 spans a wrap seam. A row-by-row scalar pass with three precomputed row offsets is simpler and bit-stable across both `cargo build` and `cargo build --features threads`.
- The brief at `/home/adamg/evosim/docs/plans/v1.2-grass-mechanic-brief.md:45` says "SIMD-friendly via the existing `wide` crate" — aspirational, not mandatory. We honor the friendliness (struct-of-arrays Vec, multiple-of-8 dim) without burning the SIMD complexity budget yet.

**Pseudocode:**

```rust
pub fn step(&mut self, r_in_cell: f32, k_propagate: f32) {
    debug_assert_eq!(self.density.len(), GRASS_CELL_COUNT);
    debug_assert_eq!(self.scratch.len(), GRASS_CELL_COUNT);

    let dim = GRASS_GRID_DIM;
    let max = GRASS_MAX;
    let inv_max = 1.0 / max;
    let d = &self.density;
    let s = &mut self.scratch;

    for iy in 0..dim {
        // Precompute row-base offsets with toroidal wrap on Y.
        let row_self = iy * dim;
        let row_n = if iy == 0 { (dim - 1) * dim } else { (iy - 1) * dim };
        let row_s = if iy + 1 == dim { 0 } else { (iy + 1) * dim };

        for ix in 0..dim {
            let c   = row_self + ix;
            let ce  = row_self + (if ix + 1 == dim { 0 } else { ix + 1 });
            let cw  = row_self + (if ix == 0 { dim - 1 } else { ix - 1 });
            let cn  = row_n + ix;
            let cs  = row_s + ix;

            let v = d[c];
            // Logistic in-cell growth term (only nonzero when v > 0):
            let logistic = r_in_cell * v * (1.0 - v * inv_max);
            // Cross-kernel propagation:
            let prop = k_propagate * (d[cn] + d[cs] + d[ce] + d[cw]);
            let next = (v + logistic + prop).clamp(0.0, max);
            s[c] = next;
        }
    }

    std::mem::swap(&mut self.density, &mut self.scratch);
}
```

**Toroidal-neighbor-lookup correctness:**
- `iy == 0` wraps north to row `dim - 1`. `iy == dim - 1` wraps south to row 0.
- `ix == 0` wraps west to column `dim - 1`. `ix == dim - 1` wraps east to column 0.
- All wrap math is integer; no float modulo. Bit-stable.

**Empty-cell preservation:** If `d[c] == 0` and all four neighbors are zero, `logistic = 0` and `prop = 0`, so `next = 0`. No spontaneous spawn — matches brief.

**Determinism:** Single-pass sequential scan; no parallelism inside `step`. PR-1 calls `step` from the sequential tick body between current step 5 (NN forward) and step 7 (the deleted sun refill). The threaded NN path at `src/world/nn.rs:82-145` does NOT touch GrassGrid.

**SIMD-friendly future shape (sketch, not for v1.2):** chunk inner loop into `f32x8`; precompute `row_n_ptr`, `row_s_ptr`, `row_self_ptr`; handle the wrap-around 8-block per row scalarly (only 2 of 30 chunks per row need scalar handling — 30 chunks × 240 rows = 7_200 chunks, ~480 scalar tail). Defer.

## 3. `bilinear_sample` pseudocode (toroidal-aware)

Used by P2d at `src/world/nn.rs` for 25 grass-patch inputs per creature per tick (see `docs/plans/v1.2-grass-mechanic-brief.md:69-75`).

```rust
pub fn bilinear_sample(&self, x: f32, y: f32) -> f32 {
    // Step 1: wrap continuous coords into [0, WORLD_SIZE).
    let w = WORLD_SIZE; // 600.0
    let xw = ((x % w) + w) % w;
    let yw = ((y % w) + w) % w;

    // Step 2: convert to fractional cell coordinates. Cell centers
    // are at (i + 0.5) * GRASS_CELL_SIZE for cell index i.
    // We sample relative to cell-center grid, so subtract 0.5 cell.
    let fx = xw / GRASS_CELL_SIZE - 0.5;
    let fy = yw / GRASS_CELL_SIZE - 0.5;

    // Step 3: get integer floor and fractional offset, wrapping.
    let dim = GRASS_GRID_DIM as i32;
    let ix0 = (fx.floor() as i32).rem_euclid(dim) as usize;
    let iy0 = (fy.floor() as i32).rem_euclid(dim) as usize;
    let ix1 = if ix0 + 1 == GRASS_GRID_DIM { 0 } else { ix0 + 1 };
    let iy1 = if iy0 + 1 == GRASS_GRID_DIM { 0 } else { iy0 + 1 };

    let tx = fx - fx.floor(); // in [0, 1)
    let ty = fy - fy.floor();

    // Step 4: read four neighbors.
    let d = &self.density;
    let dim_us = GRASS_GRID_DIM;
    let d00 = d[iy0 * dim_us + ix0];
    let d10 = d[iy0 * dim_us + ix1];
    let d01 = d[iy1 * dim_us + ix0];
    let d11 = d[iy1 * dim_us + ix1];

    // Step 5: bilinear interpolation.
    let a = d00 * (1.0 - tx) + d10 * tx;       // bottom row
    let b = d01 * (1.0 - tx) + d11 * tx;       // top row
    a * (1.0 - ty) + b * ty
}
```

**Why subtract 0.5:** cell `i`'s center is at `(i + 0.5) * GRASS_CELL_SIZE` in world coords. To express "fractional cell index where this sample lies", shift so cell center = integer.

**Worked example for the unit test:** at `(x, y) = (1.25, 1.25)` (exactly cell (0,0) center): `fx = 0.5 - 0.5 = 0`, `tx = 0`, so result = `d[0]`. At `(3.75, 1.25)` (exactly cell (1,0) center): `fx = 1.5 - 0.5 = 1`, `tx = 0`, result = `d[1]`. At the midpoint `(2.5, 1.25)`: `fx = 1.0 - 0.5 = 0.5`, `tx = 0.5`, result = `0.5*d[0] + 0.5*d[1]`. (Used as a unit-test golden in §9.)

**Toroidal seam test:** sampling at `(0.0, 0.0)` and `(600.0, 600.0)` should yield identical density (modular wrap collapses both to cell center (-0.5, -0.5) fractional → wraps to (239.5, 239.5) → reads cells (239,239),(0,239),(239,0),(0,0)).

## 4. `consume` semantics

```rust
#[inline]
pub fn consume(&mut self, cell_idx: usize, max_take: f32) -> f32 {
    let cur = self.density[cell_idx];
    let take = cur.min(max_take).max(0.0); // defends against negative max_take
    self.density[cell_idx] = cur - take;    // never negative because take ≤ cur
    take
}
```

**Single-threaded confirmation:** PR-1 P1e calls `consume` from the sequential graze body that replaces `photosynth_two_pass` at `src/world/tick.rs:176-218`. The graze body iterates `0..n_creatures` in SoA order; for each creature in Action::Graze, it walks the overlapping cells and calls `consume` on each. This is sequential — no `par_chunks_mut`, no rayon. The threaded NN path at `src/world/nn.rs:82-145` runs BEFORE the graze step (current tick step 5 = NN, step 7 = sun refill / new graze step). No atomics needed.

**Determinism:** order is fixed by SoA index × cells_overlapping_circle's deterministic iteration order (§5). Same seed → same energy gains → same hash.

**Edge cases:**
- `max_take < 0`: clamped to 0 via `.max(0.0)`.
- `max_take.is_nan()`: `cur.min(NaN) = NaN`; need explicit `if !max_take.is_finite() { return 0.0; }` guard (or rely on caller — see §11 risks). **Recommend in-body guard** for symmetry with `decode_action`'s NaN handling at `src/world/nn.rs:303-329` (per DECISIONS S5 line 207).
- `cur == 0`: returns 0, no write.

## 5. `cells_overlapping_circle` design

**Choice: callback (`impl FnMut(usize)`), not iterator, not Vec.**

Justification:
- Mirrors `SpatialGrid::for_each_in_radius` at `src/grid.rs:83-100` — same call-site shape, no impl-trait return, no Vec allocation in the hot loop.
- P1e's graze body needs `&mut self` on `GrassGrid` (to call `consume`), and an iterator-returning method that borrows `&self` would conflict. Callback resolves this cleanly: the closure captures the mutable borrow path explicitly.
- Per-creature overlap counts are tiny: a creature with radius ≤ 11u (genome.size_max=10 × BODY_RADIUS_PER_SIZE=1 + 1u min radius) covers at most `(11/2.5)^2 * pi ≈ 60 cells`. No need to materialize a Vec.

**Algorithm (toroidal bounding-box scan + per-cell torus-distance check):**

```rust
pub fn cells_overlapping_circle(
    &self,
    cx: f32,
    cy: f32,
    r: f32,
    mut f: impl FnMut(usize),
) {
    debug_assert!(r.is_finite() && r >= 0.0);
    debug_assert!(r <= WORLD_SIZE * 0.5, "radius must be ≤ half-world");

    // Bounding box in cell coords (signed; we wrap per-cell below).
    let r_cells = (r / GRASS_CELL_SIZE).ceil() as i32 + 1; // +1 for floor/center slop
    let cx_cell = (cx / GRASS_CELL_SIZE).floor() as i32;
    let cy_cell = (cy / GRASS_CELL_SIZE).floor() as i32;
    let dim = GRASS_GRID_DIM as i32;
    let half_w = WORLD_SIZE * 0.5;
    let r2 = r * r;

    for jy in (cy_cell - r_cells)..=(cy_cell + r_cells) {
        let iy = jy.rem_euclid(dim) as usize;
        for jx in (cx_cell - r_cells)..=(cx_cell + r_cells) {
            let ix = jx.rem_euclid(dim) as usize;
            // Cell center in world coords (NOT the wrapped iy/ix —
            // we want the candidate cell relative to creature, so use
            // jy/jx pre-wrap to get the right distance vector).
            let world_x = (jx as f32 + 0.5) * GRASS_CELL_SIZE;
            let world_y = (jy as f32 + 0.5) * GRASS_CELL_SIZE;

            // Shortest-vector torus distance:
            let mut dx = world_x - cx;
            let mut dy = world_y - cy;
            if dx >  half_w { dx -= WORLD_SIZE; }
            if dx < -half_w { dx += WORLD_SIZE; }
            if dy >  half_w { dy -= WORLD_SIZE; }
            if dy < -half_w { dy += WORLD_SIZE; }

            if dx * dx + dy * dy <= r2 {
                f(iy * GRASS_GRID_DIM as usize + ix);
            }
        }
    }
}
```

**Why pre-wrap jx/jy are used for distance:** the bounding-box scan already covers wrap because we iterate `jx ∈ [cx_cell - r_cells, cx_cell + r_cells]` which can be negative or > dim. Using pre-wrap jx for `world_x` keeps the geometric distance correct relative to `cx` (no spurious half-world jumps). The `rem_euclid(dim)` only happens when we compute the flat index.

**Determinism:** integer cell iteration; deterministic order (row-major, left-to-right). Same seed → same overlap set → same `consume` calls → same energy gain.

**Edge cases:**
- Creature at world seam (e.g., `cx = 0.5`, radius 2): bounding box covers `jx ∈ [-1, 1]` → cells ix={dim-1, 0, 1}; toroidal distance correctly identifies them as adjacent.
- Radius exactly equal to half-world: `r2` test includes everything; `debug_assert!(r ≤ WORLD_SIZE * 0.5)` documents the upper bound. P1e callers pass body radius which is ≤ 10u, safe.

7. **`bilinear_sample_wraps_at_seam`** — `bilinear_sample(0.0, 0.0)` should equal `bilinear_sample(WORLD_SIZE, WORLD_SIZE)` exactly (modulo wrap → identical 4-cell read).
8. **`consume_clamps_to_density`** — set `density[10] = 0.3`; `consume(10, 0.5)` returns `0.3`, leaves `density[10] = 0.0`.
9. **`consume_returns_zero_on_empty`** — `consume(0, 1.0)` on a freshly-zero grid returns 0.0; density unchanged.
10. **`consume_clamps_negative_max_take`** — `consume(0, -1.0)` returns 0.0 (no removal). Defends against P1e accidentally passing negative inputs (e.g., negative graze_efficiency × cap).
11. **`cells_overlapping_circle_finds_central_cell`** — circle at `(WORLD_SIZE/2, WORLD_SIZE/2)` with radius 0.5; callback fires exactly once with the index of the cell containing that point.
12. **`cells_overlapping_circle_wraps`** — circle at `(0.5, 0.5)` with radius 2.0; callback fires for cells including ix=0, ix=dim-1 (toroidal wrap on west seam).
13. **`cells_overlapping_circle_count_matches_brute_force`** — circle at random `(cx, cy)` with random radius ≤ 5.0; collect cells via the callback; compare against a brute-force `(0..dim).iter().flat_map(...)` scan with the same toroidal distance test. Equality (both as `BTreeSet<usize>`).
14. **`initial_seed_is_deterministic`** — two `GrassGrid::new(&mut SimRng::from_u64(42), 16)` calls should produce byte-identical density vectors. Also: `initial_seed_count = N` should produce exactly N cells with `density == GRASS_MAX` (no double-seeding because `new` picks via `rng.index(GRASS_CELL_COUNT)` with rejection on already-seeded — or, simpler, uses `rng.unit()` modulo cell count with set-tracking; pick the deterministic implementation in P1c and test it). Suggested algorithm:
    ```rust
    for _ in 0..initial_seed_count {
        let idx = rng.index(GRASS_CELL_COUNT);
        density[idx] = GRASS_MAX; // idempotent: re-seeding same cell is harmless
    }
    ```
    This is O(N) and may pick the same cell twice when seed_count is large; documented as "up to N cells, in expectation slightly fewer for large N". Acceptable per brief.
15. **`density_length_invariant`** — `assert_eq!(g.density.len(), GRASS_CELL_COUNT)` and `scratch.len() == GRASS_CELL_COUNT` after `new`.

## 10. Performance back-of-envelope

**Per-tick cost components:**
- `step`: 57_600 cells × (1 load + 4 neighbor loads + 1 mul + 1 fma + 1 mul + 3 add + 1 clamp + 1 store) ≈ 12 ops/cell ≈ **~700k ops/tick**. Plus 2× 57_600 × 4-byte memory traffic (read density, write scratch) = 460 KB streaming, fits L2/L3 trivially.
- `bilinear_sample` (PR-2 P2d): 4 loads + 6 mul + 3 add per sample × 25 samples/creature × N creatures. At N=500: 500 × 25 × ~15 = 187k ops/tick. Negligible vs vision raycast (currently dominant).
- `consume` (PR-1 P1e): 1 load + 1 min + 1 sub + 1 store per (creature, overlapping-cell) pair. At N=500 creatures, ~5 overlapping cells avg (creature radius ~3u, area = π×9u² = 28u² / cell-area 6.25u² ≈ 4.5 cells): 500 × 5 × ~5 = 12.5k ops/tick. Trivial.
- `cells_overlapping_circle` (PR-1 P1e): per-creature bounding-box scan. Box side = `ceil(r/2.5)*2+1`, for r=3u that's 5 cells × 5 cells = 25 cells visited; each does 2 mul + 4 cmp + 4 add + 1 add + 1 sub + 1 cmp = ~13 ops + 1 callback. At N=500: 500 × 25 × 14 = 175k ops/tick.

**Combined v1.2 grass-related cost: ~1 M ops/tick (≈ 1 ms on a 1 GFLOP/s single WASM core).**

**Compare to costs being deleted:**
- `photosynth_two_pass` at `src/world/tick.rs:176-218`: two passes over N creatures × per-creature sun-cell lookup + demand/payout accumulation + division. At N=500, ~5k ops/tick + ~600 ops for the sun refill loop.
- `sun.refill()` at `src/sun.rs:53-59`: 400 cells × 2 ops = 800 ops/tick.

**Net delta: grass adds ~1M ops/tick, sun deletion saves ~6k ops/tick. Net cost ≈ +1M ops/tick ≈ +1 ms/tick.** Acceptance budget at `PERF_BUDGET_MS = 8000` for 10k ticks (`/home/adamg/evosim/DECISIONS.md:105`) → 0.8 ms/tick on-CI average; 1 ms additional grass overhead consumes most of the slack. **Watch this number during PR-3 P3e tuning.** If we exceed the budget on ubuntu-latest, the SIMD optimization deferred above gets pulled forward into the same PR.

WSL2 dev-machine note: rayon overhead already dominates the threaded path on WSL2 (DECISIONS line 170-175). Grass step is sequential and won't affect that gap.

## 11. Risks

1. **`GRAZE_MAX_PER_TICK = 0.25` is unverified against the §16 acceptance seed.** Master plan §F #5 (`/home/adamg/evosim/docs/plans/v1.2-master.md:315`) explicitly defers the value lock to this plan, and §B P3e (line 159) flags balance tuning as orchestrator-owned. Cross-reviewer must check that a founder with `eye_count = 0`, `nose_count = 0`, and `graze_efficiency = founder_default` survives at this cap given `GRASS_INITIAL_SEED_COUNT_DEFAULT = 8`. If 0.25 is too low (founder starves before stumbling onto another seeded cell), bump toward 0.5 in P3e tuning. If too high (one creature drains all grass in <1 tick of grazing), lower toward 0.1.
2. **Scalar `step` cost is 1 ms/tick — close to the perf budget.** §10 shows we have headroom but it's not huge. If P3e tuning shows the grass step dominates, pull SIMD forward into P3e or accept the budget bump.
3. **`density` Vec serializes as 230 KB of JSON.** Each f32 in JSON is ~10 ascii bytes worst case, so the on-disk save grows by ~2.3 MB (it was ~50 KB before). P1f/P3c migration UX needs to bear this in mind — the IDB write cost goes up. Mitigation: don't pretty-print; future v1.3 could base64-encode the density vector. Not a P1c blocker.
4. **The brief specifies "SIMD-friendly" — declining SIMD here might be read as a partial deviation.** Document in DECISIONS that v1.2 lands scalar with a TODO; the brief at line 45 is aspirational ("SIMD-friendly via the existing `wide` crate") not prescriptive.
5. **`bilinear_sample` `WORLD_SIZE` constant coupling.** The function assumes `WORLD_SIZE = GRASS_GRID_DIM * GRASS_CELL_SIZE = 600`. If the world ever changes size (out-of-scope for v1.2), this assumption breaks. A `const _: () = assert!(WORLD_SIZE == GRASS_GRID_DIM as f32 * GRASS_CELL_SIZE);` compile-time check guards it.
6. **`cells_overlapping_circle` `r ≤ half_world` assumption.** Same as P1a's `for_each_in_radius` assumption per master plan §F #4 (line 313). All P1e callers pass body radius ≤ 11u, well under 300u half-world. Documented via `debug_assert!`.
7. **`initial_seed_count` collision behavior** (test #14 above) — for `initial_seed_count > GRASS_CELL_COUNT`, the loop runs N times but only seeds at most `GRASS_CELL_COUNT` unique cells. The dev-panel slider caps at 100, so this is not reachable in practice; nonetheless, document the "up to N" semantics in the doc comment.
