# Mission: Brain Overhaul + Color & Vision Refresh (v1.5)

*Revised after review (`docs/plans/v1.5-mission-review.md`). Original mission preserved in git history; changes integrated below.*

## Goal

Make population behavior **legible** and **evolvable to higher peaks** by:

1. Rebuilding NN inputs around semantic, low-bandwidth signals (32 inputs instead of 112).
2. Going deeper (1 hidden layer → 2) with Leaky ReLU activation in hidden layers.
3. Replacing NN-weight-hash colors with action-history colors so a glance tells you *what creatures are doing*.

Secondary: scale grass up by 16× without melting the renderer; tidy a handful of UX papercuts; spawn N founders so evolution doesn't stall on a single unlucky seed.

## Why now

The current 112-input brain *appears* to plateau, though we have no quantitative metric to confirm — we're acting on a hypothesis. The 72-slot RGB vision and 25-slot grass-patch blocks are bandwidth without semantic value, and a single hidden layer with `tanh` can't hierarchically compose features. NN-hash colors flicker on every mutation and tell the user nothing about strategy. Grass at 5u/cell looks blocky and limits sim fidelity.

This mission ships the *building blocks* and adds an objective success metric so we can measure whether the new brain is actually better.

## Baseline

Main HEAD: `1f5692e` (WebGL2 instanced renderer landed; mission's grass texture work is *narrowing the existing R32F upload to R8 + dirty-rect*, NOT a Canvas2D→WebGL migration). Renderer entrypoint is `web/src/render-gl.ts`; `web/src/render.ts` is now ~40 lines of camera math.

## Locked-in design decisions

### Brain inputs (32 total)

All inputs are encoded so that **positive signal = "this matters right now"**.

```
Self / memory (8):
  hunger                  (1 - energy/energy_max; 0 = full, 1 = empty)
  age_frac                (0 = newborn, 1 = at death-age)
  prev_vx, prev_vy        (last tick's clipped velocity, normalized by MOVE_SPEED_MAX)
  is_last_action_graze    (0/1)
  is_last_action_eat      (0/1)  → split implied when both = 0
  ticks_since_last_split  (clamped to [0, 1] via min(t/100, 1))
  cooldown_ready          (0 = can't eat yet, 1 = can eat now)

Vision (22):
  wall_proximity × 4      N/S/E/W. 1 = right against the wall, 0 = ≥50 units away.
                          Pure arithmetic (no raycasting). At a corner, two walls
                          each fire 1.0 independently; brain learns the 2-wall case.
  creature_proximity × 8  8 angular sectors, WORLD-ALIGNED (N/E/S/W + 4 diagonals).
                          Bilinear sector weighting: a hit at angle 50° contributes
                          0.78 to sector 1 (45°) and 0.22 to sector 2 (90°).
                          Eliminates flicker at sector boundaries.
                          1 = nearest creature at distance 0, 0 = ≥20 units or no creature.
                          Spatial-grid query; no raycasting.
  grass_density × 8       8 angular sectors. 1 = sector saturated, 0 = empty.
                          Sum of cell densities weighted by 1/dist², range ~20 units.
                          See "Grass-sector perf" below.
  nearest_creature_color  Dominant action-EMA channel of the nearest creature within
                          range, packed as a single float in [0, 1]:
                          0.0 ≤ green-dominant ≤ 0.33 < blue-dominant ≤ 0.66 < red-dominant ≤ 1.0.
                          Minimum-viable predator-signaling: lets prey learn "the
                          close thing is an eater." Zero if no creature in range.
  curr_grass_density      Density of the cell(s) the creature overlaps. Decides
                          "should I graze NOW vs. move."

Constants (1):
  1.0                     Implicit bias-learning (weight × 1 acts as a bias term).

Padding (1):
  0                       SIMD alignment to 32 = 4 × 8. Reserved.
```

**Distance scales (locked):**
- `creature_proximity` + `grass_density` range: **20 units** (≈ 4 max-speed ticks).
- `wall_proximity` range: **50 units**.

### Brain architecture

- **2 hidden layers**, shape `32 → 48 → 24 → 5`.
- **Leaky ReLU** (slope = 0.01) in hidden layers. Rationale: under random-weight mutation, sign-preservation makes single-weight mutations produce smoother fitness changes than ReLU (which collapses negative outputs to zero binary). NOT the "dying neurons" gradient-descent pathology — there's no gradient here.
- **`tanh` on velocity outputs** (`out[0..2]`).
- **No activation on action logits** (`out[2..5]`).
- Weight count: `32×48 + 48×24 + 24×5 = 2,808` — same as current shallow net.

**Initialization (He / Kaiming, per-layer):**
For uniform `U(-r, +r)` with `Var(W) = 2/fan_in`: `r = sqrt(6/fan_in)`.

- Layer 1 (fan_in=32): `r_l1 ≈ 0.433`
- Layer 2 (fan_in=48): `r_l2 ≈ 0.354`
- Layer 3 / output (fan_in=24): `r_l3 = 0.500`

Constants: three new `NN_INIT_RANGE_L1/L2/L3`. (Or single `NN_INIT_RANGE = 0.5` if we want to keep one knob; mission picks per-layer to avoid under-scaling layer-3 logits, which biases action selection toward fallback Graze at founder time.)

**Mutation rates unchanged** (`NN_MUT_RATE_DEFAULT = 0.02`, `NN_MUT_SIGMA_DEFAULT = 0.02`). Flag for v1.5.1 sweep if defaults underperform with new architecture.

**Existing brains are not preserved.** Fresh world only.

### Colors — action-EMA, not NN-weight hash

Per-creature 3-channel EMA, clamped to `[0, 1]`:

- **Green (Graze):** `+0.01` on a tick where **argmax was Graze** (NOT the final action after validity fallthrough — predators in cooldown should not bleed Green); `−0.01` otherwise.
- **Blue (Split):** `+0.5` on a Split tick, `−0.005` otherwise.
- **Red (Eat):** `+0.1` per **successful bite** (only when prey is actually contacted; data source: `scratch_got_a_bite` already tracked in `tick.rs::eat`), `−0.001` per non-biting tick.

**Initialization at birth:** `(0, 0, 0)`. Color emerges from observed behavior, not inheritance.

**Display floor:** when rendering, clamp each channel to `[0.15, 1.0]` so creatures aren't invisible-black on the dark background. The raw EMA values stay unclamped for inspector readout.

All deltas are hardcoded constants for v1.5; promote to sliders if iteration demands it.

### Multi-founder seeding (NEW)

To defend evaluability of the brain redesign: spawn **N founders** at world init instead of 1.

- Constant: `FOUNDER_COUNT_DEFAULT = 8`.
- Dev slider: `founder_count` ∈ `[1, 32]`.
- Positions: spread uniformly across world (halton sequence or 2D grid); each founder gets an independently-seeded random NN.

Rationale: 80% single-founder extinction rate (observed in v1.3) masks brain quality. With N=8, effective extinction is ~17%, so we can actually tell whether the new brain works.

### Grass scale-up

**Cell size 5u → 1.25u** (16× cells, **480×480 = 230,400 total** at `WORLD_SIZE = 600`).

**Sim:** `for_each_cell_overlapping_circle` already iterates correctly at smaller cells. Founder body radius 1.0 will overlap 1–4 cells per tick (NOT "~8" — that was off; radius-1 circle fits inside a 1.25u cell most of the time). The old 5×5 grass-patch block in `build_nn_input` is *deleted* (replaced by `grass_density × 8` sectors); the sim-side `graze()` doesn't change.

**Render path** (already WebGL2):
- Switch grass texture from `R32F` → `R8`. Density values `f32 ∈ [0, 1]` quantize to `u8 ∈ [0, 255]`.
- Add a `Vec<u8>` scratch buffer on `WorldHandle` for the per-frame quantization (~230 KB).
- Whole-frame `texSubImage2D` upload. At R8 × 230k cells = 230 KB/frame × 60 FPS = **13.8 MB/s** — well within the 25 MB/s budget.
- **Dirty-rect tracking deferred to v1.5.1** if measurement shows R8 alone isn't enough.

`initial seed N` slider max bumps to **8,000** so coverage stays usable at the new density.

### Grass-sector perf (corrected from review)

The new `grass_density × 8` input is the most expensive NN input we've ever added. The original estimate was off by 4× on cell count. Corrected numbers:

- 40×40 unit AABB at 1.25u cells = **32×32 = 1024 cells** per creature (~804 after circle-clip).
- Naive: 1000 creatures × ~50 ns atan2 × 1024 cells ≈ **50 ms/tick** — destroys frame budget. LUT motivation is *stronger*, not weaker.

Optimization strategy (target: ≤2 ms at 1000 creatures, regime-dependent on grass coverage):

1. **Precomputed sector-LUT.** Indexed by integer `(cell_dx, cell_dy)` offset; value is `(u8 sector_id, f32 weight)`. 33×33 = 1089 entries × 5 bytes = **5.4 KB** (fits in L1). Eliminates `atan2`.
2. **Skip empty cells.** `if density == 0 { continue; }`. Dominant optimization — performance scales with live coverage, not cell count.
3. **Per-row "any non-empty" bitset on `GrassGrid`** (~480 bytes). Regenerated during `step()`. The grass-sector scan skips whole *rows* in O(1) when sparse. Closes the mid-game band where skip-empty alone leaves ~8 ms/tick at ~20% coverage.
4. **`dx² + dy² > max_range²` for range cull** (no sqrt).
5. **Parallelize across creatures** via dynamic `N_CHUNKS` (see Threading below).
6. **Hot scratch buffer for 8 accumulators** per creature, reused across the chunk.

Performance band (from review C4):
- **Best case (early game, ~0.02% coverage):** ~10 μs/tick. Free.
- **Mid game (~20% coverage, without per-row bitset):** ~8 ms/tick — *busts the 2 ms target*. With per-row bitset: closer to ~0.5 ms (most rows empty, skipped).
- **Worst case (~50%+ coverage):** ~1.25 ms/tick with parallelism.

### Threading + worker utilization

- **Make `N_CHUNKS` dynamic on pop:** `chunks = clamp(pop / 32, 4, min(16, worker_count))`. Avoids small-pop false-sharing and large-pop under-utilization. Replaces the constant `N_CHUNKS = 8`.
- **Verify wasm-bindgen-rayon `initThreadPool` count.** Currently called with `navigator.hardwareConcurrency`. Bumping N_CHUNKS does nothing if the JS-side pool is undersized.
- **Worker-utilization widget DEFERRED to v1.5.1.** Low-leverage relative to the rest. If we ship it, rename "active/total" → "chunks: A/B" — rayon's work-stealing doesn't expose per-thread dispatch cheaply.

### Curriculum (REWORKED from review)

The original "factor = 0 below `min_pop`" design anaesthetizes selection during the regime that most needs gradient. Reworked with a **MIN_FACTOR floor** so selection pressure never fully zeros:

```
factor = MIN_FACTOR + (1.0 - MIN_FACTOR) * smoothstep(min_pop, max_pop, current_pop)
```

- `MIN_FACTOR = 0.25` (locked default; can be slider-tuned later).
- `curriculum_min_pop` default 1000.
- `curriculum_max_pop` default 2000.
- `auto_curriculum` toggle, default ON.
- Effective costs applied = `user_slider_value × factor`.
  - At pop = 0–`min_pop`: factor = 0.25. Bad brains still die, just more slowly.
  - At pop ≥ `max_pop`: factor = 1.0.
  - In between: smooth ramp.

This keeps the brain redesign's selection signal alive at low pop while still relieving pressure when the population is fragile.

**Alternative considered: time-based ramp** (costs ramp 0→1 over first 5000 ticks regardless of pop). Avoids the population-feedback oscillation but doesn't help with population fragility. Sticking with population-feedback + floor.

## Success criteria (implementation + measurement)

Done means:

1. The new 32-input brain builds, runs, and doesn't panic at high pop.
2. **Quantitative metric (NEW):** mean creature age > 500 by tick 10,000 with default sliders + multi-founder N=8. (Falsifiable; replaces "color visibly reflects strategy" alone.)
3. Color *visibly* reflects creature strategy under manual play — a creature that eats lots of others trends red; splits often → blue; grazes constantly → green.
4. Grass renders at 16× density without dropping below ~16ms/frame at 1000 creatures.
5. Grass upload bandwidth ≤ 25 MB/s with default propagation (R8 whole-frame ≈ 13.8 MB/s — well under).
6. All existing Rust tests pass (or are updated to reflect the new contract). Expect ~20-30 tests rewritten (NN layout, brain weight layout, vision raycast).
7. Dev panel, TPS dropdown, and right-edge settings layout look intentional, not glitched.

**Pre-flight baseline:** before landing #6 (grass scale-up), capture today's tick-cost breakdown via `profile_report_json()` at pop=1000 with `--features threads`. Compare post-mission: NN should be faster (smaller inputs), grass-step ~16× scaled but bounded, grass-sector new but ≤2 ms in the dominant regime.

## Architecture / topology notes for future iteration

If `32 → 48 → 24 → 5` plateaus during play:

- **Wider** (`32 → 64 → 32 → 5`) is the lowest-risk next step.
- **Deeper** (`32 → 32 → 32 → 32 → 5`) is higher-risk — each layer multiplicatively slows evolutionary convergence.
- Avoid **inverse pyramids** — early bottlenecks throw away input signal.

Research pointers (not commitments): Universal approximation theorem, NEAT (Stanley & Miikkulainen 2002), Quality diversity / MAP-Elites / novelty search, CMA-ES.
