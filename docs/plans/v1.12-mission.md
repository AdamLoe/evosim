# Mission: v1.12 — NN tab, mutation buckets, runtime-shaped Brain

## Goal

Give the user a dedicated "NN" rail tab that exposes two independent
controls over neural evolution:

- **Left pane — NN structure editor.** Stage-then-apply. Add/remove
  hidden layers (1–8), set each layer's width (multiple of 8), pick a
  per-layer activation function. Apply triggers a worker restart and
  reshapes `Brain` at construction. Live perf log section shows per-layer
  `nn.forward.l{k}` timings against the new topology.
- **Right pane — mutation policy editor.** Live-apply. Up to 8 buckets,
  each `{weight, rate, sigma}`. Per-birth, a bucket is sampled by weight
  and its `(rate, sigma)` drives the geometric-skip mutation. This
  subsumes the existing `nn_mutation_sigma` slider and the per-creature
  `nn_mutation_rate` drift mechanic — both are removed.

Performance budget: ≤5% regression on `nn.forward.total` at pop 1500 with
the legacy 32→48→24→5 topology and the legacy-equivalent single-bucket
mutation policy. If we trip the budget, fall back to const-generic
monomorphisation for common (fan_in, fan_out) pairs.

## Scope

- New `MutationPolicy` struct on `DevSliders` with 8 fixed-size buckets.
- `Brain::child_from` signature change: takes `&MutationPolicy` instead
  of `sigma: f32`. Bucket draw replaces per-lineage rate drift.
- Delete `Brain.nn_mutation_rate` field, `NN_MUT_RATE_DEFAULT`,
  `MUT_RATE_OF_RATES`, `MUT_RATE_JITTER`, and `DevSliders.nn_mutation_sigma`.
- Extend `SLIDER_NAMES` by 24 entries (`bucket_0_weight` …
  `bucket_7_sigma`). Remove `nn_mutation_sigma` from the list. Regenerate
  TS bindings.
- Runtime-shaped `Brain`: `Vec<usize> layer_sizes`, `Vec<Activation>
  activations`, `Vec<f32> weights`. Forward pass becomes a layer loop.
  Drop the `NN_HIDDEN_1`/`NN_HIDDEN_2` constants and the
  `NN_WEIGHT_COUNT` compile-assert.
- `Activation` enum: `LReLU(slope)`, `ReLU`, `Tanh`, `Sigmoid`, `Linear`.
  Applied after the per-row `reduce_add`, outside the SIMD inner loop.
- Output projection (tanh on `out[0]`, `out[1]`; raw logits on `out[2..5]`)
  preserved as a fixed post-layer step, not part of the user-editable
  activation list.
- Per-layer profiler counters: replace fixed
  `tick_forward_l1_us`/`_l2_us`/`_l3_us` with
  `Vec<AtomicU64> tick_forward_layer_us` (+ paired `_calls`). Sized at
  world construction.
- Boot payload schema extended with `nn_topology: { layer_sizes: number[],
  activations: string[] }`.
- New rail tab `"nn"` in `RailTab` union, `#rail-nn` panel in
  `web/index.html`, installer in `web/src/rail/nn.ts` (new file).
- NN tab left pane: layer-list editor with add/remove rows, width number
  input with multiple-of-8 validation, activation dropdown. Header
  pinned `inputs=32`, footer pinned `outputs=5`. Stage-then-apply.
  Apply triggers `respawnWorker()`.
- NN tab right pane: 8-row table of `{weight, rate, sigma}` number
  inputs. Weight-bar visualisation. Live-apply (24 × debounced
  `set_slider`).
- NN tab perf-log section: per-layer rows polled from the profile
  report, layer count tracked against the currently-applied topology.

## Non-goals

- Per-bucket distribution shape (Cauchy / heavy-tail). Stays Gaussian.
- Per-bucket layer targeting (mutate only output layer, etc.).
- Variable input width — `NN_INPUTS = 32` stays const.
- Variable output width — `NN_OUTPUTS = 5` stays const.
- Sharing topologies across users (no export/import in v1.12).
- Cross-layer skip connections, normalisation, dropout. The net stays a
  pyramid of dense matmuls with per-layer activation.
- Per-layer init range tuning beyond the He-uniform default
  `r = sqrt(6 / fan_in)` (computed from each layer's fan_in at
  construction).

## Plan

Three sequential waves. M1 ships standalone. M2 and M3 ship together —
M2's Apply button is meaningless without M3.

### Wave 1 — Mutation buckets (live-apply)

1. **Backend types.** Add `Bucket { weight: f32, rate: f32, sigma: f32 }`
   and `MutationPolicy { buckets: [Bucket; 8] }` to `src/brain.rs`.
   Default = bucket 0 `{1.0, 0.02, 0.02}`, buckets 1–7 zero.
2. **Wire into `DevSliders`.** Replace `nn_mutation_sigma: f32` with
   `mutation_policy: MutationPolicy`. Update `Default` impl.
3. **`Brain::child_from` rewrite.** Signature becomes
   `(parent, rng, policy, multiplier)`. Algorithm:
   - Compute `total = sum(bucket.weight)`.
   - **If `total <= 0.0`**, return `parent.clone()` — no RNG draws,
     no mutation. This is the user-facing freeze-evolution path.
   - Otherwise, draw `u = rng.unit() * total`, walk the buckets to
     pick the selected one (cumulative-weight scan).
   - Apply geometric-skip with `(bucket.rate * multiplier, bucket.sigma)`.

   Delete the drift block (`MUT_RATE_OF_RATES` / `MUT_RATE_JITTER`).
4. **Delete `Brain.nn_mutation_rate`** and the three drift constants.
   Update `Brain::founder`, `Brain::zero`, and the existing mutation
   unit tests.
5. **SAB slider layout.** `SLIDER_NAMES` is index-dispatched in
   `try_set_slider_by_index` ([src/wasm_api.rs](src/wasm_api.rs)), so
   removing a slot would renumber every later index and force a TS
   binding regen against drift. Instead: **rename index 1 in place** to
   `_reserved_legacy_nn_mutation_sigma` and make its `try_set_slider`
   arm a no-op (still consumes the value to avoid a "unknown slider"
   error during the transition tick). Append
   `bucket_0_weight`, `bucket_0_rate`, `bucket_0_sigma`, …,
   `bucket_7_sigma` (24 entries). All other slider indices stay
   byte-identical with main.
6. **TS binding regen.** `cargo run --bin gen-bindings`. Verify
   `web/src/generated/slider-ids.ts` matches.
7. **Slider drift-guard test.** Existing
   `web/tests/e2e/defaults-drift.spec.ts` and the `bindings_in_sync`
   Rust unit test cover this. The reserved-slot rename means the
   bindings test sees 23 + 24 = 47 sliders (1 reserved + 24 buckets +
   the 22 untouched live sliders).
8. **Settings persistence.** Bucket values must survive page reload.
   Add an 8-element array of `{weight, rate, sigma}` to the `Settings`
   interface in [web/src/settings.ts](web/src/settings.ts) with the
   same defaults as the Rust side (bucket 0 `{1.0, 0.02, 0.02}`, others
   zero). Extend `currentSliderState()` in
   [web/src/widgets/devpanel.ts](web/src/widgets/devpanel.ts) to fan
   the 8 buckets out into 24 `set_slider` boot-payload entries so the
   worker re-applies on respawn. The unknown-key filter on load
   ([settings.ts](web/src/settings.ts)) gates against malformed
   localStorage state.
9. **Frontend.** Add NN tab shell (just the tab button + empty panel for
   now) so the right-pane bucket editor has a home. Stub the left pane
   with "Coming in v1.12 wave 2." Right pane: 8-row table installer
   `installMutationBucketsPane(host)`. Each cell debounces a
   `set_slider("bucket_k_<field>", v)` call AND writes through to
   `Settings.mutationBuckets[k][field]` so the value persists.

### Wave 2 — NN tab structure editor (stage-then-apply UI)

1. **DOM.** Add `#rail-nn` panel and `data-tab="nn"` button to
   `web/index.html`. Add `"nn"` to `RailTab` union in
   `web/src/rail/index.ts`. Move bucket-editor install from wave 1's
   stub into the right-pane slot.
2. **Left pane installer.** `web/src/rail/nn-topology.ts`. Layer-list
   widget with:
   - Add Layer button (max 8 hidden layers).
   - Per-row: width input (number, step 8, validated multiple-of-8
     in `[8, 256]`), activation dropdown, remove button.
   - Pinned `inputs=32` header, `outputs=5` footer.
   - Apply / Cancel / Reset footer with dirty tracking.
   - Apply path: validate → write through to
     `Settings.nnTopology` → call `respawnWorker()` (which reads
     `Settings.nnTopology` when building the boot payload).
3. **Topology persistence.** Add `nnTopology: { layerSizes: number[],
   activations: string[] }` to the `Settings` interface in
   [web/src/settings.ts](web/src/settings.ts). Default =
   `{ layerSizes: [48, 24], activations: ["lrelu", "lrelu"] }`
   (hidden layers only — inputs/outputs are implicit). The unknown-key
   filter on load gates against malformed state; if any of
   `layerSizes`/`activations` arrays are missing, wrong length, or
   contain invalid widths/activation names, fall back to defaults.
4. **Boot payload.** Extend `boot` message in
   `shared-memory-and-protocol.md` schema with `nn_topology`. Default if
   absent: legacy `{layer_sizes: [32, 48, 24, 5], activations: ["lrelu",
   "lrelu", "linear"]}`.
5. **Reset semantics.** "Reset" button reverts to the legacy topology
   above. Doesn't auto-Apply.
6. **No toast on topology Apply.** The construction-only toast exists
   to tell users "this knob shapes the *next* world but you're viewing
   the current one" ([app-shell.md](../architecture/app-shell.md)).
   Topology Apply *creates* the next world immediately, so the toast
   would be misleading. Skip it. The visible respawn (~500 ms canvas
   blip) is the feedback. Bucket edits on the right pane do not touch
   construction-only state and never toast.
7. **Perf log section.** Below the editor. Polls the profile report at
   the same 1 Hz cadence as the perf panel. Renders one row per current
   hidden layer using the **1-based naming convention already in
   `src/world/nn.rs`** (`nn.forward.l1`, `nn.forward.l2`, …,
   `nn.forward.l{N}`). Row label: `l1  X.X µs/creature   N.NN ms
   total`. **Wave 3 must extend, not renumber, the existing
   `l1`/`l2`/`l3` names** so legacy three-layer topologies render
   identically.

### Wave 3 — Runtime-shaped `Brain` (backend, performance-critical)

1. **`Brain` struct.** Add `layer_sizes: Vec<usize>`, `activations:
   Vec<Activation>`. `weights` stays `Vec<f32>` but length is now
   computed at construction: `sum(layer_sizes[i] * layer_sizes[i+1])`.
2. **`Brain::founder(rng, layer_sizes, activations)`.** Per-layer
   He-uniform init: `r = sqrt(6 / fan_in)`.
3. **`Brain::forward` rewrite.** Two kernels:
   - `matmul_simd_tiled(w, in, out, fan_in, fan_out)` — runtime version
     of today's 4× output-tile loop. Used for every hidden→hidden step.
     Requires `fan_in % 8 == 0` AND `fan_out % 4 == 0`. The
     multiple-of-8 width invariant satisfies both.
   - `matmul_output(w, in, out, fan_in)` — preserves today's
     output-layer kernel (per-output untiled SIMD reduce). `NN_OUTPUTS
     = 5` is fixed, so this kernel hard-codes a 5-iteration outer loop
     and only `fan_in` is dynamic. Activation is `Linear` for the raw
     logits, but the output projection (tanh on `out[0]`, `out[1]`)
     fires as a fixed post-step regardless of the user's last-hidden
     activation.

   Layer loop:
   ```
   for k in 0..hidden_count {
       let (fan_in, fan_out) = (sizes[k], sizes[k+1]);
       matmul_simd_tiled(weights_slice, input, output, fan_in, fan_out);
       apply_activation(activations[k], output);
       swap(input, output);
   }
   matmul_output(last_weights, input, raw_logits, sizes[last_hidden]);
   apply_output_projection(raw_logits);  // tanh on out[0], out[1]
   ```
   Two scratch `Vec<f32>` buffers ping-pong as layer input/output.
4. **Scratch buffers.** Live on `World`, sized at construction to
   `max(layer_sizes)` so the forward pass never allocates. Pre-existing
   `hidden_1`/`hidden_2` scratch retired.
5. **Per-layer profiler counters.** `NnStats` gains
   `tick_forward_layer_us: Vec<AtomicU64>` and
   `tick_forward_layer_calls: Vec<AtomicU64>`, sized at world
   construction. `record_chunk_subphases` takes a `&[u64]` per-layer
   slice. The post-tick drain emits **1-based** rows
   `nn.forward.l1`, `nn.forward.l2`, … for k = 1..=hidden_count
   (preserving the existing naming so legacy three-layer topologies
   render identically). Delete the three hard-coded
   `tick_forward_l1_us` / `_l2_us` / `_l3_us` atomics.
6. **Reference scalar `forward_scalar`.** Updated to match. The
   SIMD-vs-scalar drift-guard test parameterised over three topologies:
   `[32,48,24,5]`, `[32,64,32,16,5]`, `[32,8,5]`.
7. **Bench gate.** Microbenchmark `Brain::forward` at the legacy
   topology, compare against `main`. Gate at ≤5% wall-clock regression
   over 100k iterations.
8. **Fallback (only if gate trips).** Add
   `fn matmul_const<const FAN_IN: usize, const FAN_OUT: usize>(...)` and
   a `match (fan_in, fan_out)` dispatcher for `(32, 48)`, `(48, 24)`,
   `(24, 5)`. Common topology gets fully-unrolled code; exotic
   topologies fall through to the generic kernel.

## Verification

- `cargo test --lib` — `forward_pass_matches_scalar_reference`
  parameterised, all bucket unit tests, slider drift-guard.
- `cargo test --features threads --target wasm32-unknown-unknown` —
  full sim test pass on the wasm side.
- Microbench (manual, native) — `Brain::forward` over 100k iterations,
  legacy topology, vs `main`. Record p50 + p99. Gate ≤5% p50 regression.
- Playwright e2e — new spec `nn-tab.spec.ts` exercising:
  - default panel renders, legacy topology shown.
  - mutation-bucket edit live-applies (verify via inspector
    `nn_mutation_*` is gone; bucket sliders round-trip).
  - topology Apply triggers a restart (worker terminate observable
    via a `boot_ready` count).
  - invalid width (not multiple of 8) blocks Apply.
- Manual browser smoke — load app, switch to NN tab, build a
  `32→64→64→5` net with `tanh`/`lrelu`/`linear`, Apply, watch perf log
  populate `l0`/`l1`/`l2`, watch population stabilise.

## Status

Draft. Micro-decisions locked:

- **Bucket weight semantics.** Per-birth, the 8 bucket weights are
  normalized to sum=1. **If the sum is 0 (user zeroed everything), no
  mutation runs at all** — child is a bit-identical clone of the
  parent. This is the user-facing "freeze evolution" mode; setting
  every bucket to weight=0 is the explicit no-mutation switch. Bucket 0
  no longer has any special status.
- **Activation enum on the wire.** Each activation rides the boot
  payload as a lowercase string (`"lrelu" | "relu" | "tanh" |
  "sigmoid" | "linear"`). LReLU slope is fixed at 0.01 in v1.12 — a
  per-layer slope slider can ship later if needed.
- **Worker restart UX during NN Apply.** No loading overlay, no toast.
  Existing `worker.terminate()` + spawn drops the renderer onto the
  last-good frame for ~500 ms; that's already fast enough to feel
  instant. If post-implementation profiling shows the gap is jarring
  (e.g. >1 s on slow hardware), revisit with a brief toast.
- **`%busy` table after topology change.** Implicit reset via restart.
  Worker terminate → new `NnStats` → counters start at 0 on the new
  topology. No special handling, no carry-over. Matches every other
  piece of lifetime worker state.
