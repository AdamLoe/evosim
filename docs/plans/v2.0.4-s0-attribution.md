# S0 C0 Attribution Bench — Findings

## Purpose

Gate document for stream S5 (geometric-skip + fused-RNG + rare-event tuning).
Measures per-lever ns/cell for the scatter kernel at 6.25% and ~90% fill.

## Setup

- Grid: world_size=2560 → grass_dim=512 → 512²=262 144 cells, 16×16=256 tiles
- Frontier fill: 16 384 seeded cells = ~6.25%, grassy_cells=15 925, ALL 256 tiles active
- Dense fill: 236 029 seeded cells = ~90%, grassy_cells=155 736, ALL 256 tiles active
- ns/cell denominator = **total tile cells** (262 144) to match plan's baseline convention
- Machine: native x86_64, WSL2, single-process (sequential variants)
- Bench: `benches/grass_attribution.rs` (new), criterion 0.5, bench profile (opt-level 3, lto=thin)
- Rayon shim: `rayon::prelude::par_iter` fanning the same tile kernel across native threads

## Per-lever ns/cell breakdown

Each row is the **incremental** cost added by that lever on top of the row above.
"total" rows show the cumulative cost up to and including that lever.

| lever | 6.25% fill (ns/cell) | ~90% fill (ns/cell) | notes |
|-------|----------------------|--------------------|-------|
| freeze (O-tile floor) | **0.95** | **3.08** | Reads every tile cell into src; irreducible with current design |
| + alloc (C1) | **+0.37** | **+0.39** | Vec::with_capacity(tw*th) per tile; ~constant regardless of fill |
| + instrumentation (C2) | **+0.06** | **~0.00** | Instant::now()+fetch_add / 256 tiles; amortized to noise |
| *subtotal (no RNG, no RMW)* | *1.38* | *3.37* | — |
| + RNG 4-hash (production) | **+0.69** | **+3.05** | 4× grass_hash_u64 per grassy cell; fill-proportional |
| + RNG 1-hash (fused C3) | **+0.57** | **+2.19** | 1 hash bit-sliced 4 ways; saves 0.12/0.86 ns vs 4-hash |
| *subtotal (4hash, no RMW)* | *2.07* | *6.42* | — |
| + RMW atomic | **+0.71** | **+2.90** | scatter_add/scatter_sub on AtomicU8; fill-proportional |
| *subtotal (4hash+RMW)* | *2.78* | *9.32* | — |

**Parallel rayon shim (wall-clock ns/cell):**

| variant | 6.25% seq | 6.25% par | ~90% seq | ~90% par |

| component | 6.25% fill | ~90% fill | dominant? |

## VERDICT

**RNG is the dominant fill-proportional per-cell cost at dense (~90%) fill: 3.05 ns/cell out of 6.42 ns/cell total (47%), comparable to RMW at 2.90 ns/cell.**

**Stream S5 (geometric-skip + fused-RNG) gate: MIXED.**
- Fused-RNG (C3) is worth landing: saves 0.86 ns/cell at dense (13%). Cheap and safe.
- Geometric-skip (C4) as implemented here is **counterproductive at both fill levels**:
  - At 6.25% fill: skip adds overhead (compact list build + tile-keyed gap RNG) > savings from fewer spread calls.
  - At ~90% fill: 25.1 ns/cell vs 6.42 — ~4× SLOWER. The compact list construction is O(grassy), and the tile-keyed geometric-skip RNG (per-gap hash call) is not cheaper than the per-cell roll it replaces.
- The geom_skip result here uses a tile-keyed hash for gap draws (one `grass_hash_u64` per gap). Production C4 would need a different per-tile stream RNG to be efficient. But the ~90% result implies the residual freeze+decay O(N) floor dominates regardless.

**Recommendation:**
- **C3 (fused RNG): YES — land it.** Small but real saving especially at dense.
- **C4 (geometric-skip): NO — drop stream S5 in its current form.** The bench shows skip is net-harmful. The plan's "fallback if C0 says RNG is NOT the cost" does not fully apply (RNG is a large cost), but C4 is not the right lever: at dense fill the freeze+decay floor is 3.08/6.42 = 48% of cost and is irreducible without a compact-list restructuring of the freeze itself. The compact-cell-list approach (perf-optimization-ideas.md #3) is the only path to true O(events), but that is a much larger refactor gated on a separate decision.
- **C1 (alloc): YES — land it.** 0.37–0.39 ns/cell, constant, cheap fix.
- **C2 (instrumentation): worth gating** even though it's small sequentially — the par shim shows real contention at 6.25% frontier where all tiles are competing for the same 2 cache lines.

## Caveats

1. **geom_skip bench limitation**: The bench uses `grass_hash_u64` for gap draws (a fresh hash per gap). A production implementation might use a stateful per-tile LCG for gap draws, which could be cheaper. The bench measures the "hash-based gap" variant; a stateful variant was not prototyped. Conclusion (skip is harmful) is likely correct for the 90%-fill residual-floor reason regardless of gap-RNG cost.

2. **Instrumentation cost**: The bench uses `std::time::Instant::now()` as proxy for `clock_now_us_threadsafe()`. The production profiler uses platform-native monotonic clock (same underlying call on Linux). The measured 0.06 ns/cell ÷ 256 tiles × 2 calls ≈ ~8 µs per pair of Instant calls is consistent with a fast VDSO clock. The real production cost may differ slightly on wasm (where the clock is `performance.now()` via JS).

3. **RMW bench is simplified**: The RMW variant applies `scatter_add` to a fixed `(c+1) % len` cell rather than resolving a disc-table target. This isolates the atomic read-modify-store cost but omits the disc-table lookup and wrap arithmetic. The full production path costs slightly more than the `rng_4hash_rmw` number.

4. **All tiles active at both fill levels**: `active_tiles=256` at both fills means the bench measures the fully-active-frontier case. In production at ~6.25% fill, only 40–120 tiles are typically active; the bench is slightly pessimistic for frontier.
