## Decisions log

- 2026-06-01 — Hub created; awaiting the lead's problem list before
  launching any recon or implementation agents.
- 2026-06-01 — Two recon agents (web shell / grass+SAB perf) returned;
  findings in `v2.0.1-recon-web.md` and `v2.0.1-recon-grass-perf.md`.
- 2026-06-01 — Wave 1 (web): S-RENDER (#1,#4) and S-INPUT (#2) landed,
  typecheck clean, visual confirm deferred to end gate.
- 2026-06-01 — **#3 reopened**: recon mis-identified the buttons (looked at
  Play/Pause/Restart/Perf top-bar; lead meant settings/NN/inspector
  right-rail openers). Root cause still unknown. New stream S-BTN.
- 2026-06-01 — **Grass perf decision**: lead rejected every-N-tick cadence
  throttling as the path to 10–20×. Strategy pivots to SPATIAL sparsity —
  exploit that only the growth frontier changes per tick (most cells are
  bare-0 or saturated-K equilibrium). Levers: organic separable blur
  (fixes diamond #5), active/dirty-tile frontier processing, native u8
  density (snapshot write → memcpy of changed tiles), wasm-SIMD. Keeps
  every-tick visual smoothness. All Rust-internal, no SAB seam change.
- 2026-06-01 — **Lead commits to decoupling the snapshot write from the
  tick thread** (new stream S-WRITER). A separate writer thread/worker
  does the quantize+copy concurrently so `write_output_sab` leaves the
  tick critical path. Composes with (does NOT replace) the grass
  cost-reduction work. Hazard to solve: writer reads tick T state while
  tick T+1 mutates — lean on grass ping-pong (safe if native-u8) for the
  3.69MB grass region; fast-stage the small creature SoA on the tick
  thread. CORRECTNESS-CRITICAL: touches worker control path / futex pacing
  / SAB sequencing → strong-model design + dedicated red-team
  (parallel-determinism + the Atomics regression class). Sequenced AFTER
  the grass design returns so it builds on the finalized write format;
  S-WRITER + S-GRASS land as one coordinated Rust wave (both touch the
  write_snapshot path + worker loop) to avoid collision.
- 2026-06-01 — **#3 decision: three distinct top-right buttons** (not the
  single gear). Settings/NN/Inspector each open the rail to their panel
  with exactly-one-active styling. Follow-up agent dispatched.
- 2026-06-01 — Grass design landed (`v2.0.1-grass-plan.md`): separable
  blur + 32×32 active-tile frontier + u16-internal/u8-snapshot, no seam.
  Held for the coordinated Rust impl wave pending S-WRITER design.
- 2026-06-01 — Writer design landed (`v2.0.1-writer-plan.md`): persistent
  rayon writer thread + fast-stage handshake + 3rd snapshot slot (the one
  additive Rust↔TS seam change). Sim bit-identical writer on/off.
- 2026-06-01 — **Lead: straight through both Rust waves** (no measurement
  pause). Order: grass impl (Phase A) + writer-design red-team in parallel
  → then writer impl (Phase B). Coordination: grass exposes the dirty-tile
  quantize as the callable unit writer's pack() consumes (no double-write).
- 2026-06-01 — **Writer red-team** (`v2.0.1-writer-redteam.md`): 2 blockers
  caught pre-code. Net: **the only Rust↔TS seam change is eliminated** —
  3rd slot dropped, keep 2 slots + a main-side seqlock recheck (re-read
  CTRL_SEQ after building views, discard if advanced). Writer wave is now
  Rust-internal + a ~3-line main.ts read guard. Must-fixes folded into
  Phase B dispatch as binding overrides on the writer plan.
- 2026-06-01 — **Writer Phase B hit two structural blockers** (see S-WRITER
  row). Key correction to the system model: the snapshot PUBLISH
  (CTRL_SEQ/CTRL_CURRENT_SLOT) happens in TS (`sim-worker.ts`) against the
  JS control SAB — Rust only writes snapshot BYTES into wasm memory. The
  writer-plan + red-team both wrongly assumed a Rust publish. (Durable —
  fold into `architecture/` at ship.) **B1 resolution on record** for when
  we build it: Rust writer publishes a wasm-memory seqlock ticket (the real
  release edge); TS mirrors it to the control SAB. No wire change.
- 2026-06-01 — **Lead: defer the writer, measure first.** After the grass
  shape-fix lands green, profile `write_output_sab` + `row_compute.body`
  post-grass-plan, then scope the writer (full grass-staging / creatures-
  only / drop it) against real numbers. Mirrors the u16 measure-first call.
- 2026-06-01 — **MEASURED (threaded, 12 workers, 9600² world):** all 5
  visual fixes PASS in-browser (incl. #4 small-dot YES, #5 disc).
  `write_output_sab`=2.3% of tick → **writer DROPPED**. BUT sim at **2 TPS**,
  `grass_step`=99% of tick (~1.6ms/row) → **#6 perf goal UNMET**; root cause
  = shape-fix recomputes the separable blur per-cell×per-neighbour instead
  of materializing the H pass into scratch (output bit-identical, ~10×
  cost). Frontier steady-state payoff unconfirmed (never saturated at 2 TPS).
- 2026-06-01 — **Lead: defer #6 perf to v2.0.2.** Ship v2.0.1 = 5 fixes +
  correct-but-slow grass shape. Top v2.0.2 item = materialize the 2-pass
  blur into scratch (O(1)/cell) + confirm frontier skips saturated tiles +
  re-measure. Open question carried forward: is the current grass cost a
  regression vs main, or pre-existing? (Needs main baseline — not measured.)
