# Mission: v2.0.0 — World, Body, Species

## Goal

An 8× linear (64× area) world with three biomes, optional toroidal
wrapping, creatures whose **bodies evolve** alongside their brains, and
an opt-in **species + sexual reproduction** mode that turns the sim
from a single drifting pool into 10 starting factions competing across
a real map.

The sim still feels emergent. Species are not detected — they are
seeded. Adaptation and faction dynamics are layered *on top* of the
existing single-pool drift, not replacing it. A construction-time dev
setting (`species_mode`) toggles between the two regimes; one or the
other runs from boot to restart.

Worlds are meant to be **editable across a wide range**, not pinned to
one size. `world_size` is a real runtime construction setting (not a
constant), so the same binary spans two extremes: a tiny, fast,
asexual "screensaver" world where colors fight colors and evolve
quickly, and a grand toroidal map with many species spread across
biomes — each adapting to its terrain, fighting other species, and
competing to survive. Making world size runtime forces grass-grid
dimensions (and therefore snapshot-SAB sizing) to be derived at boot
from settings rather than from compile-time constants — see
[World & biomes](#world--biomes) and the decisions log.

## The two modes

`species_mode` is a construction-time dev-panel toggle. Restart-required,
identical to today's `full_grass_on_init` plumbing.

| | `species_mode = off` (v1 evolved) | `species_mode = on` (headline feature) |
|---|---|---|
| Population | Single pool. | 10 seeded species, founders clumped at random spread-out spawn points. |
| Reproduction | Asexual `Split` (current). | Sexual `Mate` (same-species only, cooldown). |
| Action set | `{Graze, Attack, Split}` | `{Graze, Attack, Mate}` |
| Attack target | Any creature (current `Eat` semantics, renamed). | Other-species only. No cannibalism. |
| Color | Genome-derived hue. | Per-species saturated color. |
| Lineage | None. | Species ID + species history (parent species when splits land — V2.1+). |
| NN proximity inputs | 8-sector unified creature proximity. | 16-sector: 8 same-species + 8 other-species. |
| Inspector lineage | n/a | Species ID + species-history breadcrumb (empty in v2.0, plumbed). |
| Pop graph | Single line (current). | Per-species lines. |

Everything in the rest of this doc applies to *both* modes unless called
out.

## Scope

### What changes vs the current app

| Concern | Today | v2.0.0 |
|---|---|---|
| World size | 1200×1200 walled, compile-time constant | `world_size` runtime construction setting (default 9600), wrap toggle (`wrap_world`) — wraps both axes when on, walls clamp when off. Runtime size ⇒ grass-grid dims + snapshot-SAB sizing derived at boot from settings, not constants |
| World content | Uniform grass plane | 3 static biomes: plains, water, desert |
| Grass model | 960² R8 grid, 1.25u cells, bite-by-density | Coarser 5u grid (1920² ≈ 3.7 MB at default `world_size`; dims = `world_size / 5`), bite-by-density preserved |
| Grass upload | Full-texture `texSubImage2D` each RAF | Dirty-rect sub-uploads keyed on *quantized* (u8) cell changes, accumulated across ticks against an upload epoch (see render section) |
| Biome map | n/a | Static, generated once at boot from `world_seed`; lives in its own boot-time SAB (not in the snapshot) |
| Body traits | Constants (`CREATURE_SIZE`, `MOVE_SPEED_MAX`, etc.) | 6-trait `Genome`, mutated alongside brain weights |
| Reproduction | `Split` only | `Split` xor `Mate` per mode |
| Crossover (mating mode) | n/a | Construction-time `crossover_mode` setting: `average` or `fifty_fifty` per-trait/per-weight |
| Cannibalism | n/a (one pool ⇒ predation) | Species mode: `Attack` refuses same-species (no cannibalism). Single-pool: no species exist, so `Attack` hits any creature — that's the v1 predation mechanic unchanged, not cannibalism. |
| Color | Action-EMA (R/G/B drift) — **deleted** | Genome-derived (single-pool) or species-color (mating); 5-tick action ring flash on top |
| Creature sprite | Uniform radius | `body_size` scales sprite + repulsion radius |
| Camera | Pan/zoom over screen-sized world | Pan/zoom over an 8× world; wrap-aware frustum cull when `wrap_world` is on |
| NN inputs | 32, fixed | Derived from construction settings, SIMD-padded to a multiple of 8. See [NN topology](#nn-topology). Old brains discarded. |
| NN outputs | `vx, vy, {Graze, Eat, Split}` | `vx, vy, {Graze, Attack, Split\|Mate}` — continuous velocity unchanged; only action[2] semantics differ by mode |
| Biome awareness | none | Per-cell `movement_penalty` scalar fed to NN, plus 4-directional biome-penalty inputs (NESW) |
| Inspector | Click → JSON | + species (mating mode), + species history (mating mode), + 6 genome traits, + current movement penalty |
| Monitor | Single pop graph | Per-species pop graph (mating mode) |
| Action color feedback | Body EMA | 5-tick outer-ring flash: blue=created child, teal=just born, yellow=attacked, red=killed, green=grazed |

| Curriculum reserved slider slots (`_reserved_curriculum_17..20`) | Present | Removed |
| World seed | n/a (sim RNG only) | New construction setting `world_seed`, random default, drives **biome generation only** — separate from the sim RNG seed so the same map plays out differently each run (a single master seed would make the whole run a deterministic replay, which we don't want) |

### Genome (both modes)

Six continuous floats in `[0,1]`, rescaled at use site. Stored on a
per-creature SoA column alongside the brain. Mutated by the same
8-bucket policy as brain weights, with a separate sigma multiplier
(default `brain_sigma × 0.3`) so phenotype drifts slower than NN.

| Trait | Effect |
|---|---|
| `body_size` | sprite radius, repulsion radius, energy capacity, attack damage |
| `max_speed` | speed cap, movement-cost multiplier |
| `metabolism` | per-tick idle-upkeep multiplier |
| `diet` | 0 = pure grazer, 1 = pure predator. Scales graze yield and attack effectiveness. |
| `water_affinity` | reduces water-biome movement penalty |
| `heat_tolerance` | reduces desert movement penalty |

**Crossover (mating mode).** Construction-time `crossover_mode`
setting picks between:

- `average` — child trait/weight = elementwise average (midpoint) of
  parents. Homogenizing; relies on geography to differentiate species.
- `fifty_fifty` — child trait/weight = 50/50 pick per slot from the
  two parents. Preserves variance; standard GA crossover.

Both followed by mutation.

**Single-pool mode.** Child genome = parent genome + mutation (no
crossover; asexual).

### World & biomes

- 9600u × 9600u. Wrap on both axes when `wrap_world` is on; walls
  clamp when off. `wrap_world` is a construction-time setting.
- 3 biomes: `{Plains, Water, Desert}`. Static map generated at world
  init from `world_seed` (a few large blobs, not noise speckle).
  Same `world_seed` reproduces the same map across rebuilds of the
  same build — same-machine determinism, the same guarantee the sim
  already makes. No cross-platform byte-identity is promised or tested.
- Biome map and grass grid share resolution at 5u → 1920² cells.
- Storage shape:
  - **Biome map** (`u8` per cell, ~3.7 MB) lives in a dedicated
    `biomeSab` SharedArrayBuffer allocated at boot, written once by
    the worker before posting `boot_ready`, read by the renderer for
    the biome layer. Not in the snapshot SAB — biomes are static for
    v2.0 so per-tick double-buffering would waste 3.7 MB × 2 every
    snapshot.
  - **Grass density** (`u8` per cell, ~3.7 MB) lives in the snapshot
    SAB as today, double-buffered.
- Effect: biome modifies a per-cell `movement_penalty` scalar derived
  from `(biome, water_affinity, heat_tolerance)`. The scalar feeds
  **three effects at once**, each dev-tunable: reduced effective move
  speed, extra per-tick energy upkeep, and a higher move-cost multiplier.
  Penalty applies continuously every tick the creature is in that cell,
  but is *survivable* short-term — a Plains-adapted creature can dash
  through desert if it has the energy.
- **Per-biome base severity, water harshest.** Water is a much heavier
  penalty than desert (a fish on land >> a rabbit in winter). The base
  severity per biome is a construction/live setting, not hardcoded, so
  the relative harshness is tunable.
- No impassable terrain. Movement penalty only.
- Static for v2.0. Dynamic biome shifts + human-editable map are V2.1+.

### Render & UI

- Renderer engine unchanged in shape (WebGL2 instanced + R8 grass
  texture). Adds a biome texture sampled from `biomeSab` and drawn
  under the grass. Cell-color per biome for v2.0; textured /
  height-shaded V2.1+. The biome texture uploads once at boot.
- **Snapshot carries render-only fields, packed compactly.** The
  6-trait genome lives in `CreatureSoA` sim-side and never rides the
  snapshot — the renderer only needs position, body size (radius),
  display color (single-pool), stable id, the action ring-flash state,
  and (mating mode) the `species_id`. The inspector reads full genome via
  the separate `creature_inspect_json` path, not the SoA. Prefer compact
  binary encodings over per-channel f32s (e.g. single-pool color as one
  u32 RGBA8 lane, ring-flash + `species_id` bit-packed) so the per-tick
  snapshot write and the per-flip interpolation Map rebuild don't pay for
  fields the GPU never reads.
- **Stride does not grow.** Today's creature stride is 8 f32 lanes
  (32 B): `x, y, radius, color_r, color_g, color_b, id_lo, id_hi`. The
  packed v2.0 set — `x, y, radius, color_u32, id_lo, id_hi, packed_u32`
  (ring-flash + `species_id`) — is 7 lanes, padded back to 8 = the **same
  32 B**. So `CREATURE_STRIDE = 8` and the creature SAB region size are
  unchanged; only the **grass region and the new `biomeSab`** are
  settings-derived (they scale with `world_size`). The cross-language
  "computed-dims-equality" assert therefore only needs to cover grass +
  biome, not creatures. The renderer's id/color offsets shift within the
  stride and need a decode update.
- **Species color comes from a polled species→color table, not
  per-creature bytes.** In mating mode the snapshot carries only
  `species_id` per creature; the renderer (and the Monitor chart) read a
  separate **species table** (`species_id → color`, plus name/count)
  requested via the same polled-SAB-report mechanism as the per-species
  pop graph. Build the table to be **dynamic** — species constantly
  added, removed, and changing — so the V2.1 split/merge work needs no
  protocol change. v2.0 just happens to seed a fixed 10.
- Grass upload becomes dirty-rect, with two non-obvious requirements:
  - **Track quantized changes, not raw density.** Logistic growth
    nudges *every* nonempty cell every tick, so a raw-density dirty
    set is ~the whole map and saves nothing. Mark a cell dirty only
    when its **u8-quantized** value changes — at default growth rates
    a cell crosses a u8 boundary only every few ticks, so the dirty
    set stays sparse.
  - **Accumulate across ticks against an upload epoch.** RAF is
    usually slower than the tick rate and the snapshot is
    double-buffered, so many ticks elapse between GPU uploads. The
    renderer must upload the *union* of cells changed since its last
    upload, not one tick's set. Keep a worker-side accumulating dirty
    AABB (or bitset) plus a `grass_dirty_epoch`; the renderer uploads
    the accumulated region, records the epoch it consumed, and the
    worker resets accumulation past that epoch. Simplest correct
    fallback is a full upload — measure whether dirty-rect actually
    wins before keeping the machinery.
  - Renderer issues `texSubImage2D` over the accumulated bounding
    rectangle (or skips entirely if empty). Full-texture upload on
    first frame after boot or worker swap. Mipmap regeneration is
    skipped when the dirty rect is empty.
- Body color: species color (mating mode) or genome-derived hue
  (single-pool). Action-EMA deleted.
- Outer ring: 5-tick transient flash per action — blue/teal/yellow/red/green
  per the legend above. Selection ring (inspector) stays its own color.
- Camera: existing pan/zoom over the larger world. Default zoom
  shows ~1500u. **Lower the min-zoom clamp** (today `0.5`, tuned for
  the 1200u world) so the user can zoom out far enough to survey a
  large/editable world. To keep factions legible at the far end, a
  creature that would render sub-pixel is drawn as a **min-1px point** in
  its display color (skip the disc shading) so species territories stay
  visible from the survey view. No minimap in v2.0 (deferred); zoom-out +
  1px points is the v2.0 survey tool. Wrap-aware frustum cull when
  `wrap_world` is on (a body near
  `x=0` renders again at `x=WORLD_SIZE+δ` when the camera straddles
  the seam). Trails and highlight rings need the same wrap awareness.
- Right-rail Inspector: 6 genome traits, current movement penalty
  scalar; **mating mode** adds species name, species color swatch,
  species-history breadcrumb (empty until splits land in V2.1+).
- Right-rail Monitor (mating mode): stacked or overlaid per-species
  pop lines. Per-species population counts are **aggregated sim-side
  and requested from the wasm layer** via a polled SAB report (same
  shape as the profile / NN-stats reports), *not* shoved into the
  fixed 20-byte snapshot header. Species color is shared with the
  canvas — 10 saturated hues spread across the wheel. In typical runs
  only 1–3 species survive long-term, so color reuse on the chart is
  rarely a problem.
- No event log, no timeline, no major-event ticker.

### NN topology

**Principle.** NN input layout is **derived from construction
settings**. Old brains are discarded on every settings change
(no save/load, so nothing to migrate). SIMD-pad the final width to a
multiple of 8.

**Reality check — this is Wave 0, not a free plug-in.** Today the
input width is a *compile-time* constant: `NN_INPUTS == 32` is
hard-asserted in `src/brain.rs`, `Brain::forward` takes
`&[f32; NN_INPUTS]`, `Brain::founder` seeds `fan_in = NN_INPUTS`, and
`build_nn_input` writes fixed slot indices. v1.12's runtime
`NnTopology` made the *hidden layers* variable but deliberately left
inputs/outputs implicit. Settings-derived input width therefore
requires foundational work (Wave 0): make input width a runtime field
of the topology, convert the fixed `[f32; NN_INPUTS]` arrays to
max-sized slices (mirroring how hidden layers already use
`NN_MAX_HIDDEN_WIDTH`), and rewrite `build_nn_input` as a composable
layout that computes slot offsets from the active settings. A
`MAX_NN_INPUTS = 48` ceiling with a runtime `input_width` used as the
first matmul's `fan_in` is the smallest shape that satisfies the
multiple-of-8 SIMD constraint for every width in the table below — the
widest case (`wrap off`, `species on`) is 43 inputs, which pads to 48.

**Always-on inputs (both modes):**

- 8 self/memory (today's slots — hunger, age_frac, prev_vx/vy, last-action flags, ticks_since_split_norm, cooldown_ready)
- 8 grass-density sectors. **Note:** at the coarse 5u grass grid the
  current `GRASS_PROXIMITY_RANGE = 8u` only spans ~1–2 cells, too few
  to populate 8 directional sectors. Raise `GRASS_PROXIMITY_RANGE`
  (and recompute `LUT_RADIUS`, today hardwired to the 1.25u cell) so
  the sector window covers enough cells to stay directional.
- 4 biome-penalty inputs (N/S/E/W) — "if I walk one cell that way,
  what movement penalty would I pay?" Derived per-creature per-tick
  from the creature's genome (`water_affinity`, `heat_tolerance`)
  applied against the biome map.
- 1 current-cell `movement_penalty` scalar
- 1 curr_grass_density (under the body)
- 1 bias (constant 1.0 — classical NN bias slot, retained)

**Settings-conditional inputs:**

- 4 wall-proximity inputs (N/S/E/W) — only when `wrap_world = false`.
  Dropped entirely when wrapping.
- Creature-proximity sectors — 8 unified sectors in `species_mode = off`;
  16 sectors (8 same-species + 8 other-species) in `species_mode = on`.

**Resulting widths** (pre-SIMD-pad). Always-on block is **23** (8 self +
8 grass + 4 biome-dir + 1 current-cell penalty + 1 curr-grass + 1 bias):

| `wrap_world` | `species_mode` | Always-on | + walls | + creatures | Inputs | Pad to |
|---|---|---|---|---|---|---|
| off | off | 23 | 4 | 8 | 35 | 40 |
| off | on | 23 | 4 | 16 | 43 | 48 |
| on | off | 23 | 0 | 8 | 31 | 32 |
| on | on | 23 | 0 | 16 | 39 | 40 |

Hidden layers: unchanged runtime topology infrastructure (`NnTopology`)
reused as-is.

Outputs: unchanged shape (`vx, vy, 3 action logits`) and unchanged
continuous-velocity encoding, but action[2] semantics differ by mode.

The previous draft's "action-set indicator NN input slot" and
"preserved wall_proximity slots despite no walls" are both gone —
inputs follow settings.

### Reproduction details

**Mating (species mode).** `Mate` is an NN action gated entirely by the
**initiator**: a legal pick only when the initiator is off mating
cooldown **and** has enough energy to pay the cost (an invalid pick falls
through to Graze, like Split today). When `Mate` fires the sim looks for
a same-species creature within a small **contact radius**
(`mating_contact_radius` — essentially touching, on the order of the
summed body radii, *not* the 20u perception range). The first
same-species creature found within contact wins — no nearest-scan
(consistent with the "first-valid, not closest" eat decision; a full
nearest-scan was deliberately removed for perf). **All cost and cooldown
fall on the initiator only:** the initiator pays an energy cost
(proposal: same as `split_gift`) and enters a fixed-tick cooldown
(`mating_cooldown_ticks`, slider-tunable). The partner pays nothing,
needs no energy, and is **not** required to be off cooldown — it's just a
target. This deliberately lowers the bar so a clustered founder group can
actually start reproducing (see the cold-start note). Child spawns at
midpoint, with crossover-then-mutate per the `crossover_mode` setting.
Same-species check is by `species_id` only — no genome-distance gate.
(Watch item, tracked in [`v2-possible-next-steps.md`](v2-possible-next-steps.md):
with no partner cooldown, many initiators can mate one popular partner in
a single tick — add a guard if births spike.)

Because mating needs contact, a species that disperses past contact
range stops reproducing and dies out. That is intended: selection
favors lineages that learn to stay clustered.

**Splitting (single-pool mode).** Identical to today.

### Species seeding (mating mode)

1. Pick `starting_species_count` random spawn anchor points spread
   across the world.
2. For each anchor: assign a `Species` with a saturated color (hue
   spread across the wheel) and label (`Species-A..J` is fine for v2.0).
3. Roll the canonical "first member" genome **biased toward surviving the
   biome under the anchor** — a water anchor seeds high `water_affinity`,
   a desert anchor high `heat_tolerance`, plains anything. The brain is
   still a random founder. This is a deliberate reversal of the earlier
   "random founders, let the world filter them" stance: at gen 0 there is
   no learned behavior to keep a maladapted clump alive long enough to
   evolve, so we pre-adapt founders to where they spawn and let selection
   act on drift from there.
4. Spawn `starting_species_member_count - 1` additional founders nearby.
   Each is the canonical member's genome + brain run through **one normal
   per-birth bucket draw** (same `MutationPolicy` machinery as a child),
   with that bucket's **rate and sigma both multiplied by
   `starting_species_member_variance`**. Higher variance ⇒ more internal
   spread for selection to act on; too high dilutes species identity at
   tick 0, so the default is conservative.

Defaults: 10 species × 10 founders = 100 starting pop. Species extinct =
extinct. No respawn in v2.0. If clustered seeding still extinct-ends
before any learning, the cold-start levers (mate-proximity inputs,
cranking founder counts way up) live in
[`v2-possible-next-steps.md`](v2-possible-next-steps.md).

### Settings exposed at construction time

| Setting | Type | Default | Effect |
|---|---|---|---|
| `world_size` | f32 | 9600 | World edge length. **Construction-only** (grid dims depend on it). |
| `world_seed` | u32 | random | Drives **biome generation only**. Independent of the sim RNG seed (see two-seed note). Same `world_seed` reproduces the same map; the run still plays out differently each time. |
| `wrap_world` | bool | on | Torus vs walled. Off ⇒ wall_proximity NN inputs reappear. |
| `species_mode` | bool | off | Hard mode switch. Off ⇒ `founder_count` slider visible; on ⇒ the species-seeding sliders below visible. |
| `crossover_mode` | enum `{average, fifty_fifty}` | fifty_fifty | Per-trait/per-weight crossover policy (mating mode), applied to **both brain weights and genome traits**. `fifty_fifty` preserves variance (standard GA); `average` (elementwise mean of parents) available for research. See the brain-crossover caveat in decisions + next-steps. |
| `founder_count` | u32 | 32 | Single-pool starting pop. Hidden when `species_mode = on`. |
| `starting_species_count` | u32 | 10 | Number of species (mating mode). Hidden when `species_mode = off`. |
| `starting_species_member_count` | u32 | 10 | Founders per species (mating mode). |
| `starting_species_member_variance` | f32 | 3.0 | Multiplies the **rate and sigma** of the per-founder bucket draw used to spread non-canonical founders off the canonical member. 1.0 = founders drift like a normal child; higher = more spread. Tune down if species identity is diluted at tick 0. |
| `mating_cooldown_ticks` | u32 | 200 | **Initiator-only** post-mating cooldown. |
| `trait_mutation_sigma_multiplier` | f32 | 0.3 | Genome-trait mutation sigma relative to the chosen brain bucket (a rate multiplier is a possible future second knob — see next-steps). |
| `water_movement_penalty` | f32 | (tune) | Base severity of the water biome's movement penalty (harshest). |
| `desert_movement_penalty` | f32 | (tune) | Base severity of the desert biome's movement penalty (milder than water). |

Plains has no movement penalty. The two biome-penalty severities are
live-tunable so the relative harshness (water ≫ desert) can be dialed in.

Live-tunable additions: `mating_cooldown_ticks`,
`trait_mutation_sigma_multiplier`, `water_movement_penalty`,
`desert_movement_penalty`.

UI gating: the dev panel hides/shows the species-seeding sliders vs
`founder_count` based on the current `species_mode` widget value
(staged, not the running sim's mode). Toast on apply if any
construction-only knob changed.

Dropped sliders: `full_grass_on_init` (vestigial under new grass model);
all four `_reserved_curriculum_*` slots (issue 15).

**Settings schema version (localStorage migration).** Add a
`major.minor` version stamp to the persisted settings blob. On load:
a **minor** mismatch (we shipped new keys) merges the missing keys from
defaults and keeps the user's existing values; a **major** mismatch (the
config is structurally incompatible — what v2.0 is) **resets to
defaults**. v2.0 bumps the major version, so every v1 localStorage blob
resets cleanly instead of leaving stale keys behind. Bump minor on any
ordinary settings change going forward.

## Non-goals

- Species splitting, merging, hybrid zones, interbreeding (V2.1+).
- Individual ancestor lineage tree, family-tree UI (only species history).
- Photosynthesis, social/fear/aggression traits, cold tolerance,
  fertility, humidity, vegetation channel.
- Forest, swamp, tundra, mountain biomes (V2.1+).
- Dynamic / human-editable biome map (V2.1+).
- Save/load, world seeds for sharing.
- Minimap, heatmaps, population overlays (V2.1+).
- Event log, evolutionary timeline, major-event detection.
- Bases, nests, crafting, civilization, signaling, territory markers.
- Linear vegetation suppression under high pop (V2.1+ if cap binds in
  practice).
- Cannibalism (eating same-species) — off in species mode, by design.
  Single-pool has no species, so its `Attack`-any predation is the v1
  mechanic unchanged.

## Execution contract (orchestrator autonomy)

v2.0-specific guidance layered on top of the `fresh-orchestrator`
operating manual (which owns the generic
audit→plan→implement→verify→doc-migrate-via-subagents flow — not repeated
here). Purpose: **let the orchestrator run end-to-end without stopping to
ask.**

**Default to action.** Make every implementation decision yourself; do not
pause for confirmation. The only things that legitimately stop you are a
true contradiction in this plan or a guard you cannot get green after
honest effort — and even then, record the blocker, route around it to
other waves, and keep moving rather than idling.

**Decide → log → flag.** For every non-obvious choice:
- **Decide** with a sane default — favor the simplest thing that satisfies
  the decision/verification text already in this doc.
- **Log** it in the Decision log at the bottom of this file (one line:
  what · why · file/anchor).
- **Flag** it in the "⚠️ Review" subsection *only if both* (a) a
  reasonable person might prefer otherwise **and** (b) it affects feel /
  gameplay / visual identity / the headline experience. Behavior-invisible
  choices (data structures, slot ordering, algorithm internals) are
  logged, never flagged — don't spend the user's attention on them.

**The open numbers — choose, don't ask.** Pick and log defaults for all of
these, using the constraints already written here ("few large blobs,"
"water ≫ desert," "survivable short-term," etc.): biome generator
algorithm + biome proportions; the biome-driven grass seeding rule;
`GRASS_PROXIMITY_RANGE` + recomputed `LUT_RADIUS`; the two biome
movement-penalty severities; the 6 trait rescale ranges; the
biome→founder-genome mapping and the `diet` formula. Flag the
feel-affecting ones (proportions, penalty severities, trait ranges,
colors); log the rest.

**Balance (Wave 4) is the user's, not yours.** Implement every mechanism
and ship *reasonable* starting defaults so the sim runs and the objective
end-state checks pass (cap doesn't bind via random cull; 1–3 species can
survive a 10-min run; founders cluster). Do **not** spend cycles
hand-tuning for "fun" — the user does final balance. List every balance
knob you touched, with its default, in the ⚠️ Review subsection.

**If the mating cold-start fires** (species extinct-end before any
learning), don't stop: apply the cheapest cold-start lever from
[`v2-possible-next-steps.md`](v2-possible-next-steps.md) (first crank

## Known load-bearing risks

1. **Runtime NN input width (Wave 0) is foundational, not free.**
   Input width is compile-time today (`NN_INPUTS == 32` is
   hard-asserted; fixed `[f32; NN_INPUTS]` arrays; hardcoded
   `build_nn_input`). Every later wave that adds inputs depends on this
   landing first.
2. Toroidal wrap touches the widest code surface of any v2.0 change
   (movement, spatial hash, proximity sectors, renderer cull, trails,
   highlight). Wave 1 single-pool ships it exercised at scale before
   species code lands.
3. **Per-tick whole-grid work grows ~4× at 1920²** (grass propagation,
   row-bitset rebuild, `HASH_DIM²` spatial-grid rebuild). The grass *GPU
   upload* is also larger — but only 4×, not 64×, so measure full upload
   before building dirty-rect machinery. If dirty-rect is needed, track
   *quantized* changes and use a tile/bitset sub-upload, not a single
   accumulated AABB. Trust the profiler to say where the time actually
   goes (see next-steps for the deferred optimization pass).
4. **Runtime `world_size` makes grass + biome SAB sizing
   settings-derived.** The creature region is unchanged (stride stays
   32 B), but grass grid dims (and thus the grass region + the new
   `biomeSab`) come from `world_size` at boot; the cross-language safety
   model for those moves from constant-equality asserts to
   computed-dims-equality asserts. Get this wrong and typed-array views
   go out of bounds.
5. **Sexual reproduction is a far more fragile bootstrap than asexual
   Split, and naive brain-weight crossover may make brains unevolvable.**
   Mating needs a clustered, same-species partner within contact range
   from random founder brains; the v2.0 de-risking (adjacent +
   biome-adapted founders, initiator-only cost, scalable founder counts)
   may still not be enough. Separately, per-weight / `average` crossover of
   two trained nets is a known neuroevolution failure mode — we ship both
   modes anyway (it's narrative, not optimization) and keep them safe by
   staying in the **aligned regime**: same-species-only mating + small
   per-birth brain mutation + frequent within-species mating, so crossover
   is just allele-shuffling rather than basin-mixing. Module schemes and
   prototype-pull were explored and rejected. The full reasoning, the
   "what makes them smart" levers (environment, population, recurrence ≫
   crossover), and the deferred bets live in
   [`v2-possible-next-steps.md`](v2-possible-next-steps.md).
6. Directional biome-penalty inputs (4 cardinal directions) assume
   creatures can anticipate terrain from short-range cardinal samples.
   If anticipation is too weak, V2.1 can add 8-direction biome
   sectors or a per-sector penalty multiplier on the existing grass
   sectors.
7. Cannibalism off is a rule, not an evolved behavior. The bet is
   that with deeper future networks we can relax this; for now it's a
   guardrail.
