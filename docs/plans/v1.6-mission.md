# Mission: Sim-Render Decoupling (v1.6)

## Goal

Run the simulation in a dedicated Web Worker so the main browser thread does
nothing but render. Decouples sim TPS from render FPS — frame rate becomes
solely a function of how long render takes, and sim throughput becomes solely
a function of how long a tick takes. Today they fight each other inside one
RAF callback; after v1.6 they're independent.

## Why now

- `tick.nn` already scales with rayon workers. The remaining single-threaded
  bottleneck is "main thread blocked inside `step_n` while render waits."
- At pop > 1500 the sim no longer fits in a frame budget. Browser drops frames;
  the UI feels janky even though wasm is healthy.
- We have working SharedArrayBuffer infrastructure (rayon-threads build
  already requires it). Shipping cost is the orchestration code, not the
  shared-memory plumbing.
- After v1.5's per-sub-phase + per-worker instrumentation, we can actually
  measure whether v1.6 delivered.

## High-level architecture

```
┌─────────────────────────────────────────────────────────────┐
│  MAIN BROWSER THREAD                                        │
│                                                             │
│  RAF loop:                                                  │
│    snapshot = readSAB()       ← lock-free, atomic flip      │
│    render(snapshot)           ← WebGL draws                 │
│                                                             │
│  UI events (sliders, clicks):                               │
│    postMessage → sim worker                                 │
└──────┬──────────────────────────────────────────────────────┘
       │ SAB (zero-copy reads — render snapshot, double-buffered)
       │ ↑ ↓
       │ postMessage (slider/inspector commands)
┌──────▼──────────────────────────────────────────────────────┐
│  SIM WORKER                                                 │
│                                                             │
│  loop {                                                     │
│    tick_start = now()                                       │
│    world.step_n(1)            ← wasm: NN + physics + grass  │
│    writeSnapshot(SAB)         ← memcpy ~12µs, atomic flip   │
│    budget = 1000 / targetTPS                                │
│    elapsed = now() - tick_start                             │
│    sleep(max(0, budget - elapsed))                          │
│  }                                                          │
│                                                             │
│  spawns rayon child workers for parallel NN/grass.          │
└─────────────────────────────────────────────────────────────┘
```

**Render snapshot** = two SABs, double-buffered with a `current_idx`
`AtomicU32`. Sim writes the off-side slot, then atomic-flips. Main thread
always reads the live slot. Zero locks; worst case render sees state from one
tick ago (imperceptible at 60 TPS).

## What lives in the SAB

| Buffer | Size at pop=2000 | Updated by sim worker |
|---|---|---|
| Grass density (R8) | 230 KB | Once per tick |
| Creature SoA (x, y, r, g, b, body_radius) | ~48 KB | Once per tick |
| Highlight ring buffer | <1 KB | Once per tick |
| Per-tick stats (tick, pop, TPS) | <100 B | Once per tick |

Total snapshot write: ~280 KB. memcpy throughput ≈ 20–30 GB/s → **~10–14 µs
per tick**. Below the noise floor of a typical 5–30 ms tick.

## What does NOT change

- Wasm crate code stays as-is. `WorldHandle` keeps its current API — we just
  call it from a worker instead of the main thread.
- Rayon parallel NN / grass still works. Web Workers can spawn child workers;
  `initThreadPool` runs inside the sim worker, not the main thread.
- Profiler architecture stays. We add a "frame" tree (TS-side, on main) and a
  "tick" tree (Rust-side, in worker). Already separate today.
- COOP/COEP headers, threaded wasm bundle — no build changes.

## What does change

- `web/src/main.ts` shrinks to the render loop + UI plumbing.
- New `web/src/sim-worker.ts` holds the wasm and the tick loop.
- New `web/src/sim-bridge.ts` defines the message protocol + SAB layout.
- All `world.set_*` slider setters become postMessage'd commands.
- Inspector click becomes async — request goes to worker, response comes back
  with the creature snapshot to display.
- Restart flow: terminate worker, spawn new one, await init, hand back the
  SAB pointers.

## Non-goals (v1.7+)

- **GPU-side grass propagation.** Separate problem; orthogonal win.
- **Sim hot-swap / save-load.** Add later if needed; the worker abstraction
  makes it strictly easier, not harder.
- **Inspector subscription streaming.** First version uses request/response.
  If polling rate ends up high, upgrade to a push channel.
- **Multi-world / parallel sims.** Not enabled by this change; not blocked
  either.

## Implementation order (3 stages)

### Stage 1 — Sim worker with postMessage snapshots

Move wasm + tick loop into `web/src/sim-worker.ts`. Each tick, postMessage a
`{ tick, pop, grass, creatures }` payload to main. Main thread renders from
the latest payload.

**Slow** (postMessage clones the payload — ~280 KB/tick is too much), but
proves the architecture: sim runs independent, render runs independent,
restart flow works, slider commands route correctly.

Acceptance: sim worker keeps running at target TPS while main thread renders
at full FPS. `tick.nn` shows the same numbers as before. UI sliders still
update sim state.

### Stage 2 — SharedArrayBuffer-backed snapshots

Replace postMessage payloads with SAB writes. Layout defined in
`sim-bridge.ts`. Atomic flip via `Atomics.store` on a u32 index. Main thread
constructs typed-array views over the live slot each frame.

Acceptance: `grass.upload.read` (the wasm→JS copy) disappears from the
profiler — replaced by a SAB→typed-array view construction (effectively
free). Sim throughput unchanged or slightly better (no postMessage
serialization cost).

### Stage 3 — Async inspector + slider polish

- Inspector click sends `{ kind: "creature_at", wx, wy }`; worker responds
  with the full inspector schema asynchronously. Render keeps drawing while
  the request is in flight; if no response within one frame, UI shows
  "selecting…".
- Slider drag becomes a debounced stream of commands. Worker batches
  consecutive setters before applying to avoid mid-tick slider thrashing.

Acceptance: clicks and drags feel ≤1 frame of latency. No visible UI hitches
when scrubbing a slider.

## Risks + mitigations

| Risk | Mitigation |
|---|---|
| Rayon's `initThreadPool` doesn't work from a Web Worker (untested) | Stage 1 verifies this on day one. Fallback: sim worker runs single-threaded; rayon stays disabled inside the worker. Sim is still decoupled from render, just not parallel. |
| SAB visibility across workers | wasm bundle already has `shared:true` and the dev server already sends COOP/COEP. Confirm `__world.isCrossOriginIsolated()` is true post-load. |
| Restart flow drops state | Terminate worker, spawn new one, re-init wasm + threadpool, then hand SAB pointers back to main. Brief (~100ms) blip where render shows the last-good snapshot. Acceptable. |
| Inspector latency | Stage 3 adds a fast-path where the live snapshot already contains a per-creature `id` array; "click" maps to nearest id locally, then async-requests the full inspector schema. First paint is instant. |
| Debugging pain | Errors land in a separate DevTools console panel ("Sim Worker"). Document this in `docs/dev-server-prompt.md`. |

## Success criteria

1. Render maintains ≥55 FPS while sim runs at any TPS (including TPS so high
   the sim worker is constantly busy).
2. Sliding the `target TPS` slider does not affect frame rate — only sim
   throughput.
3. The "wasm bundle is non-threaded" footgun (caught in v1.5) cannot regress
   without a visible warning — sim worker logs `[sim] rayon workers: N` at
   startup just like main thread does today.
4. Inspector click → panel update visible in ≤2 frames at the default TPS.

## Budget

**Realistic: 1–2 focused days.**
- Stage 1: ~half day (mostly Vite worker bundling + message protocol).
- Stage 2: ~half day (SAB layout + atomic flip + view construction).
- Stage 3: ~half day (inspector + slider polish).

If something hits an unforeseen rayon-in-worker bug, add a day for
investigation. The fallback (single-threaded sim worker) is still a strict
win over today's main-thread setup.
