# Mission: v1.10 — All-SAB control, tight worker loop

## Goal

Eliminate `postMessage` from the worker's hot path. All main → worker
control (sliders, pause, target TPS, inspector requests, profiler
reset) moves to SharedArrayBuffer-backed state read by the worker at
the top of each tick. All worker → main responses (profile report,
inspector reply) move to SAB buffers polled by main. The sim worker's
main loop becomes a tight synchronous `while (true)` with no `await`,
no `setTimeout`, no `Atomics.waitAsync` while running. The only
remaining postMessage paths are boot handshake and worker termination
(both already external to the steady-state loop). Net effect: the
event-loop-yield tax that capped real TPS below target evaporates.

## Scope

- New SAB layout for a "control" region carrying paused, target_tps,
  every slider value, an epoch counter, an inspector request slot, an
  inspector response slot, a profile-report buffer, and a
  profile-clear epoch.
- Worker steady-state loop rewritten to read control SAB once per tick
  (snapshot it into locals — preserves the "slider at T applies at
  T+1" determinism rule from
  [`../architecture/simulation-core.md`](../architecture/simulation-core.md)).
- Paused state uses synchronous `Atomics.wait` on a futex word (now
  legal — no postMessage to dark-hole) so a paused worker burns zero
  CPU.
- Slider widgets, the pause toggle, the target-TPS dropdown, and the
  inspector click handler in `web/src/main.ts` and the right-rail
  widgets all write SAB directly instead of `bridge.postMessage`.
- `SimBridge` collapses: the `MainToWorkerMessage` discriminated union
  and the worker's `messageQueue` / `onmessage` control branches go
  away. Only the boot-time handshake message survives.
- `WorldHandle` wasm-bindgen surface is **unchanged**. `set_slider`,
  `creature_inspect_json`, `profile_clear`, etc. still exist; only
  their call sites move (worker reads SAB → calls the existing
  wasm-bindgen entry).
- Restart stays as `worker.terminate() + new Worker(...)`. It is
  external to the worker loop and compatible with a tight loop —
  no SAB-ification needed.
- E2E suite updated: every Playwright test that exercises slider /
  pause / inspector / profile-clear flows now drives them via the new
  SAB writers exposed through window helpers (or via the actual UI).
- New `sim_worker` top-level profiler tree:
  `sim_worker.read_input_sab`, `sim_worker.tick`,
  `sim_worker.write_output_sab`. Three RAII spans bracketing the three
  steady-state phases of one loop iteration. Lives alongside the
  existing four trees in the perf panel.
- Profiler rename: `nn.proximity` → `nn.build_input.proximity`,
  `nn.proximity.creatures` → `nn.build_input.proximity.creatures`,
  `nn.proximity.grass` → `nn.build_input.proximity.grass`. Reflects
  the actual call structure (`build_nn_input` invokes the proximity
  scans). Cosmetic only — no measurement changes.

## Non-goals

- Restart-via-SAB. Keep `worker.terminate()`.
- Removing the wasm-bindgen `WorldHandle` API. SAB is a transport
  layer above it.
- Changing the snapshot SAB layout. Snapshot writing and reading is
  unchanged.
- Changing tick semantics, determinism rules, or sim core behavior in
  any way.
- Phased rollout. One PR. Manual testing + e2e is enough.

## Plan

1. **Control SAB layout.** Decide field offsets and write the layout
   into [`shared-memory-and-protocol.md`](../architecture/shared-memory-and-protocol.md).
   Rough shape (refine in implementation):

   ```
   ctrl SAB (~32 KB):
     CTRL_CURRENT_SLOT     u32   (existing)
     CTRL_SEQ              u32   (existing)
     CTRL_FUTEX            u32   (existing — drives paused park)
     CTRL_PAUSED           u32   (atomic bool, 0|1)
     CTRL_TARGET_TPS       u32   (f32-bits)
     CTRL_CONTROL_EPOCH    u32   (bumped on any slider write)
     CTRL_PROFILE_CLEAR_EP u32   (bumped to request profile_clear)
     CTRL_SLIDERS          f32[N] (one slot per slider, dense by ID)
     CTRL_INSPECT_REQ_EP   u32
     CTRL_INSPECT_REQ      { wx: f32, wy: f32, tol: f32 }
     CTRL_INSPECT_RESP_EP  u32
     CTRL_INSPECT_RESP     { idx: u32, json_len: u32, json: [u8; 8192] }
     CTRL_PROFILE_REPORT   { len: u32, bytes: [u8; ~16 KB] }
   ```

   All numeric reads/writes via `Atomics.load`/`Atomics.store` on an
   `Int32Array` view (f32 carried as `f32::to_bits` per the
   snapshot-header precedent).

2. **Slider ID table.** Build a single shared list mapping
   `slider_name → ctrl_sliders_index` consumed by both sides.
   `DevSliders` already enumerates all sliders; add a stable
   ordering + a TS mirror generated or hand-kept in sync.

3. **Worker loop rewrite.** Replace the current `async simLoop` with:

   ```ts
   while (true) {
     {
       const _s = span("sim_worker.read_input_sab");
       readControlSab();   // pause, target TPS, sliders if epoch bumped,
                           // inspect request if epoch bumped,
                           // profile-clear if epoch bumped
     }
     if (paused) {
       Atomics.wait(ctrl, CTRL_FUTEX, ...);
       continue;
     }
     {
       const _s = span("sim_worker.tick");
       world.step_n(1);
     }
     {
       const _s = span("sim_worker.write_output_sab");
       writeSnapshotToSAB();
       maybeWriteInspectResponse();
       maybeWriteProfileReport();   // ~1 Hz via tick counter, not setInterval
       enforceTargetTps();          // busy spin? small Atomics.wait? see step 6
     }
   }
   ```

   No `async`. No `await`. No `setTimeout`. No `Atomics.waitAsync`
   in the running case. The three spans become the `sim_worker`
   profiler tree.

4. **Target-TPS pacing without yielding.** Two viable options to
   discuss/decide at implementation time:

   - **Spin-wait:** busy loop on `performance.now()` until the slice
     elapses. Wastes CPU at low target TPS but simple, and the
     worker has no other work to do.
   - **Sync `Atomics.wait` with finite timeout:** legal now because
     no postMessage path needs to dispatch. Parks the thread for the
     remaining slice; wakes early via `Atomics.notify` on slider
     writes that bump the futex.

   Lean toward `Atomics.wait(..., remainingMs)`. It's a real OS-level
   park, not a spin.

5. **Main-side writers.** `SimBridge` exposes:

   ```ts
   simBridge.setSlider(name: string, value: number): void
   simBridge.setPaused(p: boolean): void
   simBridge.setTargetTps(t: number): void
   simBridge.requestInspect(wx, wy, tol): Promise<InspectResult>
   simBridge.requestProfileReport(): Promise<ProfileReport>
   simBridge.clearProfile(): void
   ```

   All implemented as SAB writes + epoch bumps. `requestInspect` /
   `requestProfileReport` return a Promise that resolves when the
   response epoch advances (polled from RAF or a 60 Hz `setInterval`
   on main). Boot-time handshake remains postMessage-based.

6. **Profile-report cadence.** Replace the worker's current 1 Hz
   `setInterval` (if any) with a tick-counter check inside the loop:
   "every N ticks, serialize the profile JSON into
   `CTRL_PROFILE_REPORT` and bump the epoch." Main reads at its own
   pace. No timer-based callback in the worker.

7. **Inspector flow.** Main writes `{wx, wy, tol}` + bumps
   `CTRL_INSPECT_REQ_EP`. Worker, at top of next tick, sees the
   epoch bump, calls `creature_at(wx, wy, tol)` →
   `creature_inspect_json(idx)`, writes the JSON into the response
   buffer (length-prefixed), bumps `CTRL_INSPECT_RESP_EP`. Main
   polls `CTRL_INSPECT_RESP_EP` from RAF; on advance, reads the
   buffer and resolves the Promise.

8. **Profiler-tree changes.**
   - Add the three `sim_worker.*` RAII spans in the worker loop body.
   - Add `sim_worker` to the perf panel's `TREE_ORDER`.
   - Rename `nn.proximity*` → `nn.build_input.proximity*` in
     [`src/world/nn.rs`](../../src/world/nn.rs) `record_under_root`
     call sites. Update [`profiler.md`](../architecture/profiler.md)
     tree diagram.

9. **E2E updates.** Audit `web/e2e/` for postMessage assumptions.
   Replace `bridge.postMessage(...)` test helpers with the new
   `simBridge.*` writers. The "Atomics.waitAsync(0)" regression
   guard listed in [`../agent-context/dev-loop.md`](../agent-context/dev-loop.md)
   becomes obsolete and gets removed.

10. **Docs.**
    - [`shared-memory-and-protocol.md`](../architecture/shared-memory-and-protocol.md):
      rewritten control-SAB section, including the slider table.
    - [`worker-runtime.md`](../architecture/worker-runtime.md):
      delete the "forbidden `Atomics.wait`" rule, replace with
      "tight synchronous loop, sync `Atomics.wait` legal because no
      postMessage hot path."
    - [`simulation-core.md`](../architecture/simulation-core.md):
      `set_slider` entry-point note stays accurate (still the wasm
      API); add a note that it's called from the worker after SAB
      read, not from a message handler.
    - [`profiler.md`](../architecture/profiler.md): five-tree
      diagram (`frame`, `tick`, `sim_worker`, `nn`, `grass_step`)
      with the renamed `nn.build_input.proximity*` rows.
    - New [`../decisions/transport.md`](../decisions/transport.md)
      (or section in cross-cutting): the "all-SAB" decision, why
      restart is exempt, why this replaces the
      `Atomics.waitAsync`-based pacing.

## Locked decisions (2026-05-29)

- **Pacing**: synchronous `Atomics.wait` only when the tick finishes
  *under* the target slice (we have slack — park for the remainder).
  When the tick already ran *over* the slice (no slack), we do NOT
  yield: next iteration runs immediately. This honors the user's
  rule "only hand control back to JS when we are over our TPS, never
  when we are under." There is no postMessage hot path to dispatch,
  so the under-budget no-yield case is safe.
- **Restart**: keep `worker.terminate() + new Worker(...)`. External
  to the loop; compatible with a tight-loop worker; no in-loop
  tear-down logic.
- **Slider table**: code-generated. A Rust binary (e.g.
  `cargo run --bin gen-bindings`) emits
  `web/src/generated/slider-ids.ts` from the canonical Rust list.
  The generated file is committed to git, marked
  `// @generated — do not edit by hand`, and a Rust unit test
  verifies the on-disk TS matches what the generator would produce
  (CI fails on drift; dev re-runs the binary to update).
- **Buffer sizes**: 16 KB for `CTRL_PROFILE_REPORT`, 8 KB for
  `CTRL_INSPECT_RESP`. Both length-prefixed inside a fixed slot.

### Landed in session 2 (2026-05-29)

- **Control SAB upsized** from 16 bytes to `CONTROL_SAB_BYTES` (≈30 KB)
  per the layout in [`src/control_sab.rs`](../../src/control_sab.rs).
  Worker boot in [`web/src/sim-worker.ts`](../../web/src/sim-worker.ts)
  allocates the new size and seeds initial slider / paused / target-TPS
  values into it before posting `boot_ready`.
- **`SimMessage` collapsed to `boot` only**.
  [`web/src/sim-bridge.ts`](../../web/src/sim-bridge.ts) was rewritten:
  every former `postMessage` payload (`set_slider`, `set_paused`,
  `set_target_tps`, `inspect_at`, `inspect_id`, `request_nn_stats`,
  `request_profile_report`, `profile_enable`, `reset_jank`,
  `reset_profile`) is now an `Atomics.store` + epoch bump on the
  control SAB. The boot handshake is the only surviving postMessage.
- **`SimBridge` runtime kept the same method surface** so all existing
  call sites in [`main.ts`](../../web/src/main.ts),
  [`widgets/perf-panel.ts`](../../web/src/widgets/perf-panel.ts),
  [`widgets/worker-stats.ts`](../../web/src/widgets/worker-stats.ts),
  [`rail/inspector.ts`](../../web/src/rail/inspector.ts), and
  [`widgets/devpanel.ts`](../../web/src/widgets/devpanel.ts) only
  needed minor renames (`postMessage({kind:"set_paused"})` →
  `setPaused(...)`, etc).
- **Worker `simLoop` is now a tight synchronous `while (true)`** with
  no `await`, no `setTimeout`, no `Atomics.waitAsync`. Pacing uses
  synchronous `Atomics.wait` on the futex word with a finite timeout
  (or `Infinity` when paused). The previous "forbidden Atomics.wait"
  invariant in [`worker-runtime.md`](../architecture/worker-runtime.md)
  is now stale and must be rewritten (see Doc updates).
- **`sim_worker` top-level profiler tree** added. Three spans per loop
  iteration — `sim_worker.read_input_sab`, `sim_worker.tick`,
  `sim_worker.write_output_sab` — are measured worker-side via
  `performance.now()` and published into the always-on Rust profile
  tree via the new `WorldHandle::record_profile_sample(root, path,
  dur_us, call_count)` wasm-bindgen export. This is the
  general-purpose escape hatch for the next worker-TS span that wants
  to reach the perf panel (the in-worker TS perf module is still a
  separate instance from main's).
- **`TREE_ORDER` extended** to `[frame, sim_worker, tick, snapshot, nn,
  grass_step]` in
  [`web/src/widgets/perf-panel.ts`](../../web/src/widgets/perf-panel.ts).
- **TextDecoder + SAB compatibility**: discovered during testing that
  `TextDecoder.decode()` rejects views into `SharedArrayBuffer`. The
  bridge copies length-prefixed bytes into a fresh `Uint8Array` before
  decoding ([`sim-bridge.ts decodeBytes`](../../web/src/sim-bridge.ts)).
- **Two new e2e specs**:
  - [`tests/e2e/sab-control.spec.ts`](../../web/tests/e2e/sab-control.spec.ts)
    — 4 tests covering: `sim_worker` tree population, `snapshot` tree
    rendering, `nn.build_input.proximity` nesting, inspector
    request/response round-trip through SAB.
  - The existing [`tests/e2e/sim-bridge.spec.ts`](../../web/tests/e2e/sim-bridge.spec.ts)
    (pause / TPS / slider / profile / restart) continues to pass against
    the new transport without changes — proves backward UX compatibility.
- **All gates green**: `cargo test --lib` (122 passed) +
  `cargo clippy --all-targets -- -D warnings` (clean) +
  `pnpm typecheck` (clean) + `pnpm test:e2e` (10/10 passed).
