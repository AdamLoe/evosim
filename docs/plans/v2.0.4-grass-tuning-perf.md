# Mission: v2.0.4 — grass LOD config + per-cell scatter perf + fertility spread

## Goal

Three near-term, mostly-independent wins on top of the shipped v2.0.2 scatter +
v2.0.3 LOD pyramid:

1. **Make LOD configurable** so full-res holds for the world sizes the user
   actually runs (the hard-coded `2048` budget downsamples "a layer too early"
   for worlds past ~2048 cells/axis).
2. **Cut the per-cell scatter cost** with safe micro-opts + the geometric-skip
   sampler — the only speedups that survive a fully-dense map.
3. **Density-weighted ("fertility") spread** so denser cells spread harder →
   tighter clumps → lets the decay filter be cranked without global collapse.

Larger-scale perf directions (cadence/visibility throttling, event-sampling,
far NN sensing) are **explicitly deferred** to
[`perf-optimization-ideas.md`](perf-optimization-ideas.md).

## Baseline (measured this machine, native single-threaded, 512²=262k cells, 6.25% fill)

| kernel | full-tick | per-cell |
|---|---|---|
| scatter | ~0.90 ms | ~3.4 ns/cell |
| blur | ~38 ms | ~145 ns/cell |

~42× scatter-over-blur. Per-cell is already near the plan's "5–10 ns/cell
parallelized" floor → **there is no hidden 10× in the per-cell path**; this
wave targets a realistic ~2–4× on per-cell, and the LOD/mechanic wins. The
threaded-only costs (instrumentation false-sharing, parallel-atomic contention)
are invisible to the native bench (`threads` feature is wasm-only) and need the
attribution bench's native-rayon shim to see.

## Scope

### A. LOD configuration (render)

- **`GRASS_LOD_BUDGET_AXIS` → a config value, not a constant.** Today hard-coded
  twice and must stay in sync: [`wasm_api.rs:181`](../../src/wasm_api.rs#L181)
  and [`sim-bridge.ts:137`](../../web/src/sim-bridge.ts#L137). It is BOTH the
  LOD switch threshold (`level = floor(log2(span/budget))`,
  [`wasm_api.rs:661`](../../src/wasm_api.rs#L661)) AND the window/texture clamp
  ceiling, so raising it pushes downsampling later AND lets a bigger window
  upload before clamping. It sizes the snapshot slot → **restart-scoped**
  (or a slot realloc). **Resolved: default 4096** (full-res to ~16.7M blocks;
  costs 4× slot grass bytes ≈ 16 MB + 4× upload vs 2048). Both the Rust and TS
  constants move to 4096 from one synced source.
- **`lod_bias`** — subtract from the computed mip level (finer detail). Couples
  with budget: biasing finer than the budget can hold makes the window clamp and
  **crop the viewport edges**, so it is a "nudge within budget," not independent.
- **Aspect-ratio fix (bug):** `vis_cells_y = vis_cells_x`
  ([`wasm_api.rs:676`](../../src/wasm_api.rs#L676)) ignores viewport aspect →
  mis-sized vertical window on non-square viewports. Derive `vis_cells_y` from
  `viewport_h` independently. (Stage-3 review minor #4.)

### B. `grass_size` slider (sim) — heavy knob

- **Why it's in scope:** `grass_dim = round(world_size / GRASS_CELL_SIZE)`, so a
  bigger cell is the **bluntest perf lever there is** — fewer cells = directly
  less `grass_step` work (cell count scales `1/size²`). It's the principled form
  of the user's "maybe we just need less grass" escape hatch, and it pairs with
  the LOD/scale theme of section A (resolution ↔ area trade). User-requested.
- `GRASS_CELL_SIZE` ([`constants.rs:195`](../../src/constants.rs#L195)) currently
  const 5.0. Exposing it resizes `grass_dim`, `grass_cell_count`, `capacity[]`,
  the biome grid, AND the snapshot slot — i.e. a full world rebuild. Behaves like
  `world_size`: **restart/apply-scoped, not a live drag.** Confirm it flows
  through `WorldDims::from_world_size` and the slot-layout computation.

### C. Per-cell scatter perf (sim)

- **C0 — attribution bench FIRST.** New criterion bench with toggled variants
  {alloc on/off, fused-RNG on/off, geometric-skip on/off, instrumentation
  on/off} over BOTH a ~6.25% frontier and a ~90% dense grid. Add a small
  native-rayon shim so the threaded-only costs are measurable. Gate the kernel
  edits on the breakdown.
  - **Fallback if C0 says RNG is NOT the cost.** C1 (alloc) and C2
    (instrumentation) are worth landing regardless — they're cheap and the
    baseline already implicates allocator pressure + false-sharing. But C3/C4/C5
    only pay if RNG dominates. If C0 says the cost is the RMW atomics or the
    freeze instead, then **the RNG restructuring (C3/C4/C5) is dropped** and the
    relevant levers become interior-non-atomic writes
    ([`perf-optimization-ideas.md`](perf-optimization-ideas.md) #5) and/or a
    freeze-reducing grassy-cell list — and the wave collapses to **A + C1 + C2 +
    D + E**. Decide this from the breakdown, not up front.
- **C1 — drop the per-tile heap alloc.** [`grass.rs:1655`](../../src/grass.rs#L1655)
  `Vec::with_capacity(tw*th)` per tile per tick → stack `[u8; GRASS_TILE_SIZE²]`
  or a reused per-worker scratch.
- **C2 — gate profiling out of the hot loop.** Per-tile `clock_now_us_threadsafe()`
  + `fetch_add` onto shared counters ([`grass.rs:1643`](../../src/grass.rs#L1643),
  [1765](../../src/grass.rs#L1765), [1777](../../src/grass.rs#L1777)) cause
  cross-core false-sharing under rayon. Gate behind `if profile_on`.
- **C3 — fuse RNG draws.** A grassy cell does up to 4 full `grass_hash_u64`
  ([`rng.rs:32`](../../src/rng.rs#L32)) calls (salts 1/2/3/4). Compute one (or two)
  hashes and bit-slice decay/gate/band/pick. Keep the property "grass never
  perturbs `SimRng`."
- **C4 — geometric-skip sampler (the algorithmic per-cell win).**
  Per-tile walk a source-cell list, drawing `gap ~ Geometric(p)`
  (`gap = floor(ln(U)/ln(1-p))`), jump `gap` cells, act, repeat. This is
  **distribution-exact**, not an approximation. Turns `N·hash` into
  `(N·p)·(hash+act)` — the win scales ~`1/p`. Keep it per-tile so rayon
  parallelism survives; per-tile RNG stream keyed `(world_seed, tile, tick)`,
  never `SimRng`. Position-addressability is lost, which is consistent with the
  already-accepted non-reproducible field.
  - **NOTE — skip is only worth it with C5's rare-event tuning.** Lowering
    `spread_pct` in the *current* per-cell-roll kernel barely helps (the gate
    hash still runs per cell; only the band/pick + RMW are skipped). The big win
    requires C4 + C5 *together*.
  - **Residual O(N) floor on dense maps = freeze + decay, NOT "finding
    sources".** Geometric-skip is distribution-exact for the *spread gate only*.
    Two things stay O(tile) regardless: the **freeze loop** (step 1 reads every
    cell unconditionally into `src`, [`grass.rs:1656`](../../src/grass.rs#L1656))
    and the **decay roll** (salt 1, per grassy cell,
    [`grass.rs:1682`](../../src/grass.rs#L1682)). So on a ~90%-grassy map skip
    removes the spread gate but freeze + decay remain the floor.
  - **Costing the two approaches:** (i) the compact grassy-cell list reaches
    *true* O(events) but must restructure **freeze and decay around the list too**
    (snapshot source values into the list at build time; geometric-skip the decay
    roll over the same list) — bigger than "add a list," it's the event-sampling
    idea ([`perf-optimization-ideas.md`](perf-optimization-ideas.md) #3, ~16 MB
    at 4M); (ii) the cheaper variant ships skip as a spread-gate RNG reducer over
    the existing freeze and accepts the freeze+decay O(N) floor.
  - **Resolved: implementer's choice — the acceptance bar is the perf result, not
    the approach.** Pick whichever hits the C0-derived per-cell target; if (ii)
    reaches it, don't build (i). The stream owner decides from the C0 breakdown
    and reports which it chose + the measured speedup in the closeout.

- **C5 — rare-event spread tuning (the lever that makes C4 pay off).** Drop
  `spread_pct` (e.g. 0.55 → 0.05 or 0.01) and raise `spread_amount` to hold the
  net growth rate (`p × amount`) roughly constant. The win on the spread portion
  scales ~`1/p` (≈20× at 0.05, ≈100× at 0.01). Keep decay rare too so it doesn't
  become the floor. Pair with D (fertility) so `p` stays constant (skip-valid)
  and rare-but-big events still read smooth, not poppy. This is a tuning +
  feel-tune item, gated on C4 landing.

### D. Fertility (density-weighted) spread + clumping (sim, mechanic)

- **Spread amount ∝ source density** (variant A): `add = spread_amount * (s/cap)`
  (or `s/255`). Keeps `p` constant → **geometric-skip-compatible**. Denser
  cells push harder → self-reinforcing patch centers → tighter clumps. (Variant
  B — probability ∝ density — makes `p` per-cell and forces rejection sampling
  on top of the walk; rejected unless A proves insufficient.)
- **Clumping → decay headroom.** With amount∝density and ring1-dominant spread
  (already [`GRASS_SPREAD_RING1_PCT_DEFAULT=0.70`](../../src/constants.rs#L285)),
  patches refill their own centers, so `decay_pct` can be raised for more visible
  living-noise without a global monotonic collapse. Re-verify the persistence
  invariant (plains super-critical, water sub-critical shoreline).

### E. Far-grass NN sight — multi-band mip sensing (sim, perception)

Today grass sensing is a **single** local band: 8 sectors at fixed radius
`GRASS_PROXIMITY_RANGE = 20` units ≈ 4 cells
([`proximity.rs`](../../src/world/proximity.rs),
[`constants.rs:123`](../../src/constants.rs#L123)) — creatures cannot perceive
grass beyond ~4 cells. This is the dropped v2.0.3 "Consumer 3 / stage 2e",
now pulled in.

- **Sample the LOD pyramid for near/med/far density per sector.** Pick the mip
  level whose texel ≈ each band's radius and read it via
  `GrassPyramid::sample_clamped` ([`grass.rs:551`](../../src/grass.rs#L551)) —
  **O(1) per tap** regardless of cells-under-creature. Choose band count +
  radii (e.g. near ≈ current 20u, med, far) and directions per band.
- **New `NnInputLayout` variant** ([`nn.rs:543`](../../src/world/nn.rs#L543)) that
  appends the extra grass-band sectors; widen the input vector within
  `MAX_NN_INPUTS`. **Restart-required** (NN topology change; no save/load so the
  input vector can be redesigned wholesale).
- **Coords must match the field convention** — mirror `bilinear_sample`'s
  `rem_euclid` when `wrap_world`, clamp/ghost otherwise (do NOT use naive
  `(x/cell) as usize`, which saturates negatives).
- **Resolved: E ships default ON, with dev-panel options.** Multi-band sensing
  is the default; expose the band layout / a single-band-vs-multi-band toggle in
  the DevPanel grass section (restart-scoped, like other topology knobs). The A/B
  is now a **regression guard, not a ship gate**: confirm multi-band is not
  *worse* than single-band beyond run-to-run variance (metric: mean steady-state
  population, energy as tiebreak; ≥ 50k ticks × ≥ 5 seeds per arm). If it comes
  back clearly worse, that's a bug to fix or a layout to retune — not a reason to
  flip the default off. **Both `NnInputLayout` variants stay shipped** so the dev
  toggle works and the comparison stays runnable.

### Dependency DAG

```
S0 ──verdict──▶ S5gate
S4 ───────────▶ S5  (constant-p fertility must land first)
S1 ┐
S2 ┤
S3 ┤ (all independent) ─────────────────▶ S7

S5 (if gated-in) ───────────────────────▶ S7
S6 ┘
```

- **Only S5 is conditional/gated.** S1, S2, S3, S4, S6 fan out immediately after
  S0 returns its numbers (S3 wants the breakdown but isn't blocked by the verdict
  — alloc+instrumentation removal is unconditional).
- **S5 has two preconditions**: S0 verdict = RNG-dominant **and** S4 landed
  (fertility holds `p` constant → the geometric draw is valid). If either fails,
  S5 is dropped per the fallback.
- **S7 is the barrier**: doc migration + closeout after all code streams settle.

### Worktree isolation

S3, S4, and S5 all mutate `grass.rs` and will conflict if run concurrently in the
same tree. Give each its own worktree, and **sequence S3 → S4 → S5 on the kernel**
(they're a chain anyway: S3 cleans the hot loop, S4 adds fertility, S5 restructures
sampling). S1/S2/S6 touch disjoint files and can run fully parallel.
