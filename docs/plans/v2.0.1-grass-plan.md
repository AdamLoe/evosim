# v2.0.1 — Grass: organic spread + spatial-sparsity perf (problems #5 & #6)

Implementation plan for the evosim Rust sim core (`src/grass.rs`, `src/wasm_api.rs`,
`src/world/{mod,tick}.rs`). **Read-only design** — no source edited by this doc.

**Hard constraints from the lead:**
- Grass MUST keep updating **every tick** and look smooth. The "propagate/quantize
  every N ticks" cadence approach is **REJECTED** — it is NOT used here.
- The strategy is **SPATIAL SPARSITY**, not temporal. At any instant only the growth
  **frontier** changes; the bulk of the 3.69 M cells are bare (≈0) or saturated at
  carrying-capacity K. We skip the equilibrium bulk and pay only for the frontier.
- Combined target: **10–20×** on both `grass_step.row_compute.body` and
  `write_output_sab`'s grass quantize, with **NO SAB layout/seam change** (the TS
  reader must keep reading a `grass_dim²`-byte u8 grass region — verified below).

## 0. Verified ground truth (against `src/`, HEAD `feat/v2.0.0`)

- `WORLD_SIZE_DEFAULT = 9600`, `GRASS_CELL_SIZE = 5.0` → `grass_dim = 1920`,
  `grass_cell_count = 3_686_400` (`constants.rs`; `WorldDims::from_world_size`).
- `GRASS_MAX = 1.0`, `r = GRASS_IN_CELL_GROWTH_R_DEFAULT = 0.01`,
  `k = GRASS_PROPAGATION_RATE_K_DEFAULT = 0.003`. Per-biome cap factors
  Plains 1.0 / Desert 0.30 / Water 0.04 → per-cell `capacity[c]` (`grass.rs:33`,
  built once at construction, never mutated per tick).
- Propagation runs **every tick** in both the live path (`world/mod.rs:840`) and
  the dead-world thin path (`world/mod.rs:762`). Confirmed it must STAY per-tick.
- Kernel (`grass.rs:289-306`), per cell c with `K = cap[c]`:
  `v = d[c]; logistic = r·v·(1 − v/K); prop = k·max(d[N],d[S],d[E],d[W]); d'[c] = clamp(v+logistic+prop, 0, K)`.
  This is a **4-neighbour Von Neumann (L1) kernel** → an isolated seed grows as an
  L1 ball = **diamond**. The `max`-of-neighbours (not sum) only throttles the rate,
  not the shape. **Confirmed: this is the diamond cause (#5).**
- Double-buffer: read `density`, write `scratch`, `mem::swap` (`grass.rs:234,354`).
  No early-out exists in the inner loop — `row_body` iterates every `ix` of every
  row unconditionally (`grass.rs:267`).
- `rebuild_row_bitset` (`grass.rs:159-177`) is a **second full-grid O(cells) scan
  every tick** (`world/mod.rs:880`). It feeds only the NN grass-sector scan's
  row-skip — it is NOT consumed by propagation today.
- `consume` (`grass.rs:417`) is the only per-tick density mutation outside
  propagation; called from `graze` (`world/tick.rs:78`), which runs sequentially.
  This is the **only other dirtying source** besides propagation. It can only
  ever DECREASE a cell (drain), so it can only turn a saturated/near-K cell into
  a frontier cell — never the reverse.
- Snapshot grass write: `quantize_grass_into` (`wasm_api.rs:1319`) — scalar
  f32→u8 loop over **all 3.69 M cells every tick** into the SAB slot
  (`wasm_api.rs:607`). Profiled as `write_output_sab.snapshot.grass_copy`.
- **Seam (verified):** TS reads the grass region as `grass_dim²` u8 bytes
  (`sim-bridge.ts:136-151 makeSlotLayout`, `grassOffset`) and uploads it as a
  full R8 texture every painted frame (`render-gl.ts:984-987`, `texSubImage2D`
  full-rect). **As long as the Rust snapshot region stays `grass_dim²` u8, ANY
  Rust-internal change (kernel, storage, dirty-tile writes) is invisible to TS.**

Threaded build note: `compute_propagation` parallelizes via `par_chunks_mut` only
under `--features threads`; a plain build silently single-threads. Any perf claim
must be measured with `--features threads`. All designs below preserve the
single-thread == rayon determinism property (see correctness notes).

## 1. Organic kernel (fixes #5) — separable 1-D logistic-diffusion

**Decision: replace the 4-neighbour max kernel with a SEPARABLE two-pass blur of
the neighbour field, combined with the existing logistic term.** Separable is
chosen over an 8-neighbour stencil because it is (a) rounder — a repeated
separable [1,2,1] blur converges to a Gaussian, whose level sets are circles —
and (b) the natural data shape for both wasm-SIMD (§4) and active-tile streaming
(§2): each pass is a 1-D, cache-linear sweep.

### Exact kernel and update rule

We keep the logistic in-cell growth and the MAX-of-neighbours spill *semantics*
(one ripe neighbour grants the boost; neighbours don't stack), but make the
neighbour reach **isotropic** by computing the spill from a separable
horizontal-then-vertical max (an L∞/Chebyshev reach is a square; a *weighted*
separable blend rounds the corners). Concretely, per tick:

**Pass H (horizontal), into a scratch `h[c]`:**
```
h[c] = w0·d[c] + w1·(d[c-1] + d[c+1])        // 3-tap, w0 + 2·w1 = 1
```
**Pass V (vertical) + growth + spill, into `scratch` then swap:**
```
blur[c]   = w0·h[c] + w1·(h[c-dim] + h[c+dim])   // second separable tap → 2-D Gaussian-ish
v         = d[c]
logistic  = r·v·(1 − v/K)
prop      = k · max(blur_neighbourhood)          // see "spill" below
d'[c]     = clamp(v + logistic + prop, 0, K)
```

Weights: **w0 = 0.5, w1 = 0.25** (normalized [1,2,1]/4 per axis). The full
separable kernel is the outer product → a 3×3 [[1,2,1],[2,4,2],[1,2,1]]/16
Gaussian. Its iso-density fronts are circular to first order; two ticks of it is
visibly round, and there is **no diagonal deficit** (corners get 1/16 each, axes
2/16) so a seed expands as a disc, not a diamond.

**Spill term (preserving "max, don't stack"):** rather than re-deriving max from
a blur (a blur is a sum, which would re-introduce the stacking cascade the design
explicitly avoids), keep the spill as a **max over the blurred field's 4 cardinal
neighbours of `blur[]`**, i.e. `prop = k · max(blur[N],blur[S],blur[E],blur[W])`.
Because `blur[]` is already an isotropic local average, the max-of-4 of it has
**rounded** fronts (the blur smears the diamond corners before the max samples
them). This keeps the anti-cascade behaviour AND gets circular spread.
Equivalent cheaper variant if profiling wants one fewer buffer: keep the current
`max(d[N..W])` but apply it to the **blurred** density `blur[]` in place of raw
`d[]` for the neighbour reads only (logistic still uses raw `v`).

> Net: one extra `dim`-length scratch buffer (`h`) and one extra 1-D pass.
> Self-cost rises ~1.3–1.6× per *active* cell vs today — but §2 makes the active
> cell count tiny, so absolute cost drops sharply. The kernel change alone does
> NOT meet #6; it is the shape fix (#5) and the SIMD/active-tile enabler.

### Correctness / determinism
- Both passes are pure functions of the previous frame (read `d`/`h`, write
  `h`/`scratch`); no in-place RMW across cells → **order-independent**, so
  single-thread and rayon (`par_chunks_mut`) produce **bit-identical** results
  for a fixed seed. Same property the current double-buffer has — preserved.
- Boundary handling reuses the existing ghost-zero (walled) / opposite-edge
  (wrap) index logic (`grass.rs:249-287`), applied per 1-D pass.
- Logistic character preserved exactly (`r·v·(1−v/K)`, clamp to `[0,K]`); empty
  isolated cells with empty neighbourhood stay 0 (no spontaneous spawn) because
  `blur` of all-zero is zero. Existing grass unit tests
  (`step_empty_world_stays_empty`, `step_clamps_to_grass_max`,
  `step_logistic_grows_seeded_cell`) still hold; the directional edge test
  (`step_zero_density_at_edge`) needs its assertions relaxed from "exactly N/S/E/W"
  to "the cardinal+near-diagonal neighbourhood" — **dedicated test update**.
- **New dedicated test:** seed one center cell, step ~40×, assert the set of
  non-zero cells is approximately a disc (max radius / min radius along the
  frontier within ~15%), i.e. NOT a diamond (which would have axis/diagonal ratio
  ≈ √2). This is the regression guard for #5.

## 2. Active/dirty-tile frontier processing — the big #6 win

**This is the primary lever for both spans.** Partition the grid into fixed tiles;
each tick, propagate ONLY active tiles + a one-tile fringe, and skip equilibrium
tiles (uniformly ~0 OR uniformly at their cap K) entirely.

### Tile size
**32×32 cells** (= 1024 cells/tile). At `grass_dim = 1920` that is 60×60 = **3600
tiles**. Rationale: 32 wide matches SIMD lane batching (§4: u8x16 ×2 or f32x4 ×8)
and 1024-cell tiles amortize the per-tile bookkeeping; 60×60 tile-grid fits a
compact bitset (3600 bits = 57 u64s). (Alternative 16×16 = 14400 tiles if the
frontier is very thin and we want finer skipping — revisit after measuring
frontier coverage.)

### Active-set data structure
- `tile_active: Vec<u64>` bitset, 1 bit per tile (3600 bits). Cheap to scan.
- `tile_state: Vec<u8>` per tile: `EMPTY` (all cells ≤ ε), `SATURATED` (all cells
  ≥ cap−ε), or `FRONTIER` (mixed / changing). Only `FRONTIER` tiles AND any tile
  bordering a FRONTIER tile are processed.
- Optional `active_list: Vec<u32>` (dense tile indices) rebuilt from the bitset
  each tick so the rayon dispatch iterates only active tiles (no 3600-tile scan
  per worker). This keeps the parallel dispatch proportional to frontier size.

### Activation / deactivation rules
- A tile is **FRONTIER** if, after its propagation pass, any of its cells is in
  `(ε, cap−ε)`. Detection is cheap: track per-tile `min` and `max` density during
  the pass (two scalars, updated in the inner loop we are already running); tile
  is EMPTY iff `max ≤ ε`, SATURATED iff `min ≥ cap−ε`, else FRONTIER. ε ≈ 1e-4.
  (cap varies by biome within a tile; use the tile's per-cell cap so a Water tile
  saturates at 0.04 correctly — compare `cap[c]−d[c] ≤ ε` per cell, OR-reduce a
  `changing` flag.)
- **Spread to fringe:** when a tile becomes/stays FRONTIER, mark its 8 neighbour
  tiles active for the NEXT tick (grass can only cross a tile boundary into an
  adjacent tile in one tick since reach is 1 cell). This is the "border an active
  tile" rule — it guarantees the frontier can advance without ever processing the
  equilibrium interior.
- **Graze dirtying:** `consume` (`grass.rs:417`) drains a cell. Mark that cell's
  tile (and its 8 neighbours) active for next tick. `graze` already iterates the
  overlapping cells (`world/tick.rs:77`); add an O(1) `mark_tile_active(cell_idx)`
  there. A drained SATURATED tile becomes FRONTIER → re-enters processing,
  regrows, and deactivates when it re-saturates. This is how grazed patches keep
  regrowing every tick with zero whole-grid cost.
- A FRONTIER tile that, after a pass, has all cells EMPTY or all SATURATED and
  whose neighbours are also non-frontier **deactivates** (clear its active bit).
- **Two-frame safety:** keep a tile active for one extra tick after it looks
  settled (a "cooldown") so a value oscillating around the ε threshold can't
  flicker active/inactive and drop an update. Cheap and removes a class of bugs.

### Replaces the per-tick full bitset scan
`rebuild_row_bitset` (the *second* O(cells) per-tick scan) is **subsumed**: derive
`row_has_density` from `tile_state` (a row is non-empty iff any tile covering it
is non-EMPTY) — O(tiles), not O(cells). Removes a whole second full-grid pass.

### Expected speedup (honest)
Let `f` = fraction of tiles that are FRONTIER-or-fringe. Work ≈ `f · total + tile
bookkeeping`. 
- Steady mid-game (sparse, dispersed patches, lots of bare desert + saturated
  cores): `f ≈ 0.05–0.15` → **~7–20×**.
- Early game (8000 seeds spreading): frontier is large but interiors saturate
  fast → `f ≈ 0.2–0.4` → **~3–5×**, improving as cores fill.
- **Worst case (whole map a moving frontier, e.g. r/k cranked so nothing settles):
  `f → 1`, speedup → ~1× minus a small (~3–5%) bookkeeping tax.** This is the
  honest floor and must be called out. It is not the default regime.

This single component is expected to carry most of the 10–20× under normal play.

### Correctness / determinism
- Skipping an EMPTY tile is exact (its update is identity: 0 stays 0 with empty
  neighbourhood, guaranteed by the fringe rule keeping any tile next to non-empty
  active). Skipping a SATURATED tile is exact **only if its neighbours are also
  saturated** — that is why a SATURATED tile bordering a FRONTIER tile is kept in
  the active set (the fringe rule). **Dedicated equivalence test:** run N ticks
  with active-tile processing vs a reference full-grid pass on the same seed;
  assert bit-identical `density` (the whole point — skipping must be a pure
  optimization, never change values).
- Determinism under rayon: tiles are independent (double-buffer, read `d` write
  `scratch`), and the active_list is built deterministically (sorted tile order),
  so single-thread == rayon for a fixed seed. **Dedicated test.**
- Edge interaction with §1's separable passes: a separable pass reads ±1 across
  tile borders. Process each active tile with a +1 halo read into the previous
  frame `d`/`h` (reads are fine across borders since `d` is the frozen prior
  frame). The two-pass `h` buffer must be valid in the halo of active tiles —
  either compute `h` for active tiles + halo, or fuse both passes per tile with a
  local +2 halo. Fused-per-tile with a 2-cell halo is the clean SIMD-friendly form.

## 3. Native density format — internal u16 fixed-point, snapshot stays u8

**Decision:**
- **Snapshot grass region: stays `u8`, length `grass_dim²`. NO SEAM CHANGE.**
  (Verified in §0: TS reads exactly this. Confirmed this choice does NOT cross
  the seam.)
- **Internal density: migrate `Vec<f32>` → `Vec<u16>` fixed-point**, value in
  `[0, 65535]` mapping `[0, GRASS_MAX]` (Q0.16-ish; cap[c] stored likewise as
  u16). Rationale: u16 gives ample precision for smooth logistic growth at
  `r = 0.01` (a per-tick delta of `0.01·v·(1−v/K)` is ≈ tens–hundreds of u16
  steps near mid-density — never quantization-stalled, unlike u8 which has only
  255 levels and would visibly stair-step slow growth). u16 also doubles SIMD
  lane count vs f32 (§4) and halves memory bandwidth on the hot pass.

### Why u16 internal but u8 snapshot
- u8 internal was considered and **rejected**: at `r=0.01`, growth per tick near
  v≈0.5 is ~0.0025 of GRASS_MAX < 1/255, so a u8 cell could fail to increment for
  several ticks → visible stair-stepping / stalls. u16 has 256× the resolution,
  so the same growth is ~163 u16 LSBs/tick — smooth.
- Logistic math in fixed-point: compute `v·(1−v/K)` in u32/i32 intermediates
  (`v` and `K` are u16; `v·(K−v)` fits in u32; scale by `r` via a fixed-point
  multiply, shift down). Keep one widening multiply + shift; clamp to `[0, cap]`.
  This is branch-light and SIMD-vectorizable.
- **Snapshot becomes a near-memcpy:** `quantize_grass_into` changes from a scalar
  f32→u8 loop to `out[c] = (density_u16[c] >> 8) as u8` (take the high byte) —
  trivially SIMD/`copy`-friendly, and when paired with §2's dirty set, only
  **changed tiles** are re-quantized into the slot. The slot already holds valid
  prior bytes for unchanged tiles (double-buffer slots persist), so unchanged
  tiles need no rewrite.

> Caveat to flag: the snapshot uses TWO ping-pong slots (`slot & 1`,
> `wasm_api.rs:561`). A dirty-only write into slot S leaves slot 1−S stale for the
> tiles not touched this write. **Fix:** either (a) write changed tiles into BOTH
> slots each tick (still tiny — only frontier tiles), or (b) track per-slot dirty
> so a tile is re-quantized into a slot until both slots are current. Option (a)
> is simplest and cheap (frontier is small). This keeps both slots always valid
> with NO layout change.

### Bilinear sample / consume in fixed-point
`bilinear_sample` (`grass.rs:362`) and `consume` (`grass.rs:417`) currently return
f32 and are used by NN sensors / graze energy. Keep their **public f32 contract**:
convert u16→f32 at the sample boundary (`d as f32 / 65535.0 * GRASS_MAX`). Graze
`consume` does its arithmetic in f32 then writes back the u16. This isolates the
storage change from the rest of the sim — **no behavioural change to sensors or
energy** beyond sub-LSB rounding. **Dedicated test:** assert
`bilinear_sample`/`consume` outputs match the f32 version within u16 quantization
tolerance.

### Seam summary for §3
- u8 snapshot, `grass_dim²` length: **NO seam change.** ✅
- u16 internal storage: **Rust-internal only.** ✅
- Dirty-tile snapshot writes: **Rust-internal** (TS still reads full region; we
  just wrote less of it). **NO seam change.** ✅

## 4. wasm-SIMD on the inner pass (last, layered)

After §1 (separable 1-D passes) + §3 (u16) the inner loop is a contiguous u16
sweep — ideal for `core::arch::wasm32::v128`:
- Horizontal pass: load `u16x8`, shifted ±1, weighted add, store — ~8 cells/instr.
- Logistic: widen u16→u32 in two halves, multiply-shift, narrow back.
- Quantize-to-u8 snapshot: `u16x8 >> 8` → pack to `u8x16` — ~16 cells/instr.
- **Expected: 3–6× on the per-active-cell body** (memory-bound mitigated by u16
  halving bandwidth). Multiplies with §2's reduced active-cell count.
- **Build flag:** requires `RUSTFLAGS=-C target-feature=+simd128` (or a
  `simd` cargo feature gating the `#[cfg(target_feature = "simd128")]` path) IN
  ADDITION to `--features threads`. Provide a scalar fallback for the
  non-SIMD/native-test build so determinism tests run everywhere. **The scalar
  and SIMD paths must produce identical u16 output** (integer math, so this is
  achievable exactly — unlike f32 SIMD reassociation). **Dedicated test:**
  SIMD-vs-scalar bit-equality on a fixed seed.

## Per-component expected-speedup table

| # | Component | `row_compute.body` | `grass_copy` (snapshot) | Seam? | Risk |
|---|-----------|--------------------|-------------------------|-------|------|
| 1 | Separable organic kernel | ×0.6–0.8 (slightly MORE work/cell, but fixes #5 & enables SIMD) | — | No | Low (shape test + relax edge test) |
| 2 | Active/dirty-tile frontier | **×7–20** typical (×3–5 early; **×1 worst case**) | **×5–20** (dirty-tile re-quantize only) | No | Med (equivalence test is mandatory) |
| 3 | u16 internal + u8 snapshot | ×1.3–1.8 (½ bandwidth, more SIMD lanes) | ×2–4 (scalar f32→u8 becomes high-byte copy) | **No** ✅ | Med (fixed-point growth; sensor parity test) |
| 4 | wasm-SIMD inner pass | ×3–6 on active cells | ×2–3 (pack to u8x16) | No (build flag) | Med (scalar/SIMD parity test) |

**Combined (multiplicative on the parts that compose):** §2 alone reaches
10–20× in the normal regime; §3 widens the margin and makes the snapshot a
near-memcpy; §4 adds headroom and absorbs the worst-case (all-frontier) tax.
The **cheapest path that realistically reaches 10–20× on both spans is §2 + §3**:
frontier-only processing (the big cut) plus u16 storage (which turns the snapshot
into a dirty-tile high-byte copy). §1 is required for #5 and rides along; §4 is
optional headroom.

## Recommended landing order

1. **§1 separable organic kernel (shape fix #5), still full-grid, still f32.**
   Lands the visual fix first, lowest blast radius, and establishes the 1-D-pass
   structure §2/§4 build on. Ship with the disc-shape regression test and the
   relaxed edge test. (Does NOT improve #6 yet — set expectations.)
2. **§2 active/dirty-tile frontier processing.** The big #6 win for BOTH spans:
   propagation processes only frontier+fringe; snapshot re-quantizes only dirty
   tiles into both slots; `rebuild_row_bitset` is subsumed. Gate behind the
   mandatory full-grid-equivalence test. This is where 10–20× lands.
3. **§3 u16 internal density, u8 snapshot unchanged.** Halves bandwidth, turns
   quantize into a high-byte copy, doubles SIMD lanes. Ship with sensor/consume
   parity tests. NO seam change (snapshot stays `grass_dim²` u8).
4. **§4 wasm-SIMD inner pass** (behind a `simd128` build flag with a scalar
   fallback). Headroom + worst-case insurance. Ship with SIMD/scalar bit-parity.

## Tests that MUST exist (correctness / parallel-equivalence)
- **Disc-shape regression** (§1): center seed, step, assert circular not diamond.
- **Active-tile == full-grid equivalence** (§2): bit-identical density over N ticks
  vs reference full pass, on a fixed seed — including grazed-tile reactivation.
- **Single-thread == rayon** (§2): identical density for fixed seed under both.
- **u16 sensor/consume parity** (§3): `bilinear_sample`/`consume` within u16 LSB.
- **Both snapshot slots valid after dirty-only writes** (§3): read each slot,
  assert it equals a full quantize of current density.
- **SIMD == scalar** (§4): bit-identical u16 output.

## Seam-impact summary (the answer the lead wants)
Every component here is **Rust-internal**. The snapshot grass region stays `u8`,
length `grass_dim²` — exactly what `makeSlotLayout`/`grassOffset`/`render-gl.ts`
already read and upload. **No `sim-bridge.ts` or `render-gl.ts` change is required;
no SAB layout/seam change anywhere.** (The only thing that would cross the seam —
explicitly NOT proposed — is a coarser/downsampled snapshot grid, which would
change `grass_dim` and the texture dims.)
