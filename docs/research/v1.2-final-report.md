## Items rejected with reasoning

- **`#[serde(default)]` on new fields to soften schema bumps.** Rejected; aligned with brief's "Save format updated. Starting fresh." UX. Hard schema breaks are intentional.
- **Move-bias SET semantics** (override NN-output vx/vy). Rejected at cross-review per amendments §A.5 in favor of ADD. SET would permanently disable NN-driven motion in all descendants, preventing predator-chase evolvability. ADD preserves the Brownian-walk fallback while letting evolved NN motion add on top.
- **Per-piece plan-reviewers** (originally master plan §G.3 spec). Replaced with a single cross-reviewer covering all 12 plans (cost-efficiency); cross-review caught the critical conflicts (GRAZE_MAX_PER_TICK contradiction, PR-1 commit ordering, SET vs ADD, etc.).
- **`force_sequential_nn` deletion.** Kept (S39 plumbing); the `#[cfg_attr(not(feature="threads"), allow(dead_code))]` is intentional and integration tests rely on it.

## Known issues surfaced

1. **§16 acceptance trajectory doesn't exercise predation.** At default sliders + `evosim-test-001` seed, the 10k-tick simulation produces zero successful eat bites. The world stays grazer-dominated. This is consistent with the brief's "honestly dumb founders" intent (eye_count=0, nose_count=0; predator evolution takes more than 10k ticks). Side effect: P3a's per-bite Eat formula change had no observable effect on the golden hash. The predator/scavenger tiers are coded and tested in unit tests but evolvability headroom only — they don't bend the goldens at acceptance scale.

2. **WSL2 perf budget violation on threaded acceptance.** `acceptance_t10000_threaded` takes ~12.4s on WSL2 vs the 8s `PERF_BUDGET_MS`. The threaded test is gated behind the `EVOSIM_WRITE_GOLDEN_THREADED` bootstrap path so it doesn't block on WSL2 dev machines. Real Linux CI is expected to fit. Pre-existing condition (DECISIONS line ~220 in v1.1 audit covers this).

3. **Founder default `nose_count=0` + `eye_count=0` means founders are honestly dumb.** They move randomly (move_bias ADD + ~20-tick re-roll) and only graze when randomly stumbling onto a grass cell. With current tuning (`grass_initial_seed_count=100`, `grass_in_cell_growth_r=0.05`, `grass_propagation_rate_k=0.1`), grass spreads fast enough that the lineage survives to T=10000 with ≥ 2 species — but barely. The §16 acceptance is sensitive to these defaults; the P3e tuning ladder at PR-1 close + PR-2 close documents the iteration path. **Future-safe:** if other tweaks shift the energy balance, run the ladder again.

4. **TS slider defaults drift risk.** `web/src/widgets/devpanel.ts` hardcodes the 7 slider defaults. They match the current Rust constants but there is no build-time check; if a future Rust constant change forgets to update the TS, the dev panel shows stale defaults. Document for v1.3 follow-up: add a wasm-bindgen exported `default_sliders()` getter and read it on first install.

5. **F.30 founder hardwiring at slot 147 is dormant for nose_count=0 founders.** This is intentional per brief — the hardwired Graze detector only activates after a descendant mutates `nose_count ≥ 1`. Until then, founders only Graze via random NN-init drift on the Graze output. The hardwired hidden[1] Move baseline and hidden[2] energy_frac→Split paths DO activate for founders.

6. **`evosim.d.ts` is gitignored and regenerated by wasm-pack.** The dev experience requires manual updates to this file between Rust impl agents and `pnpm typecheck` calls. Documented in DECISIONS PR-3 P3b + P3d entries.

## Questions for the user (closeout)

These were surfaced during the pass and need user confirmation:

1. **Move-bias semantics: ADD vs SET.** Locked ADD per cross-review §D. The brief reads "Move += baseline + small random direction-persistence" literally, which we interpreted as additive. SET would permanently disable NN-driven motion in descendants. **Recommend keeping ADD.** Revertible in one line in `apply_movement_and_repulsion`. If you prefer SET (founders' Brownian-walk overrides any evolved NN motion), say so and I'll patch.

2. **GRAZE_MAX_PER_TICK = 0.4.** Amendments §A.1 explicitly authorized up to 0.25 ("Lift to 0.25 if grazers starve"). The P1h tuning ladder landed at 0.4 because 0.25 still produced extinction at the past-lifespan upkeep cliff (extinct ~5740 ticks). 0.4 (combined with the other tuning levers) produces population that survives + speciates to T=10000. **User might want to reconsider whether (a) 0.4 is too generous, (b) the past-lifespan upkeep formula is too harsh, or (c) the §A.1 0.25 was a hard cap.**

3. **SPECIES_THRESHOLD = 4.0** (reverted from v1.1's 6.0). v6 §H spec default is 4.0; v1.1 raised it because sun-driven fast drift caused speciation toast spam (DECISIONS F.31). v1.2's slower grass-driven drift won't hit 6.0 in 10k ticks. The 2-second toast rate-limit (DECISIONS F.31) still suppresses spam even with faster speciation. **OK as-is?** Or restore 6.0 and find a different lever for §16 (b)?

4. **§16 acceptance doesn't exercise predation/scavenge.** At default sliders, no eat bites occur in 10k ticks. Per § Known issues #1. If you want the §16 to verify the three-tier food chain too, we'd need a longer run (50k+ ticks) OR an artificial pre-seeded predator. Out of v1.2 scope; surface for v1.3.

5. **Default `grass_initial_seed_count = 100`** (brief default was 8). Raised via P3e tuning ladder. The dev panel slider allows 1..100 so default at the upper bound means users can only decrease at runtime — they can't seed more than 100 cells without a brief revision. **Want to bump slider max to 200?**

6. **Default `grass_in_cell_growth_r = 0.05`** (brief default was 0.005). 10× the brief. Same tuning provenance.

7. **Default `grass_propagation_rate_k = 0.1`** (brief default was 0.05). 2× the brief.

8. **Three schema bumps in one pass (v1 → v2 → v3 → v4).** Aggressive but consistent with brief's "Save format updated. Starting fresh." UX. Old saves are unrecoverable. **Comfortable with this?**

9. **TS slider defaults drift.** See Known issue #4. v1.3 candidate?

10. **Predator + scavenger evolution at acceptance scale.** See Known issue #1. v1.3 priority?

## Suggested next-pass priorities

In order of expected ROI:

1. **Balance fine-tuning sweep.** Run multiple seeds at default sliders; verify §16 holds across the seed distribution, not just `evosim-test-001`. Tune `GRAZE_MAX_PER_TICK`, mutation rates, lifespan to widen the safe-survival envelope.

2. **Longer-run analysis.** Run 50k+ ticks to verify predation/scavenge tiers actually emerge from grazer founders. Validates that the three-tier food chain is reachable, not just coded.

3. **NEAT brain (variable topology)** — the most-cited deferred item. v1.2's fixed `160 → 24 → 8` shape limits what the brain can learn; NEAT adds incremental complexity per the v6 §H direction.

4. **WebGL2 renderer.** Plan-only doc exists; v1.3 candidate per `docs/plans/webgl2-renderer-design.md`. Current Canvas2D becomes a bottleneck above ~5k creatures.

5. **Quadtree spatial index.** SpatialGrid is still the hot path for vision raycast + neighbor queries; quadtree may scale better.
