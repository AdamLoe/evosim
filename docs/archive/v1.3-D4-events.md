# D4 — Event system deletion (v1.3 simplification)

## 1. Scope summary

Delete the event system entirely:

- The Rust `events` module (`src/events.rs`) with `Event`, `EventKind`, and `EventLog`.
- The `events: EventLog` and `events_enabled: bool` fields on `World`, plus every push site.
- The first-to-* trigger logic (`first_move_fired` / `first_eat_fired` flags coordinate with D5/HoF — see §5).
- The toast subsystem on the web side: `web/src/rail/toast.ts`, `tickToasts` calls in `web/src/rail/index.ts`, the `#toast-stack` DOM element, and the toast CSS block.
- The serde shape test (`event_kind_serde_flat_tag`) in `src/wasm_api.rs`.
- The `EventLog` fields on `SaveV1` / `EventLogSnapshot` / `rehydrate_event_log` (D1 will drop these, but D4 owns the upstream simulation surface).

D4 does **not** delete the `#autosave-toast` mini-toast (D1 owns).

D4 does **not** delete `first_move_fired` or `first_eat_fired` — D5 (HoF) consumes those flags. D4 only removes the event-emission inside the `if !self.first_X_fired { … push Event }` blocks.

There are **no** wasm-exposed event readers (`events_recent_json` / `events_full_json` do not exist). The TS rail polling was already a no-op.
