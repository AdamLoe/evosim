# Repo rules — evosim

Universal git discipline (commit hygiene, cadence, destructive-command
checklist) lives in
[`~/agent-docs/v1/rules/repo-rules.md`](~/agent-docs/v1/rules/repo-rules.md).
This file covers only what is specific to this repo.

## When does this apply

You are about to commit, push, or perform any git operation — or you're
deciding which generated/build outputs must never be staged. Read this
before running any destructive git command, before `git add`, and before
any commit that touches `app/web/wasm/` or other gitignored build dirs.

## Drift gates that block commits

The repo has these classes of invariant that must hold before any commit:

- **Clippy-clean (both feature sets).** `cargo clippy --all-targets -- -D warnings`
  AND `cargo clippy --all-targets --features threads -- -D warnings`.
- **Rust unit tests (both feature sets).** `cargo test --lib` and
  `cargo test --lib --features threads`. Cross-feature equivalence
  (same seed → same output) must hold.
- **TypeScript gates.** `cd app/web && pnpm typecheck && pnpm build` (run from repo root).
- **Playwright e2e.** `cd web && pnpm test:e2e` — consolidated final
  gate; not run per-stream.

Full invocations and procedures live in
[`testing-how-to.md`](testing-how-to.md). This file owns "what must
hold"; testing-how-to owns "how to check it." The machine-readable gate
list is also the `drift-gates` slot in
[`../_meta/manifest.md`](../_meta/manifest.md).

## App-specific forbidden paths

(The universal "never hand-edit generated artifacts; never commit build
output, dependency dirs, or local run data" rules live in the global
repo-rules. Below are this repo's instances.)

- **Never commit `app/web/wasm/*`.** Gitignored. It is regenerated by
  `wasm-pack build --features threads`. If it sneaks into staging via
  `git add -A`, remove it with `git rm --cached -r app/web/wasm/`.
- This repo's gitignored build outputs are `app/target/`, `app/web/dist/`,
  `app/web/node_modules/`; never commit them.

## Worktrees

Multi-agent pipelines have left behind a forest of branches and worktree
directories named `worktree-agent-*`, `worktree-a1-*`, etc.

**Delete worktrees once their work is merged.** Project override of the
default "ask first for destructive ops" rule, scoped to worktrees only:
once a worktree's branch has landed on `main` (or its work has been
absorbed and the branch is otherwise dead), remove the worktree and
delete the branch without asking.

```bash
# Remove a worktree whose work has landed.
git worktree remove <path>
git branch -D <branch>
git worktree prune              # cleans up any stale metadata
```

The carve-out is narrow: this applies only to worktrees the user
themselves has not been working in. If a worktree contains uncommitted
changes you didn't make, leave it alone and surface it instead. The
user has stated they never use worktrees personally — anything under
`.claude/worktrees/` or named `worktree-*` is agent-generated and safe
to clean up once its work has merged.

Worktree directories under `.claude/worktrees/` are gitignored. If one
sneaks into staging via `git add -A`, the `.gitignore` entry covers
fresh ones but already-staged ones need an explicit
`git rm --cached -r ...`.
