# Repo rules

Git, commits, and what not to do.

## When does this apply

Any time you're about to run a destructive git command, make a commit,
or touch a file that "isn't quite source code" (lockfiles, generated
output, settings).

## Hard rules

- **Conventional commits only.** `<type>(<scope>): <subject>`. Active
  types: `feat`, `fix`, `perf`, `refactor`, `chore`, `docs`, `test`,
  `style`.
- **No `--no-verify`.** Pre-commit and pre-push hooks fail for reasons;
  bypass means the gate doesn't run.
- **No `--amend` on a pre-commit-hook failure.** The commit didn't
  happen; `--amend` modifies the *previous* commit. Fix the issue and
  make a new commit.
- **No `git add -A` or `git add .`.** Always `git add -- <explicit
  files>`. Wholesale add has pulled in `.claude/worktrees/` as
  embedded submodules in the past, and routinely picks up build
  artifacts that shouldn't be tracked.
- **No force-push to `main`.**
- **No destructive ops (`git reset --hard`, `git clean -f`,
  `git checkout .`, `git branch -D`) unless the user explicitly
  asks.** Treat them as one-way doors.
- **Never commit `web/wasm/*`.** Gitignored. It's regenerated by
  `wasm-pack`.
- **Never commit `.env`-style files or any credentials.**
- **One concept per commit.** Reviewing a 12-file commit that does
  three things is much harder than reviewing three 4-file commits.

## Don't add a CLAUDE.md / AGENTS.md / project-specific `.claude/` instructions

This project's docs live in `docs/`. Project-architecture context in
`CLAUDE.md` burns LLM context on every conversation regardless of
relevance, and there is no way to make it conditional. The
`docs/prompts/fresh-chat.md` template is the deterministic entry point;
substantive content belongs in `architecture/` or `agent-context/`.

`.claude/settings.local.json` for permissions or hooks is fine — that's
harness configuration, not project knowledge.

## Worktrees

Multi-agent pipelines have left behind a forest of branches and worktree
directories named `worktree-agent-*`, `worktree-a1-*`, etc. After a
session ends:

```bash
git worktree prune
git branch -D <stale-branch-names>      # only if the user explicitly asks
```

Worktree directories under `.claude/worktrees/` are gitignored. If one
sneaks into staging via `git add -A`, the `.gitignore` entry covers
fresh ones but already-staged ones need an explicit
`git rm --cached -r ...`.

## Running tests / gates

The standard per-commit gate suite for code changes:

```bash
cargo fmt --all --check
cargo build
cargo test --lib
cargo test --lib --features threads
cargo clippy --all-targets -- -D warnings
cargo clippy --all-targets --features threads -- -D warnings
cd web && pnpm typecheck && pnpm build && cd -
```

Threaded wasm rebuild (when Rust changed):

```bash
rustup run nightly wasm-pack build --target web --out-dir web/wasm --dev --features threads
grep -c initThreadPool web/wasm/evosim.js   # → 2
grep -F 'shared:true'  web/wasm/evosim.js   # → 1
```

Skip the wasm rebuild only when no Rust source files changed.
